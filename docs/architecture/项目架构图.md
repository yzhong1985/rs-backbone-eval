## 二、一次运行的完整流程

```mermaid
sequenceDiagram
    autonumber
    participant U as 操作者
    participant CLI as rs-eval cli
    participant REG as registry
    participant DISP as dispatch
    participant W as 模型worker
    participant FS as 外置存储
    participant P as Portal

    U->>CLI: rs-eval dispatch --action train --task T1 --model X --protocol Y --seed 42
    CLI->>REG: 校验 task×model×protocol×seed
    REG-->>CLI: TaskSpec / ModelSpec / ProtocolSpec
    CLI->>DISP: 解析最新内容寻址 manifest
    DISP->>FS: 创建 runs/<run_id>/ 并写 request.json (WorkerRequest)
    DISP->>W: 按 ModelSpec.worker_command 启动独立环境
    W->>FS: 读取 manifest + 权重 + 数据
    W->>W: probe 校验 / 训练 / 评价
    W-->>DISP: stdout 逐行 WorkerEvent (进度JSONL)
    DISP-->>U: 实时转发 [INFO]/[ERROR] 事件
    W->>FS: 原子更新 run.json (running→completed/failed)
    W->>FS: 保存 checkpoint / 曲线 / 指标
    W-->>DISP: 退出码
    U->>P: 浏览器查看
    P->>FS: 扫描 runs/*/run.json
    P-->>U: 运行表格·指标·曲线·产物链接
```

## 五、关键设计约束

1. **控制层不导入模型代码**：`src/rs_backbone_eval` 只用 stdlib + numpy + pydantic + typer，避免与三个上游项目的依赖冲突；模型执行全部在隔离 worker 中。
2. **仓库不存 payload**：数据、权重、缓存、checkpoint、预测、日志全部在外置根目录，通过 `RS_EVAL_*` 环境变量注入；`.gitignore`、pre-commit 和 CI 卫生脚本共同防护。
3. **run.json 是唯一权威**：Portal 只读扫描，不做数据库；worker 用 `run.json.tmp` + 原子替换更新，Portal 不会读到半份记录。
4. **manifest 内容寻址**：清单按内容计算 SHA-256 并存为 `<sha256>.jsonl`，run 记录只保存哈希，保证实验可追溯。
5. **公共规则由根项目掌控**：标签映射、损失、指标、冻结检查、种子与搜索预算集中在公共层，任何模型不得私自修改。
6. **下载目录驱动**：API 只接受 `catalog.yaml` 中已声明的资源 ID，目标路径锁定在 `data`/`weights` 根目录内。
