# 部署：裸机与 Docker 两种方式（2026-11-16）

两种方式**同时支持**，共用同一份代码、同一套配置和同一个账本。差别只在“环境装在哪”：

| | 裸机（默认） | Docker |
|---|---|---|
| 环境 | 宿主上的 `uv` + 7 个 `.venv` | 镜像里的同 7 个环境 |
| 数据/权重/账本 | 宿主目录，`.env` 指过去 | 挂载进容器，同上 |
| GPU | 直接用 | `nvidia-container-toolkit` + `--gpus all` |
| 换机器 | 重装 uv 环境和依赖 | 重拉镜像（~20 GB） |
| 适合 | 单机长期跑、要频繁改代码 | 多人/多机一致的复现、隔离 |

代码里没有任何路径写死：`RuntimePaths` 只读 `RS_EVAL_*`，`worker_command` 从
`configs/models/*.yaml` 来。所以两种方式可以**混用**——比如宿主机跑日常实验，容器里跑
复现验证；只要指向同一个 `runs/` 和同一个 GPU 锁。

## 一、裸机

### 1. 依赖

```bash
git clone git@github.com:<owner>/rs-backbone-eval.git && cd rs-backbone-eval
curl -LsSf https://astral.sh/uv/install.sh | sh      # uv ≥ 0.13
uv sync --extra portal --extra downloads --extra dev
for worker in aef anysat clay lim olmoearth prithvi; do
    uv sync --project "workers/${worker}"
done
```

各 worker 的 torch 版本不同（见 `docker/README.md` 的表），这是仓库约定，不要合并。

### 2. 配置

```bash
cp .env.example .env    # 改 RS_EVAL_DATA_ROOT / WEIGHTS_ROOT / RUNS_ROOT / CACHE_ROOT
```

`.env` 不入库。路径必须在仓库外；`/geodata` 只放账本和 manifest，大体积原始数据/缓存放
`/home/<user>/rs-eval-*`（见 AGENTS 的存储布局）。

### 3. 数据与权重

- 公开数据：`bash scripts/colab_bootstrap.sh T1 T3 T5`（HF/GCS 直连），或按
  `configs/downloads/catalog.yaml` 用 `rs-eval list-downloads` 下载；
- manifest：`uv run rs-eval build-manifest --task T11D`；正式 run 前用
  `RS_EVAL_MANIFEST` 固定具体那份；
- 权重：catalog 里的固定 revision；
- 上游源码：`ANYSAT_SRC`、`CLAY_SRC` 指向仓库外的固定 commit checkout —— 缺了对应 worker
  起不来。

### 4. 验证

```bash
bash scripts/preflight.sh          # 环境 + 路径 + GPU + 权重的一次性检查
uv run rs-eval doctor
```

## 二、Docker

```bash
cp docker/.env.example docker/.env   # 只放宿主目录和镜像源覆盖项
# 编辑 RS_EVAL_HOST_* 指向本机目录(默认是 89 这台)
docker compose -f docker/compose.yaml build
docker compose -f docker/compose.yaml run --rm rs-eval uv run rs-eval doctor
```

要点（细节见 `docker/README.md`）：

- 镜像约 20 GB：6 个 worker 钉了 4 个 torch build，同版本的靠 hardlink 共用；
- 数据、权重、缓存、账本、队列、上游源码全部**挂载**，不进镜像；
- **`/tmp` 必须挂载**：GPU 锁是 `/tmp/rs-eval-gpu.lock`，容器内外要是同一把锁，否则宿主上
  跑着 lane 时容器还会再起一个 run；
- 国内网络：构建默认把 lock 里的 PyPI / PyTorch 源改写成清华 / 阿里云镜像（文件字节相同，
  哈希仍然校验）。在国外机器上把 `PYPI_MIRROR`、`TORCH_MIRROR` 置空即可。

## 三、混用时的约定

- `runs/`、`queue/`、GPU 锁三者共用；不要在两种部署里各用一份 `runs/`；
- `run.json` 记录 `host`，同一 cell 的种子不要一半在容器一半在宿主（AGENTS 的同 host 约束）；
- 宿主的 lane 和容器的 `queue run` 会互相等待同一把锁，这是设计行为，不是卡死。

## 四、迁移到新机器的检查清单

1. `preflight.sh` 全绿；
2. `rs-eval doctor` 三个目录存在；
3. 目标模型 checkpoint 的 sha256 与 `configs/` 记录一致；
4. 任意任务跑一次 smoke（`RS_EVAL_TRAIN_LIMIT`/`EVAL_LIMIT` 小值），确认 `run.json`
   里 `tags.smoke` 为 `true` —— 提醒自己这些数字不能当结果；
5. 正式 run 前打一份 bundle：`git bundle create ~/backups/rs-eval-<sha>.bundle --all`。
