# 作业队列（2026-11-16）

## 为什么

`scripts/rerun_baselines.sh` 的 run 列表写死在 shell 的 `case` 分支里：加一批实验要改脚本、
review、合并；多个 agent 共用一块 GPU 时也没有“我要排在谁后面”的表达方式。队列把这两件事
变成**往目录里放一个文件**。

## 位置与状态

默认根目录是 `RS_EVAL_QUEUE_ROOT`，没设时取 `<runs_root>/../queue`（本机即
`/geodata/rs-eval/queue`）：

```
queue/
  pending/  20261116T103000Z_<run_id>.json   等待执行；文件名顺序 = 出队顺序
  running/  同上                              正在执行
  done/     同上 + 同名 .result.json           成功
  failed/   同上 + 同名 .result.json           失败或取消
```

队列只做调度，**结果仍以 `runs/<run_id>/run.json` 为准**。

## 一个作业长什么样

```json
{
  "run_id": "clay_v1_5-T11D-clay_rgbn_ft_last4_e80-train-42-lf10-e80-v2",
  "action": "train",
  "task": "T11D",
  "model": "clay_v1_5",
  "protocol": "clay_rgbn_ft_last4_e80",
  "seed": 42,
  "env": {"RS_EVAL_MANIFEST": "/geodata/rs-eval/data/manifests/T11D_subsets/10pct-groups.jsonl",
          "RS_EVAL_LABEL_FRACTION": "0.1"},
  "note": "P1 10% 标签全量重跑"
}
```

`env` 的键必须属于 worker 已有命名空间（`RS_EVAL_`、`CLAY_WORKER_`、`ANYSAT_WORKER_`、
`PRITHVI_WORKER_`、`LIM_WORKER_`、`AEF_WORKER_`、`OLMOEARTH_WORKER_`），写错前缀会在入队时
直接拒绝，而不是静默无效。

## 用法

```bash
# 入队：立刻按 registry 校验（task/model/protocol/seed/run_id 是否合法、run 目录是否已存在）
uv run rs-eval queue add --task T11D --model clay_v1_5 \
  --protocol clay_rgbn_ft_last4_e80 --seed 42 \
  --run-id clay_v1_5-T11D-clay_rgbn_ft_last4_e80-train-42-lf10-e80-v2 \
  --env RS_EVAL_MANIFEST=/geodata/rs-eval/data/manifests/T11D_subsets/10pct-groups.jsonl \
  --env RS_EVAL_LABEL_FRACTION=0.1 --note "P1 10% 标签全量重跑"

uv run rs-eval queue list                    # 四态一览
uv run rs-eval queue run --dry-run           # 只看下一个会跑什么
uv run rs-eval queue run                     # 常驻：取一个、跑完、再取
uv run rs-eval queue run --once              # 只跑一个
uv run rs-eval queue cancel <run_id> --reason "manifest 换错了"
```

也可以手写 JSON 丢进 `pending/`；文件名必须以 `Z_` 之前的时间戳开头才会排在手动文件之后，
按字典序出队。入队校验只发生在 `queue add`，手写文件要自己保证 `run_id` 不重复。

## 保证

- **一张卡同一时刻只跑一个**：队列和 lane 用同一把 `flock /tmp/rs-eval-gpu.lock`
  （`RS_EVAL_GPU_LOCK` 可覆盖），两者互斥；CPU-only lane 不拿锁。
- **等空闲**：拿到锁后仍会轮询显存（`RS_EVAL_GPU_IDLE_MIB`，默认 2000），并给子进程设
  `RS_EVAL_REQUIRE_IDLE_GPU=1` 作为第二道保险。
- **不重跑**：入队时 `plan_dispatch` 已经拒绝已存在的 run 目录；如果目录在排队期间出现，
  该作业直接判 failed 并写下原因，不会无限重试。
- **不删东西**：取消也是移到 `failed/` 并写 `.result.json`，保留审计轨迹。
- **失败不阻塞队列**：一个作业非零退出会记 failed 并继续下一个；`--once` 下退出码为 1。

## 与 lane 的关系

两者可以并存：lane 适合“一次性、写死在代码里的批次”，队列适合“边跑边加、多人/多 agent
共用”。同一时刻只有一方拿到 GPU 锁。迁移时把 lane 的 `run_named` 循环换成等价的
`queue add` 即可，行为一致（跳过已完成、失败继续）。

## 已知限制

- 队列守护进程被 `kill -9` 时，当前作业会停在 `running/`；`run.json` 也是 `running`。
  没有自动回收：手工把 `running/` 的文件移回 `pending/` 之前，先确认没有 worker 还在写。
- 没有优先级和并发度：严格 FIFO、单并发。需要多卡并发时，按卡拆多个队列根目录，
  并让各自的 `RS_EVAL_GPU_LOCK` 指向不同文件。
