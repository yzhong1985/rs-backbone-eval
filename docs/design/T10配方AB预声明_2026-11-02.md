## 3. 预声明的配方（组合改动）

四项一起改，因为它们各自单独都不足以让检测器脱离"全背景"：

| 项 | 锁定值（v6） | A/B 值 |
| --- | --- | --- |
| anchor sizes | 32,64,128,256 | **16,32,64,128,256** |
| anchor ratios | 0.5,1,2 | **0.5,1,2,4**（每位置 12 → 20 个） |
| 学习率 | 1e-4 | **1e-3**（AdamW，wd 0.05，warmup 500，clip 35） |
| RoI 正样本比例 | 0.25 | **0.5** |
| 预算 | 25,000 步（3.25 epoch） | **92,340 步（12 epoch，每 epoch 7,695 步）** |
| 有效 batch | 2（1×2） | 不变 |
| 主干 | 冻结 | 不变 |
| 种子 | 17/42/73 | **仅 17**（诊断） |

组合改动是有意的取舍：单变量各测一次要 4×20 h。**若本组合有效，后续必须补单变量消融**，不能把增益
直接归给某一项。

## 8. 2026-11-02 修订：为什么暂停

| 问题 | 影响 |
| --- | --- |
| anchor 生成是 anchor-major，RPN 展平是 cell-major | 训练与推理都把分数绑到别的格子/尺寸上，v6 与全部探针都受影响 |
| 逐类 NMS 用局部索引取完整分数数组 | 框与分数错配，影响合并与 AP |
| RoI 分层把 canonical level 当像素尺度 | 20 px 目标被送到 /16，参考应为 /4 |
| `LIM_WORKER_ANCHOR_SIZES` 先按整数解析失败后静默回退 | 本预声明的 5×4 anchor 实际会按 4×4 运行 |

四项已修（`0a9993a`），并加了确定性回归；审计项 `T10_DETECTOR`。修复后：
v6 的低分不能再归因于"冻结主干的能力上限"；下一个门槛是 **G1 参考校准**（用参考实现
在同一数据上证明管线能达到合理水平），而不是再加预算。原来的 anchor 覆盖率也应改按
`RPN_POSITIVE = 0.7` 的口径引用（锁定集 14.2%，候选集 42.8%），不是 IoU>0.5 的 24.5%/93.7%。
