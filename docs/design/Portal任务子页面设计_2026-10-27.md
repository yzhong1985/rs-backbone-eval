# Portal 任务子页面设计（T1–T8）

日期：2026-10-27
状态：**已实施（PR1 后端 + PR2 前端 + 8 个任务的 notes）；跨任务对比页已加**
范围：设计与实施记录（2026-10-27 当日落地）

## 一、目标与非目标

### 目标

1. 每个任务（T1、T1S、T2…T8）有独立页面，可直达、可分享链接；
2. 每页回答四个问题：**这是什么任务 / 用了什么数据与模型 / 各轨道当前分数 / 现在能得出什么结论**；
3. 页面上的数字必须与报告、矩阵**逐个一致**（同一套准入规则，不允许前端再算一遍）；
4. 结论要标"截至什么时候、依据哪个提交"，避免把旧结论当现状。

### 非目标

- 不做登录/权限（Portal 只读、单会话隧道已够）；
- 不做在线编辑（结论写在仓库里，走 git 评审）；
- 不新增任何聚合逻辑（复用 `build_matrix` + `excluded_run_ids`）；
- 不引入前端构建工具（`web/` 保持无构建静态站）。

## 二、信息架构

```text
#/                     总览（现有首页：矩阵 + 下载 + 运行表）
#/task/T1              任务页
#/task/T1S
#/task/T2 … #/task/T8
#/runs/<run_id>        单条运行（可选，后续再做）
```

- 采用 **hash 路由**：静态文件服务器无需 catch-all，刷新、分享、后退都可用；
- 任务列表页 = 现有首页顶部新增一排"任务卡"（8 个），点击进入子页面；
- 未跑的任务（T6a/T6b/T7）也显示卡片，标注"未建数据/未跑"。

## 四、内容来源与"单一真相"

| 区块 | 数据来源 | 自动/人工 |
|---|---|---|
| 任务名、传感器、波段、类别数、指标、`background_class` | `configs/tasks/*.yaml`（`Registry`） | 自动 |
| 数据集、划分规模、manifest sha、组重叠 | 现有 `report._manifest_summary` / `_split_overlap` | 自动 |
| 一句话结论、关键发现、人工局限 | **`configs/tasks/*.yaml` 新增 `notes:` 块** | **人工** |
| 各轨道成绩 | `build_matrix()`（与报告/首页同一函数） | 自动 |
| 单种子 / 被排除 / 无正式结果 警告 | 由 cells 与 `excluded_run_ids` 推导 | 自动 |
| 相关文档链接 | 固定路径约定 | 自动 |

### 为什么把结论放在 `configs/tasks/*.yaml` 而不是 `docs/`

1. **和任务定义同文件**：改任务、改结论在同一个 PR 里，避免"配置变了结论没变"；
2. **有 schema 校验**：`RegistryModel` 是 `extra="forbid"`，写错字段直接报错，不会静默失效；
3. **前端不需要 Markdown 解析器**：结构化字段（`summary` / `findings[]` / `caveats[]`）直接渲染成段落与列表，符合"无构建静态前端"的约束；
4. 若将来需要长文，再在页脚挂 `docs/reports/` 的链接，不塞进页面。

建议 schema（新增，向后兼容）：

```python
class TaskNotes(RegistryModel):
    updated: str                    # 结论的时效
    summary: str                    # 一句话
    findings: list[str] = []        # 3–5 条
    caveats: list[str] = []         # 人工补充的局限
```

任务配置示例：

```yaml
task_id: T2
# … 现有字段 …
notes:
  updated: 2026-10-27
  summary: "Prithvi 全量微调最强（0.769）；AnySat 全量微调反而下降 0.115。"
  findings:
    - "B1 相对 B2 的增益与预训练数据是否同源强相关：Prithvi +0.137，AnySat −0.115。"
    - "Clay 冻结 0.621 与全量微调 0.631 基本持平。"
  caveats:
    - "AnySat B1 的三种子方差较大（sd 0.070），解读需谨慎。"
```

## 五、新增 API

### `GET /api/tasks`

任务清单，用于首页卡片：

```json
{
  "items": [
    {
      "task_id": "T2",
      "name": "火烧迹地",
      "application": "Wildfire Scars",
      "dataset_id": "hls_burn_scars",
      "sensor": "hls",
      "metric": "burn_scar_iou",
      "suite": "in_suite",
      "cells": 6,
      "models": 3,
      "seeds_max": 3,
      "has_notes": true,
      "notes_updated": "2026-10-27"
    }
  ],
  "tracks": [{"id": "B0", "name": "Prithvi 参考复现", "description": "…"}]
}
```

### `GET /api/tasks/{task_id}`

```json
{
  "spec": { "...": "TaskSpec 全部字段（含 background_class、official_config_url）" },
  "dataset": {
    "manifest_sha256": "6a0229…",
    "splits": {"train": 252, "validation": 89, "test": 90},
    "split_overlap": {"train_test_groups": 119, "test_groups": 186}
  },
  "cells": [ "…与 /api/matrix 的 cell 结构完全一致…" ],
  "notes": { "updated": "…", "summary": "…", "findings": [], "caveats": [] },
  "warnings": [
    {"kind": "single_seed", "cell": "AnySat/B1", "text": "该单元仅 1 个种子"},
    {"kind": "group_overlap", "text": "train 与 test 存在 119 个重叠 group"},
    {"kind": "excluded_runs", "count": 4, "text": "4 条记录因审计/短跑被排除"}
  ],
  "runs": [ "…最近 20 条 public_summary…" ]
}
```

实现要点：

- 两个端点都**复用** `build_matrix()` 与 `excluded_run_ids()`，与报告、首页同源；
- `notes` 缺失时返回 `null`，前端显示"尚未撰写结论（待补）"；
- `warnings` 全部由数据推导，不由人工填写，避免"漏写警告"；
- `task_id` 不存在 → 404。

## 六、一致性保证（必须有测试）

1. **同一数字**：对同一 `task_id`，`/api/tasks/{id}.cells` 与 `/api/matrix` 中该任务的 cell **逐字段相等**（新增测试，遍历所有任务断言）；
2. **准入一致**：页面上出现的单元集合 == 报告主表该任务的行集合（用 `build_matrix` 的 cells 直接比对）；
3. **不显示被排除记录为成绩**：`runs` 列表里被排除的记录必须带 `excluded` 标记与原因；
4. 现有 `tests/test_portal.py` 已覆盖 200/404/静态资源，新端点补 3 个用例（正常、缺 notes、未知 task）。

## 七、边界与降级

| 情况 | 页面表现 |
|---|---|
| 任务无正式结果（T6a/T6b/T7） | 卡片置灰 + "未建数据/未跑"；页面显示数据集说明与"暂无成绩" |
| 单元只有 1 个种子 | 表格 `n=1`，并显示自动警告徽标 |
| 有被排除/短跑记录 | 运行列表显示，但标灰并注明原因，不计入成绩 |
| 任务无 `notes` | 显示"尚未撰写结论"，**不自动生成结论** |
| T1S / T8（域外轨） | 页头徽标 "域外轨，不并入 D1" |
| 数据/模型不匹配 | 不猜测，直接显示"该模型未在此任务上运行" |

## 九、风险

| 风险 | 缓解 |
|---|---|
| 页面与报告口径漂移 | 同一函数 + 一致性测试（§六.1） |
