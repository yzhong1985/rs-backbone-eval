# Portal 公网访问（frp + 共享 token）

日期：2026-10-28
状态：token 已启用；frp 代理已注册；**公网入口还需服务器侧的 nginx 映射**

## 1. 为什么需要 token

Portal 只读 `run.json`，本身没有任何用户体系（代码里没有账号、角色、会话）。一旦通过 frp 暴露到公网，任何拿到地址的人都能：

- 读取全部结果、结论与运行明细；
- 调用 `POST /api/downloads/{id}/start|pause|verify`（会真的触发下载任务）。

因此公网暴露必须同时开启共享 token。同事没有 SSH 权限也能用：只需要地址 + token。

## 2. token 的工作方式

启动脚本从 `.env` 读取 `RS_EVAL_PORTAL_TOKEN`，注入 Portal 进程。设置后，除 `/api/health` 外的所有路由都要求凭证：

| 方式 | 适用场景 |
|---|---|
| `https://<host>/?key=<token>` | 发给同事的链接，打开后种 30 天 HttpOnly cookie，之后正常浏览 |
| HTTP Basic，用户名任意、密码 = token | curl / 脚本 / 浏览器弹窗 |
| 不带凭证 | 返回 `401` + `WWW-Authenticate: Basic` |

cookie 里存的是 `sha256("rs-eval:" + token)`，不是 token 原文。清空 `.env` 里的值并重启即关闭鉴权（本机开发用）。

```bash
# 开启/关闭
echo "RS_EVAL_PORTAL_TOKEN=<token>" >> .env   # 关闭则写成空值
./scripts/portal_server.sh restart
./scripts/portal_server.sh status            # 会打印 auth: 已启用/未启用
```

## 3. frp 代理

`/etc/frp/frpc.toml` 追加（备份 `frpc.toml.bak-20261028`）：

```toml
[[proxies]]
name = "rs-eval-portal"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8080
remotePort = 18080
```

`sudo systemctl restart frpc` 后日志确认：

```
proxy added: [gpustack rs-eval-portal ssh-89 trading-pilot]
[rs-eval-portal] start proxy success
```

**注意**：Portal 仍然只监听 `127.0.0.1:8080`，frpc 在同机，所以不需要改 `RS_EVAL_PORTAL_HOST`，也不要把 8080 绑到 `0.0.0.0`。

## 4. 公网入口（服务器侧）

本机到 `superderp.cn` 只有 `7000`（frps 控制端口）可连，`6101 / 8001 / 3080 / 18080` 全部超时。这与 `frpc.toml` 里的注释一致：

> ssh 经 nginx stream：公网 6001 -> 127.0.0.1:6101

也就是说 frps 的 remotePort 只在本机回环上监听，公网由服务器的 nginx 再映射一层。因此 18080 还需要在**服务器**上开一个入口，二选一：

**A. 裸 TCP（最快，HTTP 明文）**

```nginx
# /etc/nginx/nginx.conf 的 stream {} 块内
server {
    listen 6002;
    proxy_pass 127.0.0.1:18080;
}
```

同事访问 `http://superderp.cn:6002/?key=<token>`。token 与 cookie 走明文，只适合内网/临时。

**B. 子域名 + TLS（推荐）**

```nginx
# http {} 块内
server {
    listen 443 ssl;
    server_name rs-eval.superderp.cn;
    ssl_certificate     /etc/letsencrypt/live/rs-eval.superderp.cn/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/rs-eval.superderp.cn/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:18080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        client_max_body_size 0;
    }
}
```

同事访问 `https://rs-eval.superderp.cn/?key=<token>`，之后 cookie 生效。

## 5. 验证清单

```bash
# 本机：token 生效
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/            # 401
curl -s -o /dev/null -w '%{http_code}\n' -u "x:$TOKEN" http://127.0.0.1:8080/api/summary  # 200
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/api/health  # 200

# 公网（在服务器侧映射完成后，从外网执行）
curl -s -o /dev/null -w '%{http_code}\n' http://superderp.cn:6002/api/health
```

## 6. 已知限制

- 只有一层共享 token：**无法区分是谁在访问**，也无法单独吊销某个人。轮换 = 改 `.env` 里的值并重启，所有人一起失效。
- 没有速率限制。token 足够长（24 字节随机）时暴力枚举不现实，但建议以后加 `limit_req`。
- 导出报告（`/api/report.md`）同样受 token 保护。
- 波长消融等诊断实验在 `runs-diagnostics`，不在 Portal 与导出报告范围内。
