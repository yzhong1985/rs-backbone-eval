# 实验执行方案 v3.4：复核意见与落地口径（2026-11-17）

- 被复核文档：`docs/design/实验执行方案_v3.4.md`（以及前一版 `实验执行方案_v3.1.md`）
- 落地框架：`docs/design/code_artifact_v3_落地计划.md`（六臂进 `workers/lim`，走账本）
- 结论：**研究设计可作为主线；§5 代码不能原样使用**。原样运行 G0a 第 2 项即失败；
  修 4 处测试、1 处模型代码后 8 项全部通过。代码按本文 §2 修正后移植进 worker。
- 主验证场：**WHU-OPT-SAR（T13）**。FBP 只作后续扩展（见 §4）。

## 1. 复核方法

把 v3.4 §5.1 / §5.2 两个代码块原样抽出到临时目录，在 LIM worker 环境
（`workers/lim/.venv`）里以 `CUDA_VISIBLE_DEVICES=""` 运行 `test_g0a_verification.py`；
每遇到一个失败先定位原因、做最小修改，再继续跑后面的项。仓库内文件未改动。

## 2. 发现的问题

| 位置 | 问题 | 性质 | 处理 |
|---|---|---|---|
| G0a-2 参数量 | 插件总参数实测 **616,096**（文档 829,088）；冻结字典后可训练 **583,328**（文档 796,320）。差额全在 `deep_aef_injectors`：实测 215,040，文档 428,032 —— 代码中注入器中间层是 `max(64, 2×64)=128`，文档按 256 计算 | 文档参数表错误 | 以实测为准；移植后按真实 LIM 通道重算并由测试断言 |
| G0a-3 梯度隔离 | 测试先冻结浅层注入器，但 `get_trainable_parameters()` 会把插件内**所有**参数重新设为 `requires_grad=True`，浅层路径第 2 步就把梯度送到 stem，隔离失效；测试文件缺 `import torch.nn.functional as F` | 测试 bug；接口会静默覆盖调用方的冻结设置 | 接口改为只读（不改 `requires_grad`），冻结由显式配置决定 |
| G0a-4 | 测试只给 500 个 AEF 样本，字典 K=512，`fit_and_init_codebook_kmeans` 正确地拒绝 | 测试 bug | 样本数 ≥ K |
| **G0a-5 插件热切换** | `load_province_plugin()` 新建的插件默认处于 train 模式；整体模型已 `eval()` 时，换省后推理仍按 `nir_drop_prob` 随机丢弃 NIR 支路，输出最大偏差 0.062（logits 量级 0.58） | **真 bug，影响部署** | 加载后 `self.provincial_plugin.train(self.training)`；测试覆盖“eval 模型热切换后输出确定” |
| 通道 | 全文按 `[128,256,512,1024]` | 与本仓库 LIM（MiT-Huge，256/512/1024/2048，stride 4/8/16/32）不符 | 用真实通道；全部参数量重算 |
| 运行方式 | 独立脚本，绕过 dispatch / `run.json` | 违反 AGENTS 账本规则 | 移植为 worker 内模块 + 协议 |
| 种子 | 未固定 / 前版用 `20261103..05` | 与仓库约定不符 | 17 / 42 / 73，每个门直接 3 种子 |

`load_merged_province_checkpoint()` 返回前调用了 `model.eval()`，没有同样的问题。

## 3. 设计层面的说明

1. **G5（E0–E3 区域对照）在 WHU 上无法按原意执行**：WHU 全部位于湖北，没有第二个省；
   FBP 是 24 类、WHU 是 7 类，共享公共分类头时不能做跨数据集错配互测。可选替代：
   WHU 内按图幅经度切东/西两个伪区域；或在 FBP 内部按省分组（每省景数少、且有
   1–3 年时间错位）。**不阻塞 G0–G4**，G3 结果出来后再定。
2. **冻结特征缓存**：主干冻结时缓存四级 LIM 特征（fp16，512 切片每片约 16 MB；
   80 幅训练图约 1 万片，合计约 160 GB，放根盘）。缓存模式下禁用几何增广
   （或对每个增广方向单独缓存），与修订意见一致。
3. **WHU 影像年份需核实**后再定 AEF 年份；当前已验证的是 AEF 2019（`WHU_OPT_SAR_接入说明` §7）。
4. P 的先验不高：PASTIS 上“把教师投影拼进下游头”已是负结果（−0.0074，3/3 负）。
   `P − Bcap < 0.6 pt` 则采纳 Bcap 的门槛必须保留。

## 4. 执行口径（对 v3.4 §4.1 的落地）

| 阶段 | 内容 | 放行条件 |
|---|---|---|
| S0 工程 | T13 task（8 类、`ignore_index=0`，背景仅占 0.001%；同时报 closed7）、图幅级划分（官方 80/20，train 留 8 幅作 val）、512 切片 / 步长 384、manifest 记录图幅号与 bbox；`arms.py`（真实通道 + §2 修复）；G0a 8 项改写为 CPU 单测；协议注册 | CI 全绿 |
| S0' AEF | 湖北 2019 共 53 块，按图幅窗口裁剪（约 28 GB），沿用 FBP 抽取的南向上读取、跨瓦片拼接、fill 率检查 | 100 幅 fill 率表 |
| G0b | 真实 LIM 前向/反向、32 片过拟合、重投影到 UTM 49N/50N 后叠图 QC | 配准 ≤ 10 m、loss 下降无 NaN |
| G1 | B0：seed 17 扫 lr `1e-4 / 1e-3 / 3e-3`，选定后 3 种子；R、R_null（全零、跨图打乱）3 种子 | R − B0 ≥ +1 pt 且 R_null ≈ 0；不过门即停 |
| G2 | D、P、Bcap，3 种子 | 均值 ≥ +1 pt 且最差种子 ≥ 对照 −0.3 pt；`P − Bcap < 0.6 pt` 采纳 Bcap |
| G3 | 字典（随机 / AEF K-Means）× λ（0 / >0）2×2 | 描述性归因 |
| G4/G5 | 难例分析；区域对照按 §3.1 再定 | — |

每个门的判据在开跑前写进对应执行说明，写死后不改。
