# T13 LIM NIR 与 SAR 插件融合实验实施计划

**2026-11-24 · v3 · Agent 实施与验收用**

以同种子、同数据划分的纯 RGB 全量微调 LIM（FT-B0）为起点，判断 NIR、配对 SAR 及两者组合能否提升 T13 分割。第一批只做基线回归、NIR 小 CNN、四通道首层对照和通过配准验收的 SAR 小 CNN。首批交付为可复现的 seed 17 验证集结果。预训练 NIR 编码器、注意力、三种子和联合实验按下文条件推进。本计划基于 v2 草案，原案中的 AEF 结果用于说明选择 FT-B0 的背景。 [仓库原方案](T13_LIM_NIR与SAR插件融合实验方案_2026-11-24.md) [FT-B0 方案](实验执行方案_v3.4_补充_FT_2026-11-19.md)

## 1. 执行顺序

| 顺序 | Agent 要做的事 | 验收后可推进 |
| --- | --- | --- |
| 1 | 核对 seed 17 FT-B0 账本和权重，固定 manifest，完成 SAR 索引及配准抽查。 | RGB/NIR 与 SAR 各自按输入是否就绪推进。 |
| 2 | 接通普通 dispatch/queue 入口、训练与只验证模式、拼接评估和分支产物。跑 CPU 回归。 | 部署固定提交后跑 4090 smoke。 |
| 3 | 在 4090 上分别跑 RGB 回归、NIR CNN、四通道首层、SAR CNN 的 smoke。 | 每臂通过后才能投入 20 epoch。 |
| 4 | 跑 seed 17 的 RGB 验证和通过 smoke 的增量臂。汇总同种子差值、边界指标及成本。 | 交付首批结果。保留四通道结果作为 NIR 对照。 |
| 5 | 执行通过门槛的三种子配对和 SAR 错配控制。可并行做冻结预训练 NIR 编码器的真实窗口前向预检。 | 按验证结果选定交付候选。预训练及注意力独立判断是否投入完整训练。 |
| 6 | 双插件均通过后测联合。锁定所有候选、基线、权重、评估模式后，再评测试集。 | 交付逐种子结果、运行记录、权重及复现命令。 |

## 2. 固定基线与数据

- **基线身份。** 在部署环境先跑 `uv run rs-eval doctor`，从账本确认 seed 17 的 `lim_mit_huge/T13/whu_ft_b0` 为 `completed`、完成 20 epoch、未 superseded、通过审计，且有 `best_full_checkpoint.pt`。明确指定 run ID，锁定基线训练提交、原 backbone SHA、manifest SHA、完整检查点 SHA、precision 和预处理。加载时校验 task、model、protocol、seed、训练预算、状态和哈希，严格恢复 LIM 与 UPerNet 两套权重。后续 seed 42、73 逐个核验，缺完整基线就先用同一配方补跑对应 FT-B0。 [T13 检查点和输入实现](../../workers/lim/src/lim_worker/t13.py)
- **固定样本和指标分母。** 通过 `RS_EVAL_MANIFEST` 固定基线用过的 manifest，审计 72/8/20 图幅划分、无跨 split 图幅、无 schema 错误。保留 512×512 窗口、步长 384、末块贴边和原拼接规则。RGB 用原 ImageNet 归一化，NIR 读光学第 4 波段。RGB/NIR/SAR/有效掩码/标签共用翻转。标签 0 始终忽略，所有臂保留同一批图幅与标签像素。
- **SAR 索引与统计。** 复用现有 `sar_index.py` 和 `T13Tiles`。对 100 幅核对配对唯一性、路径、尺寸、波段、dtype、窗口边界和文件 SHA，保存索引 SHA 及配准版本。NIR、SAR 各自只用训练 split 中的有效像素拟合并固化归一化统计，所有同模态对照复用。首轮按发布版 SAR uint8 编码值处理。有效区优先采用可核验的 coverage mask；整幅已知有覆盖且没有可信像素级掩码时可用全有效，并记录依据。零值和低回波保留。缺测的输入在进分支前屏蔽，分支输出再乘有效掩码。审计失败时停对应数据臂。
- **SAR 配准验收。** 先固定抽样和控制点选择规则。建议抽 12 幅训练、验证图幅，每幅至少 5 个可辨控制点，覆盖平原、丘陵、城镇及图幅中心和边缘。存 RGB/SAR 叠图、控制点坐标、`dx/dy`，汇总原图像素单位的中位、P95、分图幅误差及明显局部形变。首轮用融合 stride 的四分之一作为工程阈值。P95 ≤4 px 且无明显系统性局部错位时启用 stride 16/32。4 px < P95 ≤8 px 且粗尺度仍对齐时只启用 stride 32。超过 8 px 或粗尺度也失配时暂停 SAR 训练，用训练图幅定校正规则、在验证图幅复核，再锁定版本。测试图幅只应用事先冻结的规则。 [SAR 数据读取](../../workers/lim/src/lim_worker/t13_data.py) [SAR 图幅索引](../../workers/lim/src/lim_worker/sar_index.py)

## 3. 首批实现与训练

| 实验臂 | 接入方式 | 更新的参数 |
| --- | --- | --- |
| RGB 回归 | 严格加载同 seed FT-B0，走新评估入口，关闭所有插件。 | 无。 |
| NIR CNN | 单通道小 CNN，LIM stride 8/16 处加投影残差。 | NIR CNN 和投影。 |
| 四通道首层 | 原 RGB patch embedding 保持冻结，将结构等效的独立单通道卷积输出加到原卷积输出，位置在原 token 归一化之前；无新增 bias。 | 新的 NIR 通道权重。 |
| 配对 SAR CNN | 单通道小 CNN，LIM stride 16/32 或仅 stride 32，按第 2 节锁定；RGB/SAR 上下文生成门控后加投影残差。 | SAR CNN、门控和投影。 |

1. **训练配方。** 各训练臂从同一个 FT-B0 权重出发，LIM/UPerNet 始终 eval 且冻结，只有新增模块进入优化器。CUDA 沿用 FT-B0 的 bf16 autocast 与 FP32 权重，CPU 用 FP32。分割 CE、20 epoch、AdamW、LR `1e-3`、weight decay `1e-4`，首 epoch warmup 后 cosine，每 5 epoch 评验证，按验证 mIoU 选权重。以 micro 2 × 累积 4 起步，正式比较固定有效 batch 8、每 seed 样本顺序、完整更新数和精度。若显存需要改 micro batch，优先对同一比较组统一调整并记录。累积组的 CE 按该组有效标签像素计权。
2. **初始化与回退。** 投影和新增首层卷积零初始化，SAR 门控初始允许投影收到梯度。全部关闭或缺失时直接走 RGB 路径；联合模式单缺时复现对应另一个单分支。部分缺测时，分支输入显式清理无效值，按固定规则对齐有效掩码，对应尺度的残差在无效位置为零。对分支内池化，用有效像素作分母，全无效输出零。UPerNet 仍使用完整融合特征。其卷积和池化会传播上下文，片内缺测区的最终预测用实测指标描述。 [残差模块](../../workers/lim/src/lim_worker/fusion_branches.py) [UPerNet](../../src/rs_backbone_eval/heads.py)
3. **梯度与训练路径。** 深层插件可在 `no_grad` 下提取 RGB 特征，融合后的 UPerNet 要可向新增模块反传。四通道首层对照的后续 LIM 和 UPerNet 均要保留对输入的梯度。将新增诊断协议接入 `configs/protocols/`、LIM runner allowlist 和 T13 worker，声明 `panel: diagnostic`。复用 `RunWriter`、T13 数据读写和图幅拼接。普通 `train` 筛选运行只评验证集并保存最佳产物，防止 T13 现有训练末尾自动评 test 的行为流入新协议。用显式 `evaluate` 加已锁定输入运行最终测试。既有 T13 协议行为沿用原实现。 [协议字段](../../src/rs_backbone_eval/registry.py) [T13 训练与评估](../../workers/lim/src/lim_worker/t13.py)
4. **插件产物。** 单独保存新增权重和带版本的配置，绑定基线 run ID 和完整检查点 SHA。记录 manifest SHA、SAR 索引 SHA、归一化、波段顺序、融合尺度、精度、已启用模态、最佳 epoch 和权重 SHA。必要的冻结预训练编码器也绑定实现版本和权重 SHA。加载时严格核对基线与分支配置。联合直接组合保存两份插件的引用；联合训练另存一套产物。通过 worker 录入账本。

### 验收后再开 20 epoch

- **CPU 回归。** 用小网络和 `tmp_path` 覆盖入口与旧 T13 回归、检查点身份不匹配、RGB 回退、初始化等价、不同尺度和掩码、同步翻转、SAR 索引验证、训练集统计、冻结与反传、产物往返、筛选路径无法读取测试影像和标签。比对同输入、同设备、同精度的 RGB logits。直接复用 RGB 路径要求相等，零初始化等价按预先固定的数值容差验收，同时核对 argmax。片内缺测测试在融合尺度核对残差为零，并检查最终输出有限。运行 registry、dispatch、LIM T13、fusion、SAR 回归；涉及结果准入时补 matrix、report、Portal 相关测试。CPU 测试用 stub，不依赖外部数据或 GPU。
- **4090 smoke。** 从固定提交部署，按仓库说明用 dispatch/queue 和 GPU 锁机制运行。每个训练臂至少跑两个完整累积组（micro 2 × 累积 4 时至少 8 个 micro-batch）并核对至少一次非零 LR 更新、梯度有限且非零、对应权重变化、LIM/UPerNet 权重未变、loss 有限、验证及产物可读。至少用一幅真实完整验证图幅确认拼接与指标。记录每步耗时、显存、估算的正式运行时间。RGB 回归无需训练，验证同一检查点通过原路径和新路径所得的 logits 及验证 mIoU。通过后才排该臂完整训练。

## 4. 条件追加的实验

### SAR 错配与三种子

seed 17 配对 SAR 达到增益门槛后，先构建固定的各 split 内跨图幅错配表，要求 donor 与目标来自不同图幅，尽量按尺寸和有效覆盖匹配。同位置读取 donor 窗口；尺寸不同时移动到最近的合法位置，记录移动次数和距离。固定并保存映射及 SHA，训练和验证均使用各自 split 的错配输入，最终测试仅按事先锁定的映射规则取 donor。真实配对和错配共用归一化、训练预算及标签集合，报告总体及逐图幅有效覆盖差。如果可见范围明显不同，按同一共同有效掩码补一对匹配对照，再据此判断同位置的贡献。仅推理换错配输入可以作为诊断。

seed 17 过门槛的臂补 seed 42、73；NIR 保留四通道首层对照，SAR 保留三种子的配对与错配。每个种子都有自己的 FT-B0，沿用相同数据及训练配方，比较相同种子的配对差。SAR 的同位置收益以配对减错配的平均差为正、至少 2/3 种子为正作为支撑条件，同时报告全部差值和覆盖情况。

### 冻结预训练 NIR 编码器

首批结果和阶段耗时汇总后，再决定是否为预训练编码器安排完整筛选。每个编码器先用真实 512 窗口做输入、空间输出、回退和 4090 性能预检。统一只接 LIM stride 16（32×32），共用 1×1 零初始化投影接口，并加入只接 stride 16 的同尺度 NIR 小 CNN 对照。预训练臂冻结编码器，只训练投影；CNN 对照训练 CNN 与投影。各臂冻结同一 FT-B0，结果比较的是完整分支方案。若需单独归因预训练，再加同结构随机冻结权重对照。

| 编码器 | 实现与前向验收 |
| --- | --- |
| Galileo-Nano | 固定上游版本、`config.json`、`encoder.pt` 与权重 SHA。直接走 `Encoder` 的空间输出，一时相，GF-1 第 4 波段映射到 `S2_NIR_10m`（B8），其余组显式掩蔽；记录月份、patch size 与输入 GSD。固定并记录 GF-1 到模型输入的映射及分布，uint8 按发布版编码处理。检查屏蔽组数值变化不会影响提取的 NIR 特征，验证原生网格到 32×32 的空间映射。 [上游编码器](https://github.com/nasaharvest/galileo/blob/main/src/galileo.py) [波段组](https://github.com/nasaharvest/galileo/blob/main/src/data/dataset.py) [Nano 权重](https://huggingface.co/nasaharvest/galileo/tree/main/models/nano) |
| DOFA-Base | 固定上游版本与 `DOFA_ViT_base_e100.pth` SHA，从经核验的 GF-1 相机资料取单波段中心波长（µm），缺依据则暂缓该臂。加载原权重后，将 patch 位置编码从 14×14 适配到 32×32，保留 CLS 位置，记录插值或重建方式。输出池化前的 patch token，去除 CLS 后还原为 32×32 空间特征。 [上游实现](https://github.com/zhu-xlab/DOFA/blob/master/dofa_v1.py) [Base 权重](https://huggingface.co/earthflow/DOFA/blob/main/DOFA_ViT_base_e100.pth) |

预检交付真实训练及验证窗口上的输入统计、空间对齐检查、有限且随图像变化的特征、在线延迟、显存、总新增参数与可训练参数。通过后按相同预算跑 seed 17，与 RGB 和同尺度 CNN 分别比较。超过交付成本门槛的结果单列为研究结果；做这种 20 epoch 对照前单独记录实测预算和选做理由。依赖留在 LIM worker 环境。

### NIR 注意力与联合输入

- **NIR 注意力。** 锁定一个通过验证筛选、成本符合目标的 stride 16 NIR 编码器。各臂共用同一份冻结权重。若选中 CNN，则冻结筛选所得 CNN，重新训练残差和注意力各自的连接层。先比较同位置残差和 RGB 作 Q、NIR 作 K/V 的局部单向交叉注意力，固定 4×4 token 窗口。屏蔽无效 NIR 与越界填充，遇全掩码窗口直接输出零修正。遵守第 5 节相对 RGB 和同编码器残差的双重门槛。单向完成三种子配对且通过门槛后，才考虑追加 MaRS 式双向 MMA；沿用同宽度和窗口，报告相对单向的新增收益与成本。 [MaRS 方法](https://rsidea.whu.edu.cn/mars.htm)
- **联合输入。** NIR 和 SAR 各自通过三种子和交付门槛后，先在各对应 seed 的 FT-B0 上加载独立训练的插件，只在验证集测直接组合。报告联合分别减去 NIR、SAR 的差值，以及交互项 `联合 − NIR − SAR + RGB`。直接组合达标则锁定该方案；若有增益但未达准入条件、仍在延迟预算内，可先做一次 seed 17 联合训练并在验证集重新走门槛。锁定后评同时启用、缺 NIR、缺 SAR、全缺四种模式。

## 5. 门槛、最终测试与交接

以下增益均指验证集 7 类 mIoU 的同种子差值，单位为百分点。表中三种子均值按种子等权。

| 决策 | 执行阈值 |
| --- | --- |
| 增量臂 seed 17 扩到三种子 | 相对同种子 FT-B0 ≥0.5。四通道和错配是随主臂保留的对照。 |
| 单分支三种子通过 | 相对 FT-B0 均值 ≥0.5 且至少 2/3 种子为正。 |
| 注意力升级 | 仍满足相对 FT-B0 的门槛，且相对同编码器同尺度残差，seed 17 至少 +0.25 才扩种子，复核时均值至少 +0.25 且至少 2/3 种子为正。双向追加后以单向作同样的增量对照。 |
| 联合输入交付 | 相对验证集三种子均值更优的单分支，配对均值至少 +0.25 且至少 2/3 种子为正；同时满足联合延迟预算。 |
| 交付成本 | 单分支总新增参数目标 ≤100 万（计入冻结编码器），单插件端到端中位延迟增幅 ≤15%，联合 ≤25%。同时列出 P95、峰值显存和可训练参数。 |

1. **统一计时。** 同一张 4090、同精度、batch 1、512×512，同一组真实窗口和顺序，各臂预热 20 次后计至少 100 次。同步 GPU 计时，统一 IO 缓存状态并记录。给出 TIFF 读取、预处理、模型前向和整条路径的中位及 P95，SAR TIFF 读取和预训练编码器在线前向计入总成本。
2. **统一指标。** 在逐图幅拼接预测上统计忽略标签 0 的 7 类 mIoU、逐类 IoU 和逐图幅配对差。另算原图 2 像素内侧边界带的 Boundary IoU，排除靠近未标注像素和图幅外边界的位置，同一有效区累计交并、空并集记缺项。报告宏平均、道路 Boundary IoU 和道路普通 IoU，附代表性图幅叠图。验证若退化，记录幅度及是否改变交付候选的原因，检查点仍按验证 mIoU 选择。 [Boundary IoU 原论文](https://openaccess.thecvf.com/content/CVPR2021/html/Cheng_Boundary_IoU_Improving_Object-Centric_Image_Segmentation_Evaluation_CVPR_2021_paper.html)
3. **锁定后测试。** 测试前留存候选、对照、seed、权重 SHA、配置、掩码规则和所需评估模式清单。固定输入后以 `evaluate` 一次性生成结果。报告同种子差、均值、最差种子及边界变化。此前账本中的 RGB 测试分数用于复核同一基线，候选筛选只读取验证指标。
4. **交接清单。** 首批交付实现提交 SHA、CPU 回归和 4090 smoke 结果、数据验收证据路径、seed 17 基线和各臂 run ID/权重 SHA、配对指标、计时及门槛判定。后续交付补齐三种子、错配及已触发的追加实验。给出可复现的 dispatch/queue/evaluate 命令及固定配置。生产运行通过部署 checkout 及 worker 账本创建，重试用新 `-vN` run ID，报告与随运行产出的证据按仓库目录规则存放。 [部署与队列约定](../../AGENTS.md)

**当前状态。** 计划依据开发仓库 `e58185b`。现有分支模块、SAR 索引及窗口读取可复用。真实图幅配准、FT-B0 权重可用性、新协议入口和 4090 时延均待执行 Agent 验证。
