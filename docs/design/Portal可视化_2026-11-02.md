# Portal 可视化：每个任务识别了什么、对在哪、错在哪

日期：2026-11-02。状态：**设计稿，待评审后实现**。
关联：`docs/design/Portal公网访问_2026-10-28.md`、`web/`（无构建静态前端）、
`src/rs_backbone_eval/portal/app.py`。

## 1. 目标与非目标

**目标**：在 Portal 的 run 页上，对每个任务直接看到

1. 模型在这张图上识别出了什么（区域/框/类别/置信度）；
2. 和标注比，哪些是对的、哪些是错的（漏检、误检、边界误差）；
3. 这些样本是怎么挑出来的（可复现，不是挑好看的）。

**非目标**：不做在线推理服务（Portal 只读、不加载模型）；不做全测试集的可视化浏览
（成本高、价值低）；不改任何指标口径。

## 2. 数据从哪来：按需生成，不在训练时落盘

目前的 worker 只写 `run.json` 和 checkpoint，不保存预测。为了可视化而在训练/评测时
落盘所有预测，会让每次正式 run 多写几十 GB，且大部分没人看。

因此采用**离线生成**：新增 `scripts/visualize_run.py`，用 run 的 checkpoint 在少量
测试样本上重跑推理，把图写进 `runs/<run_id>/visualization/`，由 Portal 当普通产物读取。
生成过程不写 `run.json`、不改指标、不进入准入规则。

```
runs/<run_id>/
  run.json
  best_checkpoint.pt  /  head_only.pt
  visualization/
    manifest.json          # 选择规则、每样本指标、类别与颜色
    samples/<sample_id>.png
```

## 3. 脚本设计

```bash
# 在对应 worker 环境里跑（需要 torch/rasterio）
uv run --project workers/<model> python scripts/visualize_run.py \
  --run-id lim_mit_huge-T10-rotated_frozen-train-17-v6 \
  --samples 9 --seed 17
```

| 参数 | 说明 |
| --- | --- |
| `--run-id` / `--runs-root` | 定位 `request.json`、`best_checkpoint.pt`（优先 best，缺失时用 head_only） |
| `--samples` | 每个桶取几张，默认 3（共 9）；总数上限 12 |
| `--seed` | 选择规则的种子，**写进 manifest**；同 seed 同清单可复现 |
| `--split` | 默认 `test`；只允许 test/validation |
| `--force` | 覆盖已有 `visualization/`（默认拒绝） |

**样本选择（先定规则，再看结果）**

1. 从 manifest 的测试集里按 `sample_id` 的哈希排序，均匀抽样一个候选池（如 200 个）；
2. 在候选池上算每个样本的指标（分割：IoU；检测：匹配后的 TP/FP/FN）；
3. 分三桶，每桶取 `--samples` 个，桶内按哈希取，**不按指标排序**（避免只挑最好/最坏）：

| 桶 | 分割 | 检测 |
| --- | --- | --- |
| `hit` | IoU ≥ 0.7 | TP>0 且 FP=FN=0 |
| `partial` | 0.3 ≤ IoU < 0.7 | 有 TP 且有 FP 或 FN |
| `miss` | IoU < 0.3 或无预测 | TP=0 或（有 GT 但全漏） |

4. manifest 记录：候选池大小、每桶数量、被选中样本的 ID 与指标、丢弃的样本数。

**渲染**（每个样本一张组合图，PNG，宽度约 2000px）：

- 分割类（T1/T2/T3/T4/T5/T8/T9）：四联图
  `输入（RGB 合成） | GT | 预测 | 误差图`
  误差图：绿=TP、红=FP、蓝=FN、灰=ignore/无效区；角落标 IoU。
- 检测类（T10）：两联图
  `输入 + GT 框（绿） | 输入 + 预测（TP 绿 / FP 红 / FN 黄虚线）+ 分数`
  框上标类别名与分数；GT 与预测都按 le90 旋转框绘制。
- 输入渲染必须按任务声明的波段合成（HLS/S2 用 B4/B3/B2，SAR 用 VV/VH 灰度+青色），
  **不允许静默取前三个波段**；manifest 记录实际使用的波段。

**类别颜色**：T9 复用 iSAID 现有调色板；T1/T2 二值用单色；T10 的 37 类按框颜色循环，
图例只列出现频次最高的 6 类 + "其他"，完整映射写 manifest。

## 5. Portal 接入

**后端**（只读，不改准入规则）：

- `GET /api/runs/{run_id}/visualization` → 有 manifest 就返回，没有返回 `204`；
- 图片走现有的 `GET /api/artifacts/{run_id}/{path}`，不新增写路径；
- 只允许 `visualization/` 前缀，防止任意文件读取。

**前端**（run 页新增一节，位于"产物"之前）：

```
可视化                    [全部] [命中] [部分] [未命中]   ← 过滤桶
┌────────────┬────────────┐
│ 样本图（点击放大）        │ 右侧：指标、TP/FP/FN、类别   │
└────────────┴────────────┘
图例：GT / TP / FP / FN / ignore
```

- 没有 manifest 时显示一行说明 + 可复制的生成命令，而不是空白；
- 点击图片打开现有 drawer 的放大视图；
- 图注写明"样本按固定规则抽取，不代表测试集整体分布"。

## 6. 成本与存储

| 项 | 估计 |
| --- | --- |
| 生成耗时 | 单 run 9–12 张：分割约 1–3 分钟，检测（2445 tile 的 test split 里选 9 个）约 2–5 分钟 |
| 存储 | 每张 0.2–0.5 MB，单 run 约 3–6 MB |
| 训练路径 | 零改动；不增加正式 run 的耗时与磁盘 |
| Portal | 只读静态产物，不加缓存、不加载模型 |

## 7. 分阶段实现

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P0 | T9/T3/T4/T5 分割四联图 + manifest + Portal 图集与桶过滤 | 同一 seed 重跑生成相同清单；TP/FP/FN 颜色与图例一致；无 manifest 时给出生成命令 |
| P1 | T10 检测两联图（GT 框 / 预测框 + 分数） | 旋转框方向正确；FN 与 FP 分别可辨；类别名与分数可读 |
| P2 | 跨 run 对比（同一样本、两个 checkpoint 并排）与错误统计（FP/FN 面积直方图） | 同一清单可复用；统计口径写进 manifest |

## 8. 风险与边界

1. **选择偏差**：桶内按哈希而非指标排序，并在图注声明；不要把可视化当成精度证据。
2. **输入渲染误导**：必须用任务声明的波段，SAR/多光谱不能硬套 RGB；manifest 记录波段。
3. **磁盘**：按需生成、可删除；不随 run 永久保留（`scripts/prune_checkpoints.py` 不处理它，
   需要时手动删 `visualization/`）。
4. **旧 run 的 checkpoint**：`head_only.pt` 只有任务头时无法单独推理，manifest 要标明
   "只支持 best_checkpoint；head_only 需配合主干权重"。
5. **不改指标**：manifest 里的 per-sample 指标只用于分桶，不参与报告与评分卡。
