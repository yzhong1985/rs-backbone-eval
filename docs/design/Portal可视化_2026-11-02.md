# Portal 可视化：每个任务识别了什么、对在哪、错在哪

日期：2026-11-02（第 2 稿，响应 `Portal可视化与设计审查_c4513d1`）。
状态：**设计稿，待实现**。
关联：`docs/design/Portal公网访问_2026-10-28.md`、`web/`（无构建静态前端）、
`src/rs_backbone_eval/portal/app.py`、`src/rs_backbone_eval/prune.py`。

第 1 稿被指出的四个缺口在本稿补齐：回放支持范围（§2）、回放身份与"重评"语义（§7）、
样本单位与取景（§4）、多分类/空场景口径（§5）。另外修正了 `--samples` 歧义、哈希不稳定、
成本估算和示例 manifest（§6、§8、§10）。

## 1. 目标与非目标

**目标**：在 Portal 的 run 页上，对**可回放**的任务直接看到

1. 模型在这块区域识别出了什么（类别/框/置信度/掩膜）；
2. 和标注比，哪些是对的、哪些是错的（漏检、误检、类别互换、边界误差）；
3. 这些样本怎么选出来的（规则固定、可复现，不是挑好看的）。

**非目标**：

- 不做在线推理服务；Portal 只读产物，不加载模型、不改 `run.json`；
- 不做全测试集浏览（成本高、价值低）；
- **不改任何指标口径**；可视化里的 per-sample 数字只用于分桶，不进报告/评分卡；
- 不承诺"每个任务都能看"：没有权重的 run 明确显示不可用（§2）。

## 2. 回放支持范围（先决条件）

评审指出设计默认"已有 checkpoint"，与账本不符。实际规则如下（源码：`scripts/prune_checkpoints.py`）：

| run 目录里的文件 | 可回放协议 | 说明 |
| --- | --- | --- |
| `best_checkpoint.pt` | 全部 | 完整 `state_dict`，最稳 |
| `head_only.pt` | `frozen_probe` / `frozen_adapter` / `frozen_adapter_two_stage` / `rotated_frozen` | 只含可训练部分；必须用 `identity.pretrained_checkpoint` 重建冻结主干并校验 sha256 |
| 只有 `latest.pt` | 全部（未导出） | 续训状态，可回放；应先按 prune 政策导出 `head_only`/保留 best |
| 都没有 | **不可回放** | Portal 显示"无推理权重"，不显示生成命令 |

`head_only.pt` 内已写入 `identity.pretrained_checkpoint`、`git_commit`、`head_state_dict`，
导出时带 `note: "Rebuild the frozen backbone from identity.pretrained_checkpoint"`。
`full_finetune` / `prithvi_repo_config` 只有 `head_only` 时**不可回放**（主干也被训练过）。

**当前账本实况**（`/geodata/rs-eval/runs`，只统计 `completed` 且有主指标的 run）：

| 任务 | 可回放情况 | 结论 |
| --- | --- | --- |
| T1 | AnySat 6 best + 3 head_only；Clay 14 best；Prithvi 9 best；**OlmoEarth 0/15** | 部分 |
| T2 | **0/42**（AnySat/Clay/OlmoEarth/Prithvi 全无） | 不可回放 |
| T3 | AnySat 3 best；Clay 6 best；Prithvi 9 best；**OlmoEarth 0/6** | 部分 |
| T4 | AnySat 3 best；Clay 9 best；Prithvi 9 best；**OlmoEarth 0/6** | 部分 |
| T5 | 仅 AnySat 两阶段 3 个 `head_only`（`official_validation`）；**Clay/Prithvi 0/16** | 基本不可回放 |
| T8 | **0/10** | 不可回放 |
| T9 | LIM 2 best + 1 head_only + 1 `latest`；Prithvi 2 `latest` | 部分 |
| T10 | LIM 6 个 `head_only`（`rotated_frozen` 可回放），全部带 `T10_DETECTOR` 审计标记 | 可回放，但只能标"重评" |
| T1S | AnySat 4 best；Clay 4 best | 部分 |

两个直接后果：

1. **"每个任务"要改成"每个可回放的 run"**。T2/T5/T8 和全部 OlmoEarth 正式结果在
   Portal 上只能显示"未保存推理权重，无法生成预测图"，并注明这是历史策略造成的，
   不是模型/任务本身的问题；
2. 评估 split 不是统一的 `test`：T2/T5 的正式评分在 `official_validation`（没有测试标签）。
   生成器必须从任务配置/run.json 读 split，不能默认 `test`。

## 3. 生成流程：离线，不进入训练路径

训练时落盘全部预测会让每次正式 run 多写几十 GB，且大部分没人看。因此：

```
runs/<run_id>/
  run.json                    # 不改
  best_checkpoint.pt / head_only.pt
  visualization/              # 新增，可删
    manifest.json
    samples/<sample_id>.png
```

- 新增 `scripts/visualize_run.py`，用 checkpoint 在**少量样本**上重跑推理；
- 推理必须复用 worker 的正式预测路径（见 §4），不允许在生成器里重写一套预处理；
- 生成过程只读 `run.json`、只写 `visualization/`，不改指标、不进准入规则；
- 生成失败不写半成品：先写临时目录，成功后原子改名。

CLI（修正 §评审 5 的参数歧义）：

```bash
# 在对应 worker 环境里跑；--per-bucket 是每个桶的张数，不是总数
uv run --project workers/lim python scripts/visualize_run.py \
  --run-id lim_mit_huge-T10-rotated_frozen-train-17-v5 \
  --per-bucket 2 --pool 40 --seed 17 \
  --split test          # 省略时用任务配置的正式评测 split
```

| 参数 | 说明 |
| --- | --- |
| `--run-id` / `--runs-root` | 定位 `run.json`、`request.json`、checkpoint |
| `--per-bucket` | 每个桶取几张，默认 2；硬上限为总数 12，超过直接报错要求调低，不静默截断 |
| `--pool` | 候选窗口数，默认 40（见 §6 成本） |
| `--seed` | 选择种子，写入 manifest；同 seed 同 pool 得出同一清单 |
| `--split` | 默认取 run 的正式评测 split（T2/T5 为 `official_validation`） |
| `--list` | 复用固定样本清单（跨 run 对比用），此时忽略 `--pool/--seed` 的抽样部分 |
| `--mode` | `original`（默认，身份不一致直接失败）/ `reevaluate`（显式重评） |
| `--force` | 覆盖已有 `visualization/` |

**worker 适配器**：每个 worker 增加 `replay.py`，暴露

```python
def load_for_eval(run_dir: Path, *, device: str) -> tuple[torch.nn.Module, dict]: ...
def predict_scene(model, scene: dict, *, settings: dict) -> ...  # 与正式 eval 同一函数
```

生成器只负责抽样、画图、写 manifest。这样"图里的推理"就是"分数背后的推理"，
而不是另写一套。

## 4. 样本单位与处理顺序：整景推理 → 整景匹配 → 仅绘图裁剪

评审指出按 manifest 的 `sample_id` 抽样看起来是 tile，但正式指标是整景：

- T9 `score()` 按 `group_id` 分组，整图滑窗、logits 平均、padding 丢弃
  （`workers/lim/src/lim_worker/t9.py:357`，tag `test_protocol`）；
- T10 `score()` 按场景分组，tile 检测平移到原图坐标、过滤 padding、旋转 NMS 后计 AP
  （`workers/lim/src/lim_worker/t10.py:511`）。

**顺序必须固定，不能先裁窗口再匹配**（否则又变回 tile 评测）：

| 步骤 | 做什么 | 是否影响指标/分桶 |
| --- | --- | --- |
| 1 | 整景预测（T9 滑窗 + logits 平均；T10 全 tile + 坐标恢复 + 合并 NMS） | 是 |
| 2 | 整景匹配（T10 类别感知贪心，IoU 0.5）；T9 累计整景混淆矩阵 | 是 |
| 3 | 保存每个 GT / 预测的 `match_id` 与 `status ∈ {tp,fp,fn,ignored}` | 是 |
| 4 | 按窗口裁剪，**仅为绘图**：裁 GT、裁预测、裁误差图 | 否 |
| 5 | 可选 `window_metrics`（窗口内重算，单独字段） | 否，不用于分桶 |

- 窗口边界**不产生 ignore**：只有原始无效像素（T9=255）和图外 padding 按协议忽略；
  T10 的预测先过滤 padding/图外，再整景匹配——不是"裁到窗口后重新匹配"；
- 图上的 TP/FP/FN 颜色直接取第 3 步保存的 `status`，不重新匹配；落在窗口外但匹配到的
  目标在角落计数里注明"窗口外 N 个"，避免看起来比整景分数差；
- 被窗口截断的框画虚线边，并标 `truncated=true`，但不改变它的 TP/FP/FN；
- `sample_id = <group_id>@<x>_<y>_<w>_<h>`，`unit = "scene-window"`；
  按整景分桶（`scene_metrics`），`window_metrics` 只在详情里展示；
- `--unit tile` 仅用于排查，标 `diagnostic: true`，Portal 加"切片诊断，不能解释正式分数"横幅；
- T3/T5 是三时相输入：`display_time_step`（默认最后时相）+ `timestamps` 写入 manifest，
  并渲染一条小时相带，避免"只画了一期"被误读。

## 5. 指标与错误定义

### 5.1 类别语义：背景与 ignore 按任务声明，不按索引猜

评审指出"class>0 即前景"对 T5 是错的：T5 走官方 `reduce_zero_label`
（原始 0 → ignore，1..13 → 0..12），所以模型空间的 **class 0 是合法作物类**；
T8 则相反，原始 0 才是 ignore（1..24 保留）。`TaskSpec` 的注释也明确禁止按索引猜。

生成器必须从 `configs/tasks/<task>.yaml` 的 `background_class` / `ignore_index`，
加上回放适配器实际使用的 label mapping 构造类别集合，并写进 manifest：

| 任务 | 输出类 | `background_class` | `ignore_index` | 标签映射 | 二值前景 IoU |
| --- | ---: | ---: | ---: | --- | --- |
| T1 / T1S | 2 | 0 | -1 | 0=陆地/未淹 | 适用（1=水） |
| T2 | 2 | 0 | -1 | 0=未烧 | 适用 |
| T3 | 5 | 0 | -1 | 0=无火烧 | 适用 |
| T4 | 2 | 0 | null | 0=非滑坡 | 适用 |
| T5 | 13 | **null** | -1 | `reduce_zero_label`：原 0→ignore，1..13→0..12 | **不适用**（0 是作物） |
| T8 | 25 | **null** | -1 | 原 0→ignore，1..24 保留 | 不适用（无背景类） |
| T9 | 16 | 0 | 255 | 调色板→类别，pad=255 | 适用 |
| T10 | 37 | null | null | 无背景，37 个目标类 | 检测，无二值 |

规则：

- `foreground_binary_iou` 只在 `background_class != null` 或显式 `--classes` 时计算；
  否则写 `null` 并注明"该任务无背景类"；
- `ignore_values` 取任务声明 + 适配器映射（T9 是 255；T5/T8 是 -1）；**255 不是通用 ignore**；
- `empty_*` 桶只用于"有背景语义"的分割任务（T1/T2/T3/T4/T9）和检测（T10）；
  T5/T8 没有背景类，不产生 `empty_*`；
- 类别名与调色板取自任务/数据集定义，manifest 记录 `class_names` 来源。

### 5.2 分割指标

一张图里同时给出四个数，避免"前景 IoU=1 但类别全错"被涂成绿色：

| 字段 | 定义 |
| --- | --- |
| `foreground_binary_iou` | 前景二值 IoU（按 §5.1 判定是否适用）；ignore 不参与 |
| `per_class_iou` | `{class: IoU \| null}`；GT 不存在的类记 `null`，**不写 0** |
| `macro_iou` | 仅对 GT 存在的类取平均；GT 全空的窗口为 `null` |
| `pixels` | 像素级 `{tp, fp, fn}`（与检测的 `objects` 分开命名） |

误差图颜色：

- 绿 = TP、红 = FP、蓝 = FN、灰 = ignore（选中类别或前景集合）；
- **橙 = 类别互换**（GT 是 A、预测是 B，且两者都在前景集合内）；同时写 `switch_pairs`
  （如 `{"corn->soybeans": 1820 px}`），避免类别互换被二值 IoU 掩盖；
- 全 ignore 窗口：`status = "ignored"`，不给 IoU，也不进任何桶。

**分桶用哪个 IoU**：`bucket_metric` 显式写入 manifest —— 有二值前景的任务用
`foreground_binary_iou`，没有的（T5/T8）用 `macro_iou`；阈值不变
（hit ≥ 0.7，0.3 ≤ partial < 0.7，miss < 0.3）。

### 5.3 检测（T10）

匹配与 NMS 分阶段记录，**不压成一个 `nms_iou`**。当前正式值（`detector.py` / `t10.py`）：

```json
"detection": {
  "match": "class-aware greedy, descending score",
  "match_iou": 0.5,
  "score_threshold": 0.05,
  "rpn_nms_iou": 0.7,
  "class_nms_iou": 0.5,
  "merge_nms_iou": 0.5,
  "rpn_post_nms": 1000,
  "detections_per_image": 100,
  "ignore_rule": "padding and out-of-image removed before scene matching"
}
```

- 0.1 是 DOTA **G1 参考合并**的值，不是 T10 正式设置；写错会改变保留框与分桶；
- 这些参数目前在代码里是常量，protocol/request schema **没有**对应字段，不能宣称
  "读配置即可获得"；由回放适配器返回实际值，缺任何一项 → 不允许标 `original_protocol`；
- `objects: {tp, fp, fn}` 按**整景**统计；图上只裁窗口内的框并沿用第 3 步的匹配状态；
- 同一 GT 的重复检测只算一次 TP，其余 FP（与 `ap.py` 一致）。

### 5.4 空场景

| 桶 | 条件 | 适用 |
| --- | --- | --- |
| `hit` | 有 TP，且 FP=FN=0 | 全部 |
| `partial` | 有 TP，且 FP>0 或 FN>0 | 全部 |
| `miss` | 有 GT 目标，TP=0 | 全部 |
| `empty_correct` | GT 无目标且预测无目标 | 有背景语义的分割 + 检测 |
| `empty_false_alarm` | GT 无目标且预测有目标 | 同上 |

`empty_*` 只在确实存在时抽样；没有该状态时 manifest 记 `available: false`，不补零。

## 6. 抽样规则（确定性）

1. 取该 run 正式评测 split 的所有窗口，按
   `digest = sha256(f"{seed}:{group_id}:{x}:{y}:{w}:{h}".encode("utf-8"))` 排序；
2. 取前 `--pool`（默认 40）个窗口，按 `group_id` 去重得到候选景，逐景跑一次整景推理；
3. 每个候选窗口按 §5 计算桶；
4. 桶内按同一 `digest` 升序取 `--per-bucket` 张，**不按指标排序**；
5. manifest 记录 `algorithm = "sha256(seed:group_id:window) asc"`、
   `candidates_sha256 = sha256(排序后的 sample_id 列表)`、`pool_windows`、`pool_scenes`、
   实际推理窗口数、耗时。

**不用 Python 内置 `hash()`**：它按进程随机化，同 seed 会选出不同清单。用 SHA-256 的
十六进制字符串排序，跨进程、跨机器稳定。

**选择偏差**：先按结果分桶、再在桶内随机，仍然不是无偏样本。Portal 图注固定写
"按固定规则抽取的案例，不代表测试集分布，不能作为精度证据"。跨 run 对比时**先固定
共享清单**（`--list`），各模型的结果都渲染同一批窗口，而不是各自挑各自的好/坏案例。

## 7. 回放身份与"重评"语义

只记 checkpoint 哈希不够。manifest 必须固定住"这张图是用什么数据、什么配置、什么代码、
什么推理参数算出来的"，并且**这些字段要真正参与判定**：

```json
"identity": {
  "run": {"run_id": "lim_mit_huge-T9-upernet_frozen-train-42", "git_commit": "ef24581",
          "dirty": false},
  "data": {
    "manifest_path": "/geodata/rs-eval/data/manifests/T9/holdout_seed17.jsonl",
    "manifest_sha256": "…", "split": "test", "scenes": 458, "windows": 10132
  },
  "config": {
    "task":     {"path": "configs/tasks/T9_isaid.yaml",             "sha256": "…"},
    "model":    {"path": "configs/models/lim.yaml",                 "sha256": "…"},
    "protocol": {"path": "configs/protocols/upernet_frozen.yaml",   "sha256": "…"},
    "request_json_sha256": "…"
  },
  "backbone": {"path": "…/weights/lim/…", "sha256": "…"},
  "head": {"path": "head_only.pt", "sha256": "…", "format": "head-only-v1"},
  "input": {"sensor": "aerial-rgb", "bands": ["R","G","B"],
            "preprocessing_id": "…", "time_steps": 1},
  "inference": {
    "generator_version": "visualize-run/1",
    "files": {
      "scripts/visualize_run.py": "…",
      "src/rs_backbone_eval/checkpoint.py": "…",
      "src/rs_backbone_eval/evaluation/segmentation.py": "…",
      "workers/lim/src/lim_worker/t9.py": "…"
    },
    "files_sha256": "…",
    "params": {
      "crop": 1024, "stride": 824, "merge": "logits-average",
      "ignore_values": [255], "background_class": 0,
      "display_time_step_policy": "last"
    }
  },
  "replay": {
    "mode": "reevaluated",
    "run_git_commit": "ef24581",
    "generator_git_commit": "7371f63",
    "fingerprint": "sha256(files + params + env)",
    "fingerprint_at_run": "…",
    "fingerprint_now": "…",
    "worktree_clean": true,
    "stale_flags": ["T9_PADDING"],
    "reason": "run predates the padding fix; this is a re-evaluation, not the original score"
  }
}
```

**`original_protocol` 的判定（收紧）**：

1. 计算 `fingerprint = sha256(sorted(files: blob_sha) + params + env)`：
   - `files` 是适配器声明的推理依赖（生成器、worker 的 t9/t10、检测/分割工具、
     预处理与数据集读取、配置三件套），必须**包含 YAML 与 Python**；
   - `blob_sha` 在 run commit 用 `git rev-parse <commit>:<path>` 取，与当前工作树文件
     内容哈希比较；
   - `params` 是适配器实际使用的滑窗/阈值/合并/ignore 等完整字典，**缺键即失败**；
   - `env` 记录影响数值的版本（torch、CUDA、timm 等）与相关环境变量；
2. `fingerprint_at_run == fingerprint_now`，且工作树干净、`stale_flags` 为空，
   才允许 `original_protocol`；
3. **仅"HEAD 是原 commit 的后代"不算证据**：后代可能改了推理代码而没改 YAML；
4. 任一指纹无法计算（文件在该 commit 不存在、适配器缺参数、dirty 工作树、环境缺失）
   → 一律 `reevaluated`，除非显式 `--mode original` 且能补齐全部身份；
5. 校验 `run.json` 的 `dataset.manifest_sha256`、`model_checkpoint_sha256`、`protocol_id`、
   `seed`、`input` 与生成器实际使用的值一致；不一致直接失败（`--mode reevaluate` 才降级）。

`reevaluated` 的图在 Portal **每张图都带**"重评：当前代码/配置，非原 run 分数"徽标，
manifest 保留原 `stale_flags`（如 `T10_DETECTOR`、`T9_PADDING`）。

这条规则直接回应当前状况：T10 的 6 个 run 全部带 `T10_DETECTOR`，即使回放成功也只能
标成重评，不能拿来解释 v6 的历史 mAP。

## 8. manifest 契约（完整样例）

以 T9（LIM，整景滑窗）为例；字段与 §5/§7 一致。该样例会作为
`tests/test_visualization_manifest.py` 的校验输入，避免文档与 schema 漂移：

```json
{
  "schema_version": "1.0",
  "run_id": "lim_mit_huge-T9-upernet_frozen-train-42",
  "task_id": "T9",
  "model_id": "lim_mit_huge",
  "protocol_id": "upernet_frozen",
  "run_seed": 42,
```

## 9. Portal 接入

**后端**（只读）：

| 路由 | 行为 |
| --- | --- |
| `GET /api/runs/{run_id}/visualization` | 有 `visualization/manifest.json` 返回；没有返回 `204` |
| `GET /api/artifacts/{run_id}/visualization/...` | 复用现有 artifacts，只允许 `visualization/` 前缀 |

`run_detail` 增加三个只读字段：`visualization.available`、`visualization.replayable`
（依据 §2 的 checkpoint 规则与协议）、`visualization.reason`（缺权重/缺清单）。

**前端**（run 页新增一节，位于"产物"之前）：

```

状态徽标：重评（T10_DETECTOR）· 切片诊断

│                          │ 类别、窗口、时相   │
└──────────────────────────┴──────────────────┘
图例：TP / FP / FN / ignore / 类别互换
```

- 无 manifest 时：可回放 → 显示生成命令；不可回放 → 显示原因，**不给命令**；
- 卡片把 `scene_metrics`（分桶所用）与 `window_metrics`（仅窗口内参考）分栏显示，
  后者不参与分桶，避免"图上区域"和"旁边数值"对不上；
- `empty_*` 过滤按钮由 manifest 的 `available` 决定，T5/T8 不显示空场景桶；
- 图注固定写明抽样规则与"不代表整体精度"；
- 复用现有 drawer 放大，不新增前端构建步骤。

## 10. 成本与 GPU 队列

成本按**候选池**算，不按最终 9 张算：

| 任务 | 候选池 | 整景推理量 | 估计 |
| --- | --- | --- | --- |
| T9 | 40 窗口 / ~12 景 | ≈ 12 景 × 中位 9 窗 ≈ 110 次滑窗（最大单景 208） | 2–5 分钟 |
| T10 | 40 窗口 / ~30 景 | ≈ 40 tile + NMS（中位 1 tile/景） | 2–4 分钟 |
| T3/T4/T5 | 同上 | 单景整图，3 时相 | 3–8 分钟 |

存储：每张 0.2–0.5 MB，单 run 约 2–5 MB；`visualization/` 可随时删除，
`scripts/prune_checkpoints.py` 不处理它（设计上不把它当审计产物）。

**队列约束**：生成要用 GPU，不能在正式训练旁启动。生成器启动前检查
`nvidia-smi` 是否有其他任务、或直接复用 `scripts/rerun_baselines.sh` 的空闲等待锁；
生成日志写到 `visualization/generate.log`，不写 `run.json`；同时只允许一个生成进程。

## 11. 分阶段实现

按"先能看见 T10/T9，再扩到其他 worker"排，而不是一次铺满所有任务：

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P0 | LIM worker：T10 检测两联图 + 5 桶 + manifest + Portal 图集 | 同一 seed 重跑清单一致；`head_only` 回放能重建主干并通过哈希校验；三阶段 NMS 取值与 `detector.py`/`t10.py` 一致；重评徽标正确；manifest 样例通过 schema 测试 |
| P1 | LIM worker：T9 分割四联图（复用整景滑窗/合并） | 先匹配后裁剪，裁剪不改变整景指标；`background_class` 与 ignore 取自配置；类别互换颜色正确；全 ignore 窗口不进桶 |
| P2 | 其他 worker（AnySat/Clay/Prithvi）的分割适配器 | 每个 worker 只实现 `load_for_eval`/`predict_scene`；T5 的 class 0 按作物处理（不设背景）；T8 的 0 按 ignore；预处理与正式 eval 一致 |
| P3 | 跨 run 共享清单对比 + FP/FN 统计 | 同一 `--list` 下所有模型渲染同一批窗口 |

T2/T5/T8/OlmoEarth 在补权重或重跑之前不进入 P2 验收。

## 12. 风险与边界

1. **不可回放是硬边界**：T2/T5/T8 与 OlmoEarth 目前只能显示"无权重"。不要用
   `confusion_per_scene.json` 反推预测图，也不要拿新模型冒充旧 run。
2. **重评 ≠ 原结果**：T9/T10 的旧 run 都带审计标记，图必须带徽标；不能在报告里引用
   "重评后的可视化"解释原分数。
3. **选择偏差**：桶内哈希只保证可复现，不保证无偏；图注必须声明。
4. **输入渲染**：按任务声明的波段合成（HLS/S2 用 B4/B3/B2，SAR 用 VV/VH 灰度+青色），
   禁止静默取前三个波段；manifest 记录实际波段。
5. **类别语义不能猜**：T5 的 class 0 是作物、T8 的 class 0 是 ignore、T9 的 ignore 是 255；
   一律读任务配置与适配器映射，写进 manifest。
6. **不能污染指标**：per-sample 数字只分桶；生成失败不影响 run 状态与报告。
7. **磁盘**：按需生成、可删除；不随 run 永久保留。
