## 2. 统一头与输入路径

### 2.1 统一头：自研 torch-only UPerNet

- terratorch 的 `ConvModule` 把 `nn.BatchNorm2d` 写死（`terratorch/models/decoders/utils.py:43`），无法换 GN；
- terratorch 只装在 `workers/prithvi`，其余 worker 没有；`heads.py` 不应反向依赖 worker 框架。

做法：`src/rs_backbone_eval/heads.py` 新增只依赖 torch 的 UPerNet（PPM + FPN + 分类头），`norm_layer` 可配、默认 GroupNorm；`head_id=upernet_gn`。

### 2.2 归一化、有效 batch 与校验

| 项 | 决定 |
|---|---|
| 头归一化 | **GroupNorm**（已定） |
| 有效 batch | **8**（micro 1 × accum 8），iSAID 单独口径，所有主干一致 |
| 校验 | **worker 侧硬校验**：T9 的 `micro_batch × grad_accum` 不等于 8 就报错退出 |
| 记录 | tags 写死 `micro_batch` / `grad_accum` / `effective_batch` / `norm_layer` |

**关于 `variant_key`**：它已含 `head_id`（`matrix.py:59`），所以不同头不会合并；但**不含 batch**。因此：

- 用 worker 校验把它钉死为 8；
- 若将来确实要试别的 batch，必须用 `head_id` 后缀区分（如 `upernet_gn_b4`），否则会被当成同一 variant 一起平均。

更正 v2 的误述：同事是 **SyncBN + batch 12 分布在 6 卡**，统计来自 12 个样本，不是"单卡等效 batch 2"。

### 2.3 现有轨道并非都用一个头

`lite_spatial_head`（T1/T1S/T4/T8）、`temporal_segmentation_head`（T3/T5）、`+spectral_adapter` / `+band_adapter`、`upernet_decoder`（B0）。因此统一头是新增轨道，不是替换既定头。

### 2.4 各主干的输入路径（含 GSD 错配）

| 主干 | 通道处理 | **隐含 GSD** | 元数据 | 四级金字塔 | 记录 |
|---|---|---|---|---|---|
| **LIM** | 原生 3 通道 | **原生（0.3–1 m）** | 无 | 原生 4 级 | `head_id=upernet_gn` |
| **Prithvi** | 3 → 6：1×1 卷积合成 NIR/SWIR1/SWIR2（禁止补零，沿用 T8） | **30 m（HLS 预训练）** | 不传 | token `[5,11,17,23]` | `head_id=upernet_gn+band_adapter` |
| **Clay** | 3 通道，波长 0.48/0.56/0.655 µm | **声明 1.0 m**（唯一可显式告知的主干） | **`gsd=1.0` 固定声明值**，`gsd_source=declared` | 8×8 token 抽 4 层 | tags: `gsd_source=declared`、`wavelengths_um` |
| **OlmoEarth** | 放入 12 波段 B02/B03/B04；**10 m 组补 B08**（用**标准化均值**填充），**20 m 组（B05/B06/B07/B8A/B11/B12）与 60 m 组（B01/B09）整组标 MISSING**。规则实现见 `workers/olmoearth/src/olmoearth_worker/tasks.py`（band-set 判定约 218–251 行；tag 约 384–386 行），现有 tag 为 `band_adapter=constant_fill_12band` | **10 m（S2 入口）** | 无 | 稠密 token，池化 T/BS | tags: `band_adapter=constant_fill_12band`、`missing_bandsets` |
| **AnySat** | `s2` 10 波段入口 + 光谱适配器 | **10 m（入口假设）** | 无 | token 展平顺序需逆向（风险最高） | tags: `gsd_assumed=10` |

**推论（修正 v4）**：**除 LIM 外，四个主干都存在尺度错配**——Prithvi 按 30 m 训练、Olmo 与 AnySat 的 S2 入口按 10 m、Clay 只能被告知一个声明值；**只有 Clay 有一个能显式传 GSD 的入口**。

**还有一个同等重要、但 v4 之前写错的因素：主干输出步长**。裁块大小（512 或 1024）**不改变分辨率**，在同一 GSD 下车辆始终是 10–30 px；真正决定小目标细节的是主干把像素压缩多少倍：

| 主干 | patch / 步长 | 一辆 20 px 的车在特征图上 |
|---|---|---|
| LIM（MiT-Huge） | 第一级 H/4 | **3–7 个格**，细节保留最好 |
| Clay | patch 8 | 2–3 个格 |
| AnySat / Olmo | patch 16（S2 入口） | **1–2 个 token** |
| Prithvi | patch 16 | **1–2 个 token**，而 UPerNet 的金字塔是从同一个 /16 特征上采出来的，小目标细节本来就不存在 |

因此 iSAID 的客场劣势有两个来源：**GSD 错配**（尺度假定）与**输出步长**（空间分辨率）。两者都要写进报告，且都不能读作架构优劣。

**若将来要逐图 GSD**：需下载 DOTA `labelTxt-v1.0/labelTxt.zip`（标注文件首行含 `imagesource` / `gsd`，部分为 `None`），列为 P0-a 可选任务并补进 `catalog.yaml`。本版**不依赖**它。

## 4. 协议设计

### 4.0 轨道：B2U（冻结主干 + UPerNet）

**可训练部分不对等，必须显式声明**：

| 主干 | 练什么 | 说明 |
|---|---|---|
| LIM / Clay | 仅 UPerNet 头 | 入口不需要适配 |
| Prithvi | 头 + **3→6 通道适配器** | 结构必需，否则进不去（沿用 T8 的 1×1 卷积做法） |
| AnySat | 头 + **光谱适配器**（3→10 波段） | 同上（沿用 T8/frozen_adapter 的做法） |
| OlmoEarth | 头（填充不需要参数） | 无适配器参数 |

协议取 **`train_input_adapter: true`**，含义是"**入口结构必需时允许适配器**"，而不是"每个模型都加适配器"。报告必须逐主干列出 `可训练参数 = 头 + 适配器`，并注明适配器是结构必需而非调参选择。

与现有 B2 的对应关系：现有 B2 分 `frozen_probe`（无适配器）与 `frozen_adapter`（有适配器）两个协议；**B2U 是一条轨道里的两种形态**，靠 `head_id` 里的 `+band_adapter` / 隐含光谱适配器与 `run.json` 的 `adapter_parameters` 区分，报告按"有无适配器"分两组展示。

### 4.1 划分：从 train 按原图切 validation

```bash
uv run rs-eval holdout-manifest \
  --manifest <isaid train manifest> --out <isaid manifest> \
  --split validation --source train --fraction 0.12 --seed 17
```

**前置条件**：manifest builder 必须把原图编号（`P0000`）写进 `group_id`，否则切的是"块"不是"图"。

**比例按块复核**：图像尺寸差异极大（387–12029 px 宽），按 12% 抽**图**不保证得到 12% 的**块**。因此 P2 必须同时报告"验证图占比"与"验证块占比"，**以块占比为准**；若偏离 10–15% 的预期区间，调整 `--fraction` 后重切。

### 4.2 组泄漏：**未排除**

DOTA 无地理坐标、文件名无地理语义，同一机场/港口可能同时出现在官方 train 与 val；**无法证明有、也无法证明没有**。报告用词为"未排除"，结论限定同分布。

### 4.3 TTA

主表：单尺度、滑窗 stride 1/3、**无 TTA**；附表：+d4 TTA 仅说明增益。

### 4.4 同事配方（修正版）

`use_amp: False`、`scale 0.5–2.0`、`aux_weight 0.2`、1024 裁块、batch 12（6 卡）、200 epoch、滑窗 1/3 + d4。

### 4.5 数据溯源

**校验和已补齐**：`scripts/isaid_p0a.py` 对 2 个标注 json、2 个掩码 zip、4 个 DOTA 图像 zip 共 **8 个文件**计算 sha256，写入 `data_root/derived/isaid/p0a_report.json` 的 `sha256` 段。

**下载已脚本化**：`bash scripts/fetch_isaid.sh [DATA_ROOT]`（默认取 `RuntimePaths`），
idempotent，逐文件校验上表的 sha256，不匹配即失败。

**未进 `catalog.yaml`**：iSAID 与 DOTA 的 8 个文件全部托管在 Google Drive，>100 MB 的文件
会返回 HTML 确认页，`http_files`（aria2c/python-http）拿不到真档案；`downloads.py` 目前只有
`http_files` / `hf_snapshot` / `gcs_rsync` 三种方法。硬塞一条会点开就坏的记录比不记更糟，
因此本版用脚本记录来源，`catalog.yaml` 的新方法（`gdown`）留作独立改动。

### 4.6 整图评测（P2 已实现）

- `data/tiling.py`：唯一切块实现（`tile_origins` / `tiles_covering` / `tile_bounds` / `pad_tile`）；
- `evaluation/windows.py`：`predict_bands` 逐行带流式推理——同一条带内按列累加 logits，
  切到下一条带时把不再被任何块覆盖的行**先平均再 argmax** 后输出，再上移缓冲；峰值内存
  是 `C × crop × width`，与图高无关；
- 评测端**不按 `valid_fraction` 过滤**（那会改变分母），只在训练抽样时可用；
- 单测覆盖：小图 387×278 统计像素数恰为 107,466；重叠块平均后 argmax；pad 区 logits 不得
  翻转真实像素；流式结果与全画布暴力参考逐像素一致；GT 里 `ignore_index` 的像素不计入。

## 5. 算力与 GPU 优先级

### 5.1 预算（按迭代数）

| 项 | 数值 |
|---|---|
| 步数 × 有效 batch | 25k **optimizer steps** × 8 = **20 万 tile**（`LIM_WORKER_TOTAL_STEPS=25000` 数的是 optimizer step，micro 1 + accum 8 → 8 个 tile 一步；早期实现误把 tile 当 step，1.6 h 就会停，已修并把那次 run 隔离为 `.budget-unit-tiles-not-steps`）。当前 manifest 每 epoch 23,808 块 → 约 8.4 个 epoch |
| 1024/512 切块数 | 训练 **29,457**、验证 **10,132**（§11 可复现结果，含边缘补块） |
| 覆盖遍数 | 按**像素口径**：训练集共约 94.2 亿像素，20 万 × 1024² ≈ 209.7 G 像素 → **约 22 遍**。按块数算会偏低（11,828 个不重叠块里含 pad 像素），报告统一用像素口径 |
| 吞吐假设 1 张/秒 | **≈2.3 天/种子** ← **这是 B1U（全量微调）的上限估计，不是 B2U 的成本** |
| B2U | 不反传主干，实际更快；**具体数字等 P0-b** |

### 5.2 第一轮范围

**B2U + LIM + 1 个种子**：先拿真实吞吐与第一个数字，再补 3 种子、再接其他主干。

### 5.3 P0-b 吞吐 smoke（两套配置都要测）

| 配置 | 目的 |
|---|---|
| B1U（全量微调）512²/1024² | 上限参考，判断后续是否值得做全量微调 |
| **B2U（冻结）512²/1024²** | **第一轮真实成本**（LIM） |
| 验证（滑窗 1/3）512²/1024² | 评测成本 |

**每个主干接入前都要单独跑一次冻结 smoke**（写入 P4 的 gate）：1024² 下 Clay 的 patch 8 是 **128² = 16,384 token**，冻结前向的显存也可能吃紧；Prithvi 还要额外验证 `absolute_pos_embed` 从 56² 插值到 256² 后能否正常前向与收敛。

**实测（2026-10-29，4090 24GB，LIM，20 个 tile 的短跑，`scripts/isaid_p0b_smoke.sh`）**：

| 配置 | crop | 训练吞吐 | 像素吞吐 | 峰值显存 | 评测吞吐 |
|---|---|---|---|---|---|
| B2U 冻结 | 1024 | **4.00 tile/s** | 4.19 Mpx/s | 4,446 MB | 3.67 tile/s |
| B2U 冻结 | 512 | 7.17 tile/s | 1.88 Mpx/s | 2,480 MB | — |
| B1U 全量 | 512 | 5.81 tile/s | 1.52 Mpx/s | 12,266 MB | — |
| B1U 全量 | 1024 | **1.23 tile/s**（开梯度检查点） | 1.29 Mpx/s | 12,820 MB | — |
| B1U 全量 | 1024 | **OOM**（22.93 GB 已分配） | — | — | — |

结论与预算换算：

- **1024 是更划算的档位**：冻结时按像素算比 512 快 2.2 倍（4.19 vs 1.88 Mpx/s），512 的小 tile 喂不满 4090；
- **B2U 第一轮成本**：20 万样本 ÷ 4.00 ≈ 13.9 h/种子；加 10,132 个测试 tile 的整图评测（3.67 tile/s ≈ 46 min）≈ **15 h/种子**；
- **B1U 上限**：20 万 ÷ 1.23 ≈ 45 h/种子（约 1.9 天），与 §5.1 的 2.3 天上限估计一致 —— 值得做，但不能先做；
- **1024 全量微调必须开 `LIM_WORKER_CHECKPOINT=1`**：不开就是 OOM；开梯度检查点后峰值 12.8 GB，速度代价约 1.2 倍（对比 512 的 1.52 Mpx/s）；
- 这些是 **smoke**：每格只跑 20 个 tile、1 个 epoch，`run.json` 带 `[SMOKE]`，不能当结果；
- 调试期失败记录全部移入 `runs_quarantine/` 并注明原因：`.bad-eval-broadcast`（评测张量多一维，4 条）、`.oom-no-ckpt`（1024 全量不开检查点）、`.rgba-crash` / `.grayscale-crash` / `.norm-stats-4band`（DOTA 的 1/4 通道图，已修）、`.budget-marker-bug`（worker 自带 `OFFICIAL_EPOCHS=50` 把跑满 25k 步的 run 标成 REDUCED-BUDGET，已集中到 `matrix.stopped_short_of_budget`）。

### 5.3.1 Clay 在 1024 上的资源阻断（2026-10-29 实测）

| 输入 | encoder 前向 | UPerNet 头（前向+反向） | 折算 20 万 tile |
| --- | ---: | ---: | ---: |
| 512 | 0.38 s | 0.02 s | ≈23 h/种子（3080） |
| 1024 | **5.19 s** | 0.06 s | **≈290 h/种子**（3080），4090 估计 ≈110 h |

Clay 是全注意力：1024 有 16,384 个 token，注意力二次增长（4 倍像素 → 13.6 倍耗时），瓶颈全在
encoder。显存不是问题（1024 冻结 6.4 GB / 20 GB），**算力是**。因此 Clay 的 T9/B2U **记为资源
阻断，不安排运行**，也不为它单独把全谱系降到 512（那会让其它模型的 1024 结果失去可比性）。
若将来要纳入 Clay，只能以**预先声明的 512 独立 cell** 形式出现，`train_crop_px` 已把它与 1024
分在不同的 cell 里。

测量方法：`torch.cuda.synchronize()` 之后计时；早期探针报的 0.16 s 只是 kernel 入队时间
（`d55f373` 修）。同一实测也解释了 Galileo 的高分辨率风险：它的 S2 入口同样在 1024 上产生
16,384 个 token。

### 5.3.2 Prithvi 的 T9 接入（2026-10-29）

Prithvi v2 在 1024 上是 64×64 的 /16 网格（4,096 token），terratorch 会插值位置编码；实测
256/1024 前向均为有限值，冻结主干时只有 adapter + UPerNet 头可训练（225,686 参数）。这是
iSAID 上最"客场"的配置：30 m HLS 预训练 + /16 步长，用于谱系的粗粒度端。缺失的 NIR/SWIR 由
可训练 1×1 adapter 合成并在 tags 里标为 `missing_bands ... synthesized, not observed`。

### 5.4 GPU 优先级

4090 在跑 T4 DEM 诊断（预计 15:10 结束）；3080 预留给业务侧新项目。因此：

1. P0-b **不能与 T4 DEM 并行**；
2. **已决定（业务侧 2026-10-29）：iSAID 优先，T1S/T8 收尾后置。** 评审先前建议先收尾 T1S/T8，现按业务侧决定执行；
3. P0-a（数据体检）不占 GPU，已完成（§11），可继续做 manifest builder。
