用途：供方案作者修订设计、实现与实验验收；本文件不替代训练代码。

## 一、总体判断

**可以沿 v2 的研究路线继续推进，但应先修复实现并通过验收，再启动正式实验。**

v2 已把“推理时使用真实 AEF 的融合”和“训练时利用教师、部署时只输入影像”分开，也补上了容量匹配对照。主线比 v1 清楚，下一步的重点应是把这些约束落实到数据管线、计算图和测试中。

目前第 5 节仍应定位为**模型与损失原型**。其解码、缓存增广、教师训练和测试覆盖存在具体问题；尚未包含完整的数据加载、优化器、调度器、检查点及评估流程，不宜称为可以直接执行正式实验的完整框架。

### 评审边界

- 本次依据 v2 正文及内嵌代码进行静态检查，并结合前轮材料判断实验含义。
- 已检查两段 Python 代码的语法，并对解码与标准化问题做小型数值核验。
- **未执行 PyTorch 前向、反向或训练验证**；本文的验收项是后续要求，不代表已通过。
- 未取得同事原始 `AEF_Fusion_Kit_20261113` 代码包及其完整规格、配置，不能独立确认“1:1 复刻”“100% 兼容”。旧实验计算图的判断依赖 v2 的描述。

## 二、应保留的设计

| 设计 | 判断与保留条件 |
|---|---|
| 将旧 `feat-mlp-distill=0.51120` 归为真实 AEF 融合结果 | 若 v2 所述推理图属实，该结果不能证明纯影像部署有效。 |
| D 与 B0 比较 | 适合检验在相同学生结构下，教师监督是否改善分割。 |
| P 与 Bcap 比较 | 两者应具有相同 Predictor、Injector 与分割头，仅改变教师对齐损失。 |
| D 先做输出蒸馏，特征蒸馏权重设为 0 | 降低初期变量数量，先检验最直接的知识迁移。 |
| A 必须具有共享可训练路径 | 辅助损失应更新部署时保留、且分割也使用的参数。 |
| 区分任务模型提升与通用主干提升 | 分割头或外挂模块变好，不等于冻结主干的通用表示已经变好。 |

关于旧辅助损失，建议使用准确表述：

> 若辅助头只读取冻结缓存特征，且其参数不参与分割前向，则辅助损失对分割路径没有直接梯度作用。

不建议写成“对最终结果绝无影响”：随机数消耗、全局梯度裁剪、按总损失调度等实现细节仍可能间接影响训练。

## 三、正式开跑前必须修复的问题

### 1. OlmoEarth 解码与函数承诺不一致

**位置：** `decode_and_mask_teacher_embedding()`。

当前代码将 int8 除以 127，属于线性缩放；注释却称其为官方非线性反量化。

对于官方文档所述的原始 OlmoEarth int8 编码，有效值应按下式解码，`-128` 单独作为 NoData：

```text
decoded = sign(q) × (abs(q) / 127.5)²
```

例如，q=64 时，当前代码给出约 0.503937，正确解码约为 0.251965。这不是统一缩放，可能改变特征方向；后续做 L2 归一化也不能自动纠正。

**修订要求：**

- 显式区分 AEF、OlmoEarth 原始 int8、已解码浮点数据，禁止重复解码。
- NoData 以数据产品元信息和格式约定为准，不能用同一个默认数值规则处理所有教师。
- 先检查有限值，再用 `where` 或等效操作清理无效值；不能依靠 `NaN × 0` 清除 NaN。
- 单个通道为 0 不代表无效；“全零向量无效”也应是明确的数据约定。
- 函数注释声称返回 L2 归一化特征，但实际未归一化。应明确“解码—空间聚合—按损失需求归一化”的顺序，保持代码与契约一致。

**验收：** 覆盖正值、负值、0、-128、NaN、Inf，以及已解码输入；与官方公式一致，输出无意外非有限值。

来源：[OlmoEarth 官方 Embedding 导出文档](https://docs.olmoearth.allenai.org/exporting-embeddings/)。

### 2. 缓存特征、几何增广与微调模式冲突

**位置：** `sync_augment_tile()` 和模型 `forward()` 的 `cached_feats` 分支。

当前增广只变换影像、标签和 AEF，没有处理缓存特征及有效掩膜。若标签翻转、旋转后，仍使用原方向缓存，监督就会错位。

此外，一般不能假设：

```text
旋转 backbone(X) = backbone(旋转 X)
```

尤其对带位置编码的模型，仅旋转特征图不等于重新编码增强后的影像。

**修订要求：**

第一轮选择一种清楚的策略，并对所有匹配实验臂一致执行：

1. 使用静态缓存时，先关闭几何增广；
2. 分别缓存各个增广版本对应的真实编码结果；
3. 对增强后的影像在线编码。

如果要微调 backbone，必须在线执行主干。当前代码优先采用 `cached_feats`，即使主干参数设置了 `requires_grad=True`，也可能完全绕过主干；应对此设置直接报错的断言。

另外，缓存必须来自**未融合教师信息的纯影像主干**，记录生成模型、权重、预处理和输入来源。不能使用 `bb_inj` 或其他教师融合之后的缓存来证明纯影像部署。

**验收：** 增广后影像、标签、教师及掩膜空间一致；微调模式禁止静态缓存；至少完成一次从原始影像到预测的端到端推理。

### 3. 冒烟测试尚不能支持“全部通过”的结论

**位置：** `run_smoke_test_all_six_arms()`。

当前有四个明显缺口：

- 对 R 只调用 `backward()`，没有 `optimizer.step()`。注入器末层仍为全零，随后作为教师时，AEF 注入分支尚未学到任何贡献。
- 实际循环只覆盖 B0、Bcap、P、D，另有 R；没有覆盖 A 和 R_null。
- 没有实际测试“向纯影像模型传入 AEF 必须报错”。
- P 的梯度来自 CE 与对齐损失之和，不能据此证明 CE 本身能够更新 Predictor。

**零初始化的测试应分步做。** 在 Injector 末层权重全零时，第一次 CE 反传通常能更新末层，却暂时不能经该末层把梯度传给 Predictor。这是初始化机制的预期行为。应先完成优化器更新，再重新前向、仅用 CE 反传，检查 Predictor 的梯度。

**修订要求与验收：**

- 实际执行优化器更新，比较预期可训练参数更新前后的差异。
- 分开检查 CE 与对齐损失各自通向哪些模块。
- 覆盖 A 的共享 Adapter 或主干，以及 R_null 的构造与前向。
- 正式 D 实验加载已训练的 R 检查点，并设置教师 `eval()`、冻结参数、无梯度推理。
- 实际触发非法 AEF 输入异常。
- 增加全无效教师、全忽略标签及少量有效像素的边界检查，避免 NaN。
- 至少覆盖一个真实数据小批次，不能只使用随机特征。

完成前，将“全部六臂冒烟自检 100% 通过”改为实际已覆盖的项目描述。

### 4. Z-score 的默认行为使评测依赖 batch 组成

**位置：** `ChannelZScoreNorm2d.forward()`。

未调用 `set_stats()` 时，训练和评测都会使用当前 batch 的均值、标准差。同一张 tile 与不同影像拼成 batch，会得到不同的标准化特征。

简单数值示例：特征 [0, 2] 单独计算样本标准差时，标准化约为 [-0.707, 0.707]；与 [100, 102] 一起计算时，前者变为约 [-0.883, -0.849]。这说明变换本身依赖同批样本，不是实际模型精度测试。

**修订要求：**

- 只用训练集有效区域拟合统计量，并保存为模型 buffer。
- 验证和测试固定使用这些统计量。
- 未拟合时明确报错，或显式选择恒等映射；不能默默退回测试 batch 统计。
- 匹配实验臂采用一致的标定协议。

**验收：** 模型评测模式下，同一 tile 单独推理与和其他 tile 拼 batch 推理，结果在合理数值误差内一致。

### 5. “Footprint 对齐”目前只是尺寸对齐，掩膜处理也不完整

**位置：** `AEFInjector.align_spatial_footprint()`、教师对齐损失及 D 的蒸馏损失。

当前函数只知道 H/W，通过池化或插值改变尺寸，无法检查 CRS、仿射变换、地理范围及像素中心是否对齐。

如果前处理已经严格对齐地理网格，这个函数可以作为后续重采样操作；应写明前提并检查元信息，不能把它本身称为完整的地理对齐。

**修订要求：**

- 在数据准备阶段确认坐标系、范围、网格原点、分辨率及像素中心约定。
- 非整数比例时，确认池化窗口符合目标地面覆盖；`adaptive_avg_pool2d` 不自动等价于精确面积重叠加权。
- 区分“特征网格间距”和“网络感受野”。例如 stride=8 时，4 m 输入对应 32 m 网格间距，5 m 输入则为 40 m；都不代表实际感受野仅有这些大小。
- 教师聚合应考虑有效覆盖率，并设置最低覆盖阈值。基本形式为：

```text
聚合教师 = aggregate(清理后的教师 × 有效掩膜)
           / aggregate(有效掩膜)
```

- 有效掩膜必须与几何增广同步。
- D 的 KL 当前仅排除忽略标签，特征蒸馏则直接取均值。需明确教师缺失区域的处理策略，并落实相应掩膜；若保证全覆盖，应显式验证该前提。
- 对所有无效区域，定义跳过或回退行为，避免分母为零与 NaN。

注意：零填充造成的幅值改变，在特定余弦计算中可能被归一化抵消，不能一概声称必然产生方向误差；但真实融合路径的幅值、无效覆盖及非有限值问题仍需处理。

**验收：** 用可人工核验的小栅格检查位置、聚合值与有效覆盖率，并检查边缘 NoData 区域。

### 6. 原实现兼容性与指标口径还没有被证明

**位置：** “1:1 复刻”“100% 兼容”等描述、`TinyUPerNet`、训练 CE 与 mIoU 实现。

同名类不等于相同实现。当前 `TinyUPerNet` 更接近轻量特征金字塔融合头，不能仅凭名称认定与原始头结构一致；原始自定义实现仍需查验。

**修订要求：**

- 最好在已有训练管线中增加新实验臂，保留原有 backbone、head、优化及评估流程。
- 若采用新的框架，应核对结构、参数量、归一化、插值设置、检查点键及加载结果。
- 若无法确认一致，应重跑新的 B0 和 R，不能把旧 0.4909 直接当成新框架的匹配基线。

尤其需要区分两件事：

1. 评估时不把背景 IoU 纳入平均；
2. 训练时把背景标签设为 `ignore_index`。

两者不是同一个操作。旧代码片段使用默认 CE，新代码使用 `ignore_index=0`，是否改变了训练目标必须结合原始标签映射核实，不能仅凭评估配置推断。

7 类与 8 类 mIoU 也不存在固定换算比例。在各类 IoU 完全相同的前提下：

```text
mIoU_8 = (7 × mIoU_7 + IoU_background) / 8
```

仅当背景 IoU 为 0 时，才出现乘以 7/8 的情况。

**验收：** 固定原始标签映射、训练忽略值、输出通道数、有效类别、缺失类别处理规则；先累计整个评测集的混淆矩阵，再计算 mIoU，避免平均各 batch 的 mIoU。

## 四、实验设计建议

### 1. A 放在第二阶段，并补充匹配对照

冻结缓存特征且 `enable_shared_adapter_for_A=False` 时，A 的辅助头仍可能只学习独立投影，无法改善分割使用的特征。

建议选择：

- **Adapter 路线：** CE 和辅助损失共同更新同一个 Adapter；部署时保留 Adapter，只移除辅助头。对照 B_A 保留完全相同的 Adapter，仅使用 CE。
- **主干微调路线：** 在线编码，两个损失共同更新主干；对照使用相同微调范围与预算，仅使用 CE。

A 的价值取决于共享路径，不取决于辅助损失是否下降。

### 2. D 先回答“蒸馏是否有效”，再回答“AEF 带来了什么”

D 与 B0 的比较可以证明教师监督在当前设置下有效，但不能单独证明提升源于 AEF 信息。

若 D 有稳定收益，再增加：

| 实验 | 教师 | 学生部署输入 | 主要用途 |
|---|---|---|---|
| B0 | 无 | 影像 | 基线 |
| D_img | 纯影像教师 | 影像 | 一般教师监督的对照 |
| D_R | 影像 + AEF 教师 R | 影像 | 检验含 AEF 的教师是否带来额外收益 |

尽量匹配教师训练预算、学生结构与蒸馏协议，并报告教师自身成绩。D_R 与 D_img 的差异能加强 AEF 贡献的证据，但仍应结合教师能力差异解释。

### 3. Shuffle/null 是补充诊断，不能替代匹配基线

错误区域教师或噪声可能造成分布扰动。配对正确优于打乱，说明配对有作用，但不等于完整的因果证明。

特别是 D 中，给冻结 R 输入错配 AEF，会改变教师预测。这不同于单纯打乱已生成的蒸馏目标，必须明确具体操作和解释范围。

建议优先完成 B0、Bcap 等匹配基线，再添加 shuffle/null。噪声均值、方差只用训练集估计；需要固定每个样本噪声时，用“全局种子 + 样本标识”定义，避免每个 batch 重新播种造成位置重复。

### 4. 不用单次小差异宣称等价，也不用失败证明“不可能”

建议修订措辞：

| 原倾向表述 | 建议表述 |
|---|---|
| 单 seed 差异小于 0.6 个百分点，因此等价 | 初筛未观察到明确差异，需重复实验；0.6 可作为预设业务阈值，不能代替统计等价检验。 |
| 冻结和微调均失败，证明单影像不可预测教师信息 | 当前数据、模型与优化条件下尚未获得有效迁移。 |
| Shuffle 已证明严格因果关系 | 配对扰动结果支持模型依赖对应信息，仍需结合匹配对照解释。 |
| 30 epoch 已完成充分训练 | 30 epoch 为初筛预算，需结合验证曲线检查收敛。 |
| 统一使用 B0 的学习率就是完全公平 | 这是初步受控比较；否定路线前，应给予各臂同等的小规模验证集调参预算。 |

候选方案至少进行 3 个种子的重复实验，报告均值、标准差及相同种子下的成对差值；3 次仍属于最低限度的稳定性检查。空间划分需避免相邻切片跨集合泄漏，测试集不参与选择配置。

## 五、建议执行顺序

| 阶段 | 工作 | 进入下一阶段的条件 |
|---|---|---|
| 0：实现验收 | 修复解码、缓存与增广、统计量、地理对齐、掩膜及冒烟测试 | 小型数值测试、真实小批次训练和纯影像端到端推理通过 |
| 1：建立可靠参照 | 在同一管线重跑 B0 与 R；保存并冻结 R | 指标口径一致，R 确实使用教师且有可解释的验证收益 |
| 2：最小 D 实验 | D 对 B0；仅 CE + 输出 KL，特征蒸馏权重为 0 | 评估是否存在初步稳定收益 |
| 3：最小 P 实验 | P 对 Bcap；先 AEF、先 cosine | 评估收益是否超出额外参数与结构的贡献 |
| 4：复核与归因 | 对候选方案重复种子；必要时增加 D_img 与 shuffle/null | 收益具有稳定性，结论与对照相符 |
| 5：共享特征学习 | A + 匹配的 B_A，或主干微调 + 匹配微调基线 | 辅助损失确实更新部署时保留的共享模块 |
| 6：迁移与扩展 | FBP 等目标任务；随后考虑 OlmoEarth、InfoNCE、多教师、特征 KD | 新增复杂度能够回答明确问题 |

初期不建议同时展开多个主干、多个教师、多个注入位置和多个损失。先建立一个解释清楚、部署约束正确的完整实验链路，再扩展组合。

名称建议统一为“6 个核心实验臂 B0/R/Bcap/P/A/D，加 R_null 补充对照”；若将 B_A、D_img 纳入，也应分别列出，避免名称与实际数量不一致。
