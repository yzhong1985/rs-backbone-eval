# 多光谱骨干模型评测：阶段报告

- 日期：2026-10-14
- 代码版本：`e1f7aed` 之后（含验证集选择、实验矩阵）
- 状态：第一阶段完成；学习率搜索进行中（夜间运行）

## 1. 目的

比较三个地球观测基础模型在同一批下游任务、同一划分、同一评测口径下的表现：

- **AnySat（base）**
- **Clay v1.5**
- **Prithvi-EO-2.0 300M-TL**（论文中的 TL 版本）

同时校验本项目流程与论文的一致性。

### 2.3 轨道（按设计文档）

- **B0 参考复现**：按论文协议或官方仓库配置复现 Prithvi，用于校验流程。
- **B1 全量微调（主结果）**：backbone 与任务头一起训练。
- **B2 冻结表征（辅助）**：backbone 冻结，只训练任务头。
- **B3 原生输入（能力上限）**：使用模型原生输入。目前只完成前向探针，尚无训练结果。

轨道数量保持 B0–B3 不变，这是设计文档确定的结构。唯一预期的新增是自研模型计划中的 **S 轨道**（随机初始化训练），目前只有方案，尚未执行。

### 2.4 训练与评测约定

- 种子：17、42、73（三个）。
- 指标：T1 为水体 IoU，T2 为烧毁区 IoU，T5 为 13 类 mIoU（同时记录 macro F1）。
- 评测划分：T1 用 test；T2、T5 用 official_validation（锁定，只运行一次）。
- 训练预算：T1、T2 为 50 epoch；**T5 为非官方的 20 epoch**（官方为 125），三个模型相同，结果不能直接与论文比较。
- 头部：分割任务使用 LiteSpatialHead（约 140 万参数）；T5 使用时序分割头。
- 输入：Prithvi 与 AnySat 为六波段（HLS 的 B02–B07）；Clay 使用派生元数据。AnySat 通过显式光谱适配器映射到十波段入口，不做零填充。

### 3.1 Backbone 评分卡（四个维度）

分数是相对值：只在本报告内比较，加入新模型后会变化。覆盖任务数不全时，该维度只能参考。

| 模型 | D1 任务效果 B1（覆盖） | D1 任务效果 B2（覆盖） | D2 输入灵活性 | D3 适配成本（分，B1 耗时/显存/参数量） | D4 稳定性（分，B1 种子标准差） |
|---|---|---|---|---|---|
| AnySat Base | 1.000（1/3） | 0.983（3/3） | 待测（需输入扰动实验） | 0.000（耗时 94.6 分钟，显存 19733 MB，B2 可训练 1580119，总 127485566） | 0.832（sd 0.0111） |
| Clay v1.5 | 0.941（1/3） | 0.873（3/3） | 待测（需输入扰动实验） | 0.951（耗时 4.6 分钟，显存 1396 MB，B2 可训练 2671661，总 314114605） | 0.789（sd 0.0139） |
| Prithvi-EO-2.0 300M-TL | 0.857（1/3） | 0.733（3/3） | 待测（需输入扰动实验） | 0.900（耗时 9.5 分钟，显存 5855 MB，B2 可训练 2671661，总 306557999） | 0.000（sd 0.0659） |

各维度的计算方式：

- **D1 任务效果**：各任务上相对最优模型的比例（均值），1 = 每个任务都是最优
- **D2 输入灵活性**：输入扰动（波段缺失、分辨率、时相）下的性能保持率
- **D3 适配成本**：B1 训练耗时的相对值（越省越高），并列出参数量、显存、微调增益
- **D4 稳定性**：B1 各任务种子标准差的相对值（越稳越高）

**解读**

- **任务效果（D1）**：三个模型都做过的任务只有 T2、T5，用的是冻结（B2）口径。在这一口径下 AnySat 最强（相对最优 0.983），Clay 次之（0.873），Prithvi 明显偏低（0.733）。B1 目前只有 T1，三个模型的数值接近（1.000 / 0.941 / 0.857），样本太少，只能作为初值。
- **冻结与微调的差距（D3 中的微调增益）**：这是最值得注意的一点。Prithvi 在 T1 上冻结比最优低约 3.9 个点，但微调后反而**高于**冻结结果约 7.5 个点，说明它的表征需要适配才能发挥；AnySat 和 Clay 微调后基本不变甚至略降，说明它们的特征直接可用。因此，若只看冻结结果会低估 Prithvi。
- **适配成本（D3）**：Clay 最省（B1 约 4.6 分钟、显存约 1.4 GB），Prithvi 居中（约 9.5 分钟、约 5.9 GB），AnySat 最费（约 95 分钟、约 19.7 GB，接近 24 GB 显卡上限）。如果要在有限的硬件上快速迭代，Clay 的性价比最高；AnySat 需要更多资源。
- **稳定性（D4）**：目前只反映 T1 的旧结果（学习率未按验证集选择），Prithvi 的种子波动最大（标准差 0.066）。学习率搜索完成后这个数字会更新，暂不作为结论。
- **综合判断**：现阶段可以说 AnySat 的原始特征最好、Clay 的性价比最好、Prithvi 需要微调且波动较大；但因为每个模型只覆盖了部分任务、D2 尚未测量，**还不宜给出总体排名**。等 B1 搜索和输入扰动实验完成后更新。

## 4. 关键决策与纠正

| 日期 | 决策 / 事件 | 原因与影响 |
|---|---|---|
| 10-12 | 使用 Prithvi 300M-TL，不用 600M | 与论文的 TL 版本对应，算力可承受 |
| 10-12 | 确定三家统一的 head（LiteSpatialHead）与评测器 | 保证公平比较 |
| 10-13 | 修复 TerraTorch 归一化问题，恢复 Prithvi 的波段归一化 | TerraTorch 1.2.13 的数据模块未应用增强，导致结果偏低 |
| 10-13 | 跳过全忽略标签的 batch | 避免交叉熵 NaN |
| 10-13 | AnySat B1 使用 224 裁剪 | 256 在 24GB 显卡上 OOM，**与其他模型输入不一致，需说明** |
| 10-14 | 隔离 3 个 AnySat 冻结 run，并重跑 | 这些 run 早于 NaN 修复，有 NaN loss，且没有代码版本；重跑后结果一致（0.8050 ± 0.0154） |
| 10-14 | T5 统一改为 20 epoch 非官方预算 | 官方 125 epoch 在单卡上不可行（AnySat 约 38 小时/种子） |
| 10-14 | T5 中 AnySat 使用原生时序融合；Clay 与 Prithvi 为逐日期编码 + 时序头 | 接口限制，**两种结构不同，需说明** |
| 10-14 | 发现 B0 学习率选择依据测试集，判定为违规，安排重做 | 违反"不用测试集调参"规则 |
| 10-14 | B1 改为按验证集选择 checkpoint，学习率在 {3e-5, 1e-4, 3e-4} 中按验证集选 | 与设计文档一致；搜索在夜间进行 |
| 10-14 | 暂不做 T5 的 B1（微调） | 每个种子约 3.6 小时起，成本高，待 T1、T2 结论后再定 |
| 10-14 | 暂不做 T6（Sen4Map） | 需要新硬盘 |

## 6. 局限与风险

1. **与论文不能直接比较**：T5 是 20 epoch 的冻结设置，论文是 80–125 epoch 的微调。
2. **B2 对需要适配的模型不利**：Prithvi 在 T1 上 B2 为 0.615，B1 为 0.690，说明冻结结果会低估它的潜力。因此，判断 backbone 好坏应以 B1 为主，B2 作为辅助。
3. **B1 的 AnySat 输入尺寸与其他两家不同**（224 vs 512），比较时需说明。
4. **部分早期 run 缺少代码版本与权重哈希**：从 10-14 起新 run 会自动记录（`-dirty` 表示有未提交的改动）。
5. **种子数较少**：T5 只有 1–3 个种子，T2 的标准差较大（Prithvi 为 ±0.053），部分差距在误差范围内，不能下结论。
6. **B0 与论文仍有约 6.8 个点的差距**，原因未确认（论文使用了超参搜索与 10 个种子）。
