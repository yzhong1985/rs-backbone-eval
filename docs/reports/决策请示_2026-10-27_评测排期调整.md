## 三、关键事实：T8 的记录损坏是可恢复的

v1 说"T8 产出为零、继续跑是白烧"，**这个判断是错的**，已撤回。核查结果：

| 事实 | 证据 |
|---|---|
| 六条正式 T8 记录都有完整混淆矩阵 | `run.json` 的 `artifacts` 指向 `confusion_per_scene.json`，内含逐 group 的 25×25 计数 |
| 主指标 mIoU 本身有效 | Clay 记录 0.41963516… 与由混淆矩阵重算的值**逐位吻合** |
| 只有两个辅助指标损坏 | 每条正式记录**都只有** `frequency_weighted_iou` 与 `class_0 IoU` 为空 |
| 原因是确定性的，不是偶发 | T8 把 0 号类设为"忽略类"，其像素数为 0 → IoU 无定义 → `0 × 无定义` 污染加权和 |
| 任何 T8 运行都会复现 | 6 条正式记录 + 3 条 smoke 记录全部命中同一模式 |

结论：**修好写入逻辑后，用已存的混淆矩阵重算即可，不需要重训，也不需要中止正在跑的训练。**

> **执行进展（2026-10-27，代码提交 `5925ab0`）**：已按此路径完成。九条 T8 记录（6 条正式 + 3 条 smoke）通过新工具 `scripts/rederive_metrics.py` 重算恢复，主指标与重算值逐位一致，原始 `run.json` 已备份为 `run.json.pre-rederive-2026-10-27`。恢复后 T8 进入报告与 Portal：

> | Prithvi-EO-2.0 300M-TL（冻结） | 3 | 0.4301 ± 0.0190 |
>
> 说明：这两个数字是**恢复出来的**，不是新训练；它们的训练早于本次修复，因此 `git_commit` 仍指向旧提交。审计不将其判为 stale，因为重算证明了所有有限值逐位一致（58 条有混淆矩阵的记录，0 处差异）。

顺带纠正 v1 的另一处判断：中止当前 AnySat 训练**确实会丢进度**。该 worker 没有逐轮断点续训；且**冻结轨不保存权重**（`best_checkpoint.pt` 只在 `select=True` 的全量微调分支写出，已核对冻结记录目录内无 checkpoint）。真正可复用的是**混淆矩阵**，不是权重。所以 v1 把中止代价说成"作废 4 小时"是低估。

## 四、四个方案的公平对比

**所有方案都包含 D1（修写入逻辑 + 重算六条记录）**——修 bug 是共同前置，不构成方案差异。

| | A 中止 T8 | B 不干预 | C 另一台机器试跑 1 个种子 | **D（建议）** |
|---|---|---|---|---|
| 修 T8 记录 | ✅ | ✅ | ✅ | ✅ |
| T8 AnySat 训练 | 中止，已跑进度全部丢失 | 继续 | 继续 | **继续** |
| AnySat 缺波段 | 4090 立即跑，约 4.5 小时（仅 B2 三训练） | 排到最后，10/29 晚 | 3080 跑 1 个种子，约 1.5 小时 | **3080 跑完整组**，10/28 凌晨 |
| T8 有效结果 | 顺延一天，且 AnySat 需重跑 | 随训练完成陆续产出 | 同 B | **同 B** |
| 作废工作量 | AnySat 已跑的约 4 小时 | 0 | 0 | **0** |
| 显存风险 | 无 | 无 | 3080 只有 20 GB，全量微调可能不足 | 同 C |
| 主要缺陷 | 前提不成立，白白丢进度 | 缺波段结果最晚，且占用 4090 两天 | 单种子不能进主表 | 需先做数据/环境验证 |

**工时的口径**（v2 写"约 10 小时"时未说明范围，现更正）：整条 `T1HOLDA` 队列是 **6 次训练**，不是 3 次——

| 组成 | 内容 | 实测/估算 |
|---|---|---|
| B2 × 3 种子 | 干净评测 + 缺波段 2 组 + 降分辨率 2 组 + 日期扰动 + Bolivia | 77.7 min/种子 + 5 次附加评测 ×1.8 min ≈ **87 min/种子，合计 4.4 h** |
| B1 × 3 种子 | 干净评测 + Bolivia | 112 min/种子，**合计 5.6 h** |
| 合计 | | **≈ 10 h** |

所以"补测 AnySat 缺波段"本身是 **4.4 h**；**10 h** 指的是整条队列。若只想要缺波段结论，可以只拆出 B2 部分（见 §7.4）。

**为什么建议 D**：

1. 中止 T8 的唯一理由（"产出为零"）不成立，反而会真实损失 4 小时进度；
2. 3080 今晚就空出来了，且只要有 T1 数据就能跑——**数据只有 1.8 GB**，局域网传输成本可忽略；
3. 这样 4090 和 3080 各干各的，两条线并行，**总完成时间最短**；
4. 单种子能验证可跑性、估出真实工时，比直接排整条队列更稳。

## 六、结论边界（修订 v1 的过度承诺）

v1 写"已有结论不会被推翻"，这句话不成立，已删除。正确表述：

> **已完成的实验数值不因排期调整而改变；但补测 AnySat 缺波段的目的是检验现有解释，如果 AnySat 同样抗缺波段，"只有 Clay 稳得住"这一结论必须改写。**

同时，缺波段结论本身有明确适用范围，不能概括成"缺波段致命"：

- **任务**：仅 T1（洪水）；
- **轨道**：仅冻结路径（全量微调未测）；
- **处理方式**：推理时把指定通道替换为训练集均值，不是物理缺失通道；
- **测试范围**：NIR + 两个 SWIR；未测可见光缺失；
- **未覆盖**：AnySat（本次补测）、T8、T5。

同理，"元信息不影响"也只覆盖 T1 冻结路径的日期/GSD 扰动，不外推。

## 七、预先声明的规则（避免"看结果定样本量"）

### 7.1 T8 的 AnySat：先 1 个重复

- 单重复标注为 `exploratory`，**只用于**验证可跑性、估算真实工时、给出方向性信号；
- **不进主表、不进 D1/D2 汇总、不进对外报告**；
- 与已完成的两个模型（Clay、Prithvi，各 3 个重复）对比时，必须注明 AnySat 为单重复。

### 7.2 补满三个重复的触发条件（与结果好坏无关）

同时满足三条即补满，不满足则不补满，**不因"结果看起来有希望"而追加**：

1. 单重复运行完整完成，无 OOM、无异常退出；
2. 实测工时在预算内（≤ 每个重复 16 小时）；
3. 该单元在正式对照表中有对应位置（即当前 T8 确实需要三个模型对比）。

若三条不满足，记录为工程结论（不可行/超预算），不升级为正式结果。

### 7.3 跨机器口径（按 `AGENTS.md` 执行）

- 同一实验单元的种子**必须留在同一主机/GPU 类型**，不能把 4090 与 3080 的种子拼成同一组正式结果；
- 因此搬到 3080 的必须是**整组**（三个种子 + 同一轨道），不能"4090 跑两个、3080 跑一个"；
- 若只做单种子探索，标注 `exploratory`，不并入任何正式 cell；
- 报告与 `run.json` 记录 host/GPU 类别，跨机器比较只作参考。

### 7.4 只拆 B2 的选项

若只需要"AnySat 缺波段"这一条结论，可以只执行 `T1HOLDA` 的 B2 部分（3 次训练，**约 4.4 h**），把 B1 留到 4090 空出后再跑。代价：该 cell 的 B1 与 B2 不同批产出，报告中需注明批次。

## 九、小词典

| 词 | 解释 |
|---|---|
| 主干模型 | 提前用海量卫星图训练好的"通用看图能力"，如 AnySat、Clay、Prithvi |
| T1 / T1S / T4 / T8 | 具体任务：洪水（光学/雷达）、滑坡、国产高分影像地物分类 |
| 重复（种子） | 同一实验用不同随机初始化跑几遍，看结果稳不稳；正式结果统一跑 3 遍 |
| 缺波段实验 | 推理时把某几个波段替换成"平均图"，看模型还认不认得出目标 |
| 混淆矩阵 | 一张"预测 vs 真值"的计数表，指标可以从它完整重算 |
| 记录被拒收 | 结果文件不符合规范，系统拒绝读取；本次为可修的系统性写入问题 |
| 域外轨 | 训练数据里没见过的传感器/区域，单独考察泛化，不并入主排名 |
