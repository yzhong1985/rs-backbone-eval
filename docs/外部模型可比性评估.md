# 外部模型可比性评估（OlmoEarth / TerraMind / DOFA）

日期：2026-10-15。版本：v2（按上级评审意见修订，修订点见第 12 节）。状态：评估与建议，尚未接入任何新增模型，也未产生新增成绩。

本评估回答一个问题：**对"自研 5–15M、多模态、多分辨率、带时序的光学＋SAR 骨干"这一目标，候选外部模型能提供什么样的参照？** 结论用于修订[模型扩展与低成本评测计划](./模型扩展与低成本评测计划.md)的候选排序。关联：[自研骨干接入现有评测计划](./自研骨干接入现有评测计划.md)、[遥感Backbone评价体系改进建议](./遥感Backbone评价体系改进建议.md)。

> **v2 核心修正**：撤回 v1"容量匹配即可判断架构是否正确"的论证。容量匹配只**降低混淆**，不构成架构归因的前提；证明自研架构有效**主要靠同数据、同预算的内部受控消融**。外部模型（无论大小）提供的是**性能与成本参照**，大模型同样有效，不应说成"只能作能力上限"。**保留的结论：OlmoEarth Tiny 优先。**

## 1. 目的与判断标准

自研骨干的目标可拆成四个维度。外部模型在这四维上的覆盖程度，决定它**能回答哪一类问题**（而不是决定它是否"可比"）：

1. **容量**：参数量是否落在 5–15M 附近。容量相近能减少"大小差异"这一混淆项，但**不能消除**预训练数据、预训练目标、训练预算的差异，因此**不能仅凭容量相近就归因架构**。
2. **多模态**：是否**学过 SAR**、**单模态能否分别迁移**、**是否支持联合输入**、**联合输入是否有实测收益**——这四件事要分开看，不能由"输入入口的形式"单独推断。
3. **多分辨率**：接口是否接受 GSD/尺度；以及**是否做过尺度实验**（打勾不等于验证）。
4. **时序**：模型内部是否有时序机制，还是靠任务侧逐日期编码＋外部头拼接。

**关键区分**：

- **外部模型**：提供性能与成本参照（"成熟大模型能达到什么水平、花多少成本"），以及特定机制（如波长条件化入口、多模态融合）的对照。
- **架构归因**：由自研模型在**同数据、同预算**下的受控消融支撑（RGB/完整光谱、单期/多期、预训练/随机初始化）。

## 2. 依据与方法

- **参数量**：分别统计 **backbone / 输入适配器 / 任务头 / 总参数**，不混用口径（v1 的修正点之一）。现有三模型读取运行记录；新增候选在本机构建 backbone 实测（**仅 backbone，不含任务头与适配器**）。
- **输入机制**：官方仓库/模型卡，加上本仓库 worker 的实际调用代码。
- **环境**：TerraTorch 1.2.13 + torchgeo 0.9.0，位于本仓库 `workers/prithvi/.venv`；运行记录位于 `/geodata/rs-eval/runs`。复现命令见第 10 节（需要该 venv 与运行目录，环境不同则数值可能不同）。

## 4. 能力维度矩阵

**模态与融合**（区分"学过 SAR"与"联合融合"，v1 的修正点之一）：

| 模型 | 用过 SAR 预训练 | 光学单模态可迁移 | SAR 单模态可迁移 | 支持联合输入 | 联合输入实测收益 |
|---|---|---|---|---|---|
| AnySat base | ✅ 多传感器 | ✅ | ✅ 原生 s1 入口 | 多模态入口 | 本项目未实测 |
| Clay v1.5 | ✅ 官方规格含 S1 | ✅ | △ 经波长/平台元数据 | 本项目未实测 | 未实测 |
| Prithvi | ✗ 纯光学 | ✅ | ✗ | ✗ | — |
| OlmoEarth Tiny | ✅ S1＋S2 | ✅ | ✅ | 支持 | 未实测 |
| TerraMind tiny | ✅ S2＋S1 | ✅ | ✅ | 支持（`modalities`） | 未实测 |
| DOFA base | ✅ 论文含 S1 | ✅ | ✅ 官方 SAR 用法 | ✗ 单模态一次前向、跨模态共享权重，非融合架构 | — |

**分辨率 / 时序 / 容量**：

| 模型 | 多分辨率接口 | 尺度实验 | 原生时序 | backbone |
|---|---|---|---|---|
| AnySat base | ✅ `patch_size` 以米为单位 | 本项目未做（仅固定 160m） | ✅ 内部按日期聚合 | 125.9M |
| Clay v1.5 | ✅ `gsd` 为显式输入 | 未做 | ✗ 单时相 | 311.4M |
| Prithvi | △ 固定位置编码 | 未做 | ✅ 3D patch＋temporal 位置编码 | 303.9M |
| OlmoEarth Tiny | ✅ 10/20/40/80m | 未做 | ✅ 1–12 个时相 | 12.5M |
| TerraMind tiny | ✅ 位置编码可插值，224 仅为默认 | 未做 | ✗ 靠 wrapper | 5.6M |
| DOFA base | ✗ 固定 patch16/224 | 未做 | ✗ | 111.3M |

**读法**：接口一栏是"能力存在"，"未做"一栏表示本项目尚无证据。**接口打勾不等于能力已验证**——多分辨率需要尺度实验，融合需要配对样本对照。

## 5. 逐模型评估

### 5.1 现有三模型（Clay / AnySat / Prithvi）

- **AnySat 覆盖最全**：原生多传感器入口（含 S1）、`patch_size` 以米为单位、内部按日期聚合。是自研目标最接近的"大模型版"，但 125.9M backbone。
- **Clay 覆盖多分辨率与光谱入口**：`gsd` 显式输入、`waves` 波长元数据；官方规格表明预训练用过 S1（**因此不能说它"不是多模态"**），但本项目未做联合输入实验，也没有原生时序（T5 只能逐日期＋外部头）。
- **Prithvi 只覆盖时序**，且纯光学。

三者作为**性能与成本参照**保留；"架构是否有效"仍由自研内部消融回答。

### 5.2 OlmoEarth v1.2 Tiny —— 保留为首选

- 编码器 12.5M，与自研目标同量级。
- 多模态（S1、S2、Landsat）、多分辨率（10/20/40/80m）、**原生时序（官方建议 1–12 个时相，不是"1–12 月"）**。
- 官方开源（`allenai/olmoearth_pretrain`）。

它是"同量级＋多模态＋多分辨率＋原生时序"的外部参照，**但容量相近不代表能证明自研架构正确**；它的价值是提供一个同量级、同时具备多模态/多分辨率/时序的性能与成本参照点。代价：需要新依赖与其自身模态/分辨率体系；T5 的冻结读出是它自身的时序编码器，与 Clay/Prithvi 的"逐日期＋头"不是同一融合口径，必须单列。

### 5.3 TerraMind v1（修正点：普通 backbone 输出连续特征）

- 已安装在现有 TerraTorch 1.2.13 中（`terratorch_terramind_v1_tiny/small/base`，含 `_tim` 变体与 S2L2A/S1RTC tokenizer），接入路径与 Prithvi 同栈。
- 官方支持波段子集：`bands={'S2L2A': ['BLUE','GREEN','RED','NIR_NARROW','SWIR_1','SWIR_2']}`，正好对应 T1 六波段。
- **普通 backbone 接收原始影像、输出连续的 Transformer patch 特征**（本机实测为连续 float 张量）。v1 说它是"量化 token"是**错误**：FSQ 量化属于生成/TiM 路径的 tokenizer，与普通编码器不是一回事，两者不能混为一谈。
- 224 只是默认输入尺寸，实现通过**位置编码插值**支持其它尺寸（`encoder_embeddings.py`："Fixed-size positional embeddings. Can be interpolated to different input sizes"）。
- 许可 Apache-2.0；TerraTorch 提供多时相 wrapper 及多时相作物示例。
- **tiny 仅 5.6M，是除 OlmoEarth Tiny 外同量级的多模态候选**。
- 局限：默认单图（时序靠 wrapper，属任务侧融合）；本项目尚未做尺度实验。

### 5.4 DOFA

- 已安装在现有 torchgeo 0.9.0 中（`dofa_base/large_patch16_224`）。
- 独特能力：**波长条件化动态 patch embedding**，传波段中心波长即可接收任意波段子集；**官方提供 SAR 输入用法**（S1 用 3.75 占位波长）。因此不能说它"没有 SAR 能力"。
- 它**学过 SAR**，但设计上是"单模态一次前向、跨模态共享权重"，**不是光学＋SAR 联合融合架构**；联合输入收益无从谈起。
- 局限：backbone 111.3M/337.2M，比目标大一个数量级；单图模型；本机实测 `forward_features` 默认返回全局池化向量（`(1, 768)`，即使 `global_pool=False`），做分割需自行提取 patch token。

**定位：DOFA 用于"光谱入口"这一个机制问题，不进入 backbone 能力比较主表。**

## 6. 结论

1. **保留 OlmoEarth Tiny 优先**：它是同量级、且同时具备多模态/多分辨率/原生时序的外部参照。
2. **撤回 v1 的强论证**：容量匹配**只降低混淆，不构成架构归因的前提**；即使参数相近，预训练数据、目标、预算仍不同。
3. **大模型仍是有效参照**：提供性能上限与成本参照，不再表述为"只能作能力上限"。
4. **架构结论由自研模型的受控消融支撑**（同数据、同预算；RGB/完整光谱、单期/多期、预训练/随机初始化）。
5. **TerraMind tiny 保留为同量级候选**；**DOFA 用于光谱入口机制问题**。
6. **能力不能靠接口打勾**：多模态融合需要配对样本对照，多分辨率需要尺度实验。

## 7. 建议范围（恢复原低成本预算约束）

原计划的预算约束是：**默认只新增 OlmoEarth Tiny，第二候选按需二选一**。本评估不改变该约束：

| 阶段 | 模型 | 任务 | 轨道 | 运行数 |
|---|---|---|---|---:|
| 默认 | OlmoEarth Tiny | T1 ＋ T5 | B2 冻结 | 4–6 |
| 按需二选一 | TerraMind tiny **或** DOFA | 各一个针对性任务，种子 17 | B2 冻结 | 1（初筛） |

- **不排"依次接入三家"**。DOFA 不铺两个任务；只有"光谱入口"问题仍未被现有证据回答时才启用。
- 若某任务要下**融合收益**结论，必须补**配对样本**上的三个对照：光学单独 / SAR 单独 / 联合输入（且配对需一致地点、标签支持集与可用日期）。
- 若某任务要下**多分辨率**结论，必须补**尺度实验**，不能只声明接口支持。

结果表须显式列出 **backbone / 适配器 / 任务头 / 总参数**，避免把容量差距误读为架构结论；首轮按任务展示，不做全任务综合排名。

## 8. 比较边界与已知限制

- **读出/融合口径不统一**：OlmoEarth 用原生时序编码器读出，Clay/Prithvi/TerraMind/DOFA 用逐日期编码＋共享头。只有读出与融合设置可比时才讨论特征质量，否则分表。
- **HLS 映射**：T5 用三期 HLS 六波段，而 TerraMind/OlmoEarth 的原生模态是 S2。HLS 需显式声明为"映射输入"并单列。
- **DOFA 池化输出**：默认 `forward_features` 返回全局向量，分割需自行取 patch token。
- **接入成本只是小头**：每个新增模型都要在锁定协议下重跑对应冻结基线，否则同口径不成立。
- **权重尚未下载**：TerraMind / DOFA / OlmoEarth 的权重与下载条目尚未接入；本评估的参数量为"构建 backbone 实测"或"官方文档"，不是完整下游成绩。

## 9. 前置条件与下一步

1. **修 Prithvi 的 manifest 记录**：现仍把文件名当 `manifest_sha256`（见第 11 节）。
2. **逐条审计历史运行**：按当前协议核对每条 T1/T5 冻结成绩，**只重跑不一致的对照**，不整批重跑（见第 11 节）。
3. **接入 OlmoEarth Tiny 并先做短跑**：记录成本、显存、吞吐、缓存体积，再决定是否进入正式种子。

## 11. 历史成绩审计

- **确认存在**：Prithvi worker 的 `manifest_sha256` 仍记录清单文件名（`workers/prithvi/src/prithvi_worker/runner.py`），此前 R10 只修了 AnySat/Clay。影响"复用历史结果"的数据追溯，应在重跑基线前一并修复。
- **协议变更后不能直接复用旧成绩**：上一轮 R1–R8 已改变实验身份、验证选模、D2 分类与**冻结路径的损失网格**（R6 改了 Prithvi `t1_frozen`/`t2`/`t3` 与 Clay `t3`，更早改了 Prithvi/Clay T5）。
- **做法**：**逐条审计**历史运行，核对每条 T1/T5 冻结成绩是否满足当前协议（划分、波段、日期、标签网格、选模口径、损失网格、清单身份）；**只重跑不一致的对照**，不整批重跑。
