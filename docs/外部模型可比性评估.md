# 外部模型可比性评估（OlmoEarth / TerraMind / DOFA）

日期：2026-10-15。状态：评估与建议，尚未接入任何新增模型，也未产生新增成绩。

本评估回答一个问题：**对"自研 5–15M、多模态、多分辨率、带时序的光学＋SAR 骨干"这一目标，候选外部模型能否提供同口径、可解释的参照？** 结论用于修订[模型扩展与低成本评测计划](./模型扩展与低成本评测计划.md)的候选排序。关联：[自研骨干接入现有评测计划](./自研骨干接入现有评测计划.md)、[遥感Backbone评价体系改进建议](./遥感Backbone评价体系改进建议.md)。

## 1. 判断标准：四个可比性维度

自研骨干的目标可以拆成四个维度。外部模型只有在这四维上都"对得上"，才能回答"我们的架构选择对不对"：

1. **容量可比**：参数量落在 5–15M。若外部模型大 10–60 倍，任何精度差距都能被"人家大"解释掉，无法归因于架构。
2. **多模态**：能真正接收光学＋SAR（而不只是"把 SAR 当带假波长的普通通道"）。
3. **多分辨率**：把地面采样距离（GSD）作为显式输入，能处理真实多分辨率。
4. **原生时序**：模型内部有时序机制（而非靠任务侧逐日期编码＋外部头拼接）。

## 2. 依据与方法

- **参数量**：现有三模型直接读取真实运行记录的 `training.total_parameters`；候选模型在**已安装环境**中构建 backbone 后实测；OlmoEarth 取官方文档（本地尚未安装，见第 8 节）。
- **输入机制**：官方仓库/模型卡，加上本仓库 worker 中的实际调用代码。
- **环境核验**：现有 Prithvi worker 环境（TerraTorch 1.2.13 + torchgeo 0.9.0）已可直接构建 TerraMind 与 DOFA，无需新依赖。

## 5. 逐模型评估

### 5.1 现有三模型（Clay / AnySat / Prithvi）

- **AnySat 覆盖最全（三个维度）**：原生多传感器入口、`patch_size` 以米为单位（分辨率感知）、内部按日期聚合。它是自研目标最接近的"大模型版"，但 127.5M，仍比目标大 8–25 倍。
- **Clay 覆盖两个**：`gsd` 是显式输入（多分辨率）、`waves` 波长元数据支持任意波段；但预训练以光学为主、**不是真正的光学＋SAR 融合**，且**没有原生时序**（T5 只能逐日期编码＋外部头）。
- **Prithvi 只覆盖时序**，且纯光学。

**结论：三者可作为能力上限参照并保留，但不能回答"自研架构选择是否正确"。**

### 5.2 OlmoEarth v1.2 Tiny —— 唯一四维全中

- 编码器 12.5M，与自研目标同量级。
- 多模态：官方公开 S1、S2、Landsat 的时空模型。
- 多分辨率：显式支持 10/20/40/80m。
- 原生时序：1–12 个月的时序上下文。
- 官方为开源仓库（`allenai/olmoearth_pretrain`）。

**它是目前唯一"同量级＋多模态＋多分辨率＋原生时序"的外部参照，正是自研目标最缺的那一格。**

代价：需要新依赖（`olmoearth_pretrain`）与它自己的模态/分辨率体系；T5 的冻结读出是它自身的时序编码器，与 Clay/Prithvi 的"逐日期＋头"不是同一融合口径，必须在报告中单列。

### 5.3 TerraMind v1

- 已安装在现有 TerraTorch 1.2.13 中（`terratorch_terramind_v1_tiny/small/base`，含 `_tim` 变体与 S2L2A/S1RTC tokenizer），接入路径与 Prithvi 同栈。
- 官方支持波段子集：`bands={'S2L2A': ['BLUE','GREEN','RED','NIR_NARROW','SWIR_1','SWIR_2']}`，正好对应 T1 六波段。
- 许可为 Apache-2.0；TerraTorch 提供多时相 wrapper 及多时相作物示例。
- **tiny 仅 5.6M，是除 OlmoEarth Tiny 外唯一同量级的多模态参照。**
- 局限：**单图模型**（时序靠 wrapper，属任务侧融合）；**无 GSD 输入**，回答不了多分辨率；是生成式 tokenizer 模型，冻结特征为量化 token，与连续 ViT 特征相比需说明口径。

### 5.4 DOFA

- 已安装在现有 torchgeo 0.9.0 中（`dofa_base/large_patch16_224`）。
- 独特能力：**波长条件化动态 patch embedding**，传波段中心波长即可接收任意波段子集，甚至 S1 VV/VH（用 3.75 占位）。这是"我们该不该用固定输入适配器"的直接对照。
- 局限：**参数量 111M/337M，与目标差一个数量级**；**单图模型**；S1 只是占位波长、**不是真正的光学＋SAR 融合**；本机实测其 `forward_features` 默认返回全局池化向量（`(1, 768)`，即使 `global_pool=False`），做分割需自行提取 patch token。

**结论：DOFA 应定位为"光谱入口机制对照"，不应进入"backbone 能力比较"主表。**

## 6. 结论

1. **现有 Clay / AnySat / Prithvi 只能作能力上限参照**：容量 127–315M，比目标大 10–60 倍，无法归因架构差异。
2. **四维全中的外部参照只有 OlmoEarth Tiny（12.5M）**，因此它是本轮最值得投入的新增模型。
3. **TerraMind tiny（5.6M）补"同量级＋多模态"这半格**，接入成本低（同 TerraTorch 栈），但无时序/多分辨率贡献。
4. **DOFA 只在"光谱入口"这一个机制问题上值得做**，且不是同量级、不是真融合、不做时序任务。
5. **反对对新增模型都铺 T1＋T5**：那正是原计划警告的"只是增加一个模型名字，没有新问题"。每个外部模型应绑定一个它独有的比较问题。

## 7. 建议的接入范围

| 模型 | 定位（它独有的比较问题） | 任务 | 轨道 |
|---|---|---|---|
| **OlmoEarth Tiny** | 同量级＋多模态＋多分辨率＋时序的主参照 | T1 ＋ T5 | B2 冻结（必要时 T1S） |
| **TerraMind tiny** | 同量级多模态参照；光学＋SAR 融合入口 | T1（＋ T1S） | B2 冻结 |
| **DOFA base** | 波长条件化光谱入口 vs 固定适配器 | T1 ＋ T1S | B2 冻结，单种子 |
| Clay / AnySat / Prithvi | 能力上限参照（已存在） | 复用 | — |

报告中的**结果表必须显式列出参数量与容量差距**，避免"大模型赢小模型"被误读为架构结论。首轮输出按任务展示，不做全任务综合排名（与既有 D1 共同任务集口径一致）。

## 8. 比较边界与已知限制

- **读出/融合口径不统一**：OlmoEarth 用原生时序编码器读出，Clay/Prithvi/TerraMind/DOFA 用逐日期编码＋共享头。只有读出与融合设置可比时才讨论特征质量，否则分表。
- **HLS 映射**：T5 用三期 HLS 六波段，而 TerraMind/OlmoEarth 的原生模态是 S2 L2A。HLS 需显式声明为"映射输入"并单列。
- **TerraMind 生成式表示**：冻结 token 特征与连续 ViT 特征的比较需注明口径。
- **DOFA 池化输出**：默认 `forward_features` 返回全局向量，分割需自行取 patch token。
- **接入成本只是小头**：每个新增模型都需在锁定协议下**重跑对应的 T1/T5 冻结基线**，否则同口径不成立。
- **权重尚未下载**：TerraMind / DOFA / OlmoEarth 的权重与下载条目尚未接入，本评估的参数量为"构建 backbone 实测"或"官方文档"，不是完整下游成绩。

## 9. 前置条件与下一步

1. **先修 Prithvi 的 manifest 记录**：现仍把文件名当 `manifest_sha256`（R10 漏项），影响基线数据可追溯（见第 11 节）。
2. **锁定协议并重跑 T1/T5 冻结基线**：这是所有新增对照成立的前提。
3. **按第 7 节顺序接入**：OlmoEarth Tiny → TerraMind tiny → DOFA，每接入一家先做短跑（成本、显存、吞吐、缓存体积），再决定是否进入正式种子。

## 10. 证据与出处

**环境版本（本机核验）**：TerraTorch 1.2.13；torchgeo 0.9.0；两者均在现有 `workers/prithvi/.venv` 中。

**参数量**：现有三模型取自 `/geodata/rs-eval/runs/*/run.json` 的 `training.total_parameters`；TerraMind/DOFA 为在已安装环境构建 backbone 后 `sum(p.numel())` 实测。

**官方出处**：

- OlmoEarth：[仓库](https://github.com/allenai/olmoearth_pretrain)（v1.2 Tiny 编码器 12.5M / decoder 1.9M；分辨率 10/20/40/80m；时序 1–12 月；S2/S1 输入）。
- TerraMind：[仓库](https://github.com/ibm/terramind)、[模型卡](https://huggingface.co/ibm-esa-geospatial/TerraMind-1.0-base)（`modalities` 与 `bands={...}` 子集 API、Apache-2.0、多时相 wrapper 示例）。
- DOFA：[仓库](https://github.com/zhu-xlab/DOFA)、[torchgeo 文档](https://docs.torchgeo.org/en/latest/api/models/dofa.html)（波长条件化输入；S1 用 3.75 占位波长）。

## 11. 附带发现

- 核查基线可复用性时发现：**Prithvi worker 的 `manifest_sha256` 仍记录清单文件名**（`workers/prithvi/src/prithvi_worker/runner.py`），此前 R10 只修了 AnySat/Clay。该项影响"复用历史结果"的数据追溯，建议在重跑基线前一并修复。
- 上一轮 R1–R8 已改变实验身份、验证选模、D2 分类与**冻结路径的损失网格**（R6 改了 Prithvi `t1_frozen`/`t2`/`t3` 与 Clay `t3`，更早改了 Prithvi/Clay T5）。因此现有 T1/T5 冻结成绩与新增模型不同口径，**不能直接当对照**。
