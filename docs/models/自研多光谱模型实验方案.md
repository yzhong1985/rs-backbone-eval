# 自研多光谱模型实验方案

版本：v1.0（草案） ｜ 日期：2026年10月13日 ｜ 状态：**待评审，尚未实施**

> 本文只定义"自研模型"这一条实验线的范围、口径与实施步骤，**不改变**现有 7 任务评测协议。
> 主协议见[《AnySat 与 Clay 七任务下游评测设计（Prithvi-EO-2.0 对照）》](../evaluation/七任务冻结主干评测设计_AnySat_Clay.md)，
> 基础设施见[《代码基础设施与 Web Portal 设计》](../architecture/代码基础设施与Web_Portal设计.md)。

## 一、目的

回答三个现有评测无法回答的问题：

1. **多光谱预训练到底值多少钱**——一个从零训练的同规模模型，在这 7 个任务上落后多少？
2. **红外波段贡献多少**——同一自研模型在 RGB / RGB+NIR / 六波段 / 十波段下的增益曲线。
3. **时相与架构选择的性价比**——空间编码器（CNN vs ViT）、时相融合方式（均值 vs 注意力）、参数量阶梯各带来多少收益。

## 二、范围与边界

| 项 | 决定 |
|---|---|
| 比较层级 | **只设计编码器（encoder），解码统一用根项目的共享 `LiteSpatialHead`**。这样与现有 B1/B2 表同头可比，差异只来自编码器设计 |
| 新增轨道 | 新增 **S 轨道（scratch，随机初始化）**，与 B1（预训练后微调）、B2（冻结）分开成表，禁止混排 |
| 输入 | 严格按各任务的官方协议波段与时相（T1 六波段 S2、T2 六波段 HLS、T5 三时相 HLS 六波段）；额外模态（S1/DEM/VHR）只能作为 S3 原生输入补充轨道单列 |
| 现有结果 | 不修改、不重算已有的 B0/B1/B2 记录；S 轨道是新增行 |
| 预训练 | 本方案**不含**自监督预训练（那是阶段 4 的可选项，需单独方案与算力评估） |

## 三、与现有框架的接口

自研模型作为**第四个模型**接入，复用现有全部公共层：

```text
configs/models/scratch_<name>.yaml      # ModelSpec：model_id / worker_id / checkpoint_env / worker_command
configs/protocols/from_scratch.yaml     # ProtocolSpec：新增 regime=scratch
workers/scratch/                        # 独立环境（torch + rs-backbone-eval 可编辑依赖）
  src/scratch_worker/
    model.py                            # 自研编码器（唯一的"设计"部分）
    dataset.py                          # 复用 manifest 读取逻辑
    train.py                            # 训练循环（复用 RunWriter/指标/共享头）
    runner.py                           # WorkerRequest 处理与动作分派
```

复用清单（不重复实现）：

- `rs_backbone_eval.heads.LiteSpatialHead`（统一轻量头）
- `rs_backbone_eval.evaluation`（全局混淆矩阵、逐类 IoU、mIoU、bootstrap）
- `rs_backbone_eval.worker_runtime.RunWriter`（run.json 原子生命周期）
- `rs_backbone_eval.data.*`（manifest 与审计）
- Portal 自动按 `model_id` 聚合展示，无需改动

## 四、新增轨道定义

| 轨道 | 含义 | 训练内容 |
|---|---|---|
| **S0** | 从零训练的参考基线 | 编码器 + 共享头，全部随机初始化 |
| **S1** | 自研模型消融 | 同上，仅改变输入波段/时相/容量/机制 |
| **S3**（可选） | 自研模型原生输入 | 额外模态（S1 雷达等），不与 S0/S1 混表 |

命名规范：`model_id = scratch_<arch>`（如 `scratch_unet6`、`scratch_convnext6`）；`protocol_id = from_scratch`；`run_id` 由现有规则生成（`<model>-<task>-<protocol>-<action>-<seed>`）。

## 五、公平规则（与主协议一致，缺一不可）

1. **同头**：S 轨道所有模型（含自研）使用同一个共享头；自研模型若自带解码器，只能作为 S2"完整架构"轨道单列。
2. **同输入**：按任务协议波段与时相，禁止偷偷多喂模态。
3. **同预算**：同一 epoch 数、同一学习率预算（沿用 B1 的单一共享 lr 或同一对数网格搜索次数）、同 batch/梯度累积规则。
4. **同种子**：`17 / 42 / 73`，报告均值±标准差。
5. **同增强**：若为从零训练引入增强（翻转/裁剪/旋转），**必须同时应用到 B1 三家的重跑**，否则 B1 表作废。增强策略需固定并记录。
6. **同评价器**：一律使用根项目公共指标；测试集只在配置锁定后评价一次，**禁止用测试集调参**。
7. **成本随成绩报告**：参数量、可训练参数量、特征步长、单步显存、总训练时长。
8. **可追溯**：记录代码 commit、配置哈希、manifest 哈希、随机种子、环境版本。

## 六、设计空间

### 6.1 三个设计轴

| 轴 | 选项 | 针对的假设 |
|---|---|---|
| 光谱编码 | 早期融合（通道堆叠）/ 波段级 token / **波段注意力** / 波长编码 | 红外贡献、波段交互 |
| 空间编码 | 小 CNN（U-Net/ConvNeXt 式）/ 小 ViT / Swin | 小数据下的归纳偏置价值 |
| 时相融合 | masked mean / 轻量时相注意力 / 3D 卷积 / ConvLSTM | 时相信息的性价比（T5/T7） |

### 6.2 候选架构（按实现成本排序）

| 编号 | 架构 | 参数量级 | 预期成本（RTX 4090） | 主要检验 |
|---|---|---:|---|---|
| ① | 小 U-Net，六波段早期融合 | 1–5M | T1 数分钟/种子 | 从零训练的合理下限 |
| ② | ConvNeXt-tiny 式编码器 + 共享头 | ~28M | T1 约 15 分钟/种子 | 现代 CNN 归纳偏置 |
| ③ | U-TAE 式（CNN + 时相注意力） | 1–2M | T5 数十分钟/种子 | 轻量时相注意力性价比 |
| ④ | 波段注意力 + CNN（自研） | 2–5M | 同 ③ | **红外/波段贡献的显式量化** |
| ⑤ | 小 ViT / Swin-tiny | ~28M | 更慢 | 无预训练 ViT 是否可行 |

### 6.3 推荐递进路线

```text
① 小 U-Net（下限）
   → ④ 波段注意力（回答红外问题，并产出 RGB 消融）
   → ② 容量阶梯（编码器容量收益）
   → ③/⑤ 机制对照（时相/注意力机制是否值得）
```

理由：当前训练集很小（T1 252 景、T2 486 景）且基线无增强，从零训练的大模型几乎必然过拟合；先拿到干净的下限，再逐步增加设计复杂度，每一步都有对照。

## 七、数据与训练协议

| 任务 | 输入 | 训练集/评价集 | 时相 |
|---|---|---|---|
| T1 | S2 六波段（BLUE/GREEN/RED/NIR_NARROW/SWIR_1/SWIR_2） | train 252 / test 90 | 1 |
| T2 | HLS 六波段（BLUE/GREEN/RED/NIR_BROAD/SWIR_1/SWIR_2） | train 486 / official_validation 264 | 1 |
| T5 | HLS 六波段 × 3 时相 | train 3083 / official_validation 771 | 3 |
| T7（后续） | S2 六波段 × 4 时相，回归 | 官方划分 | 4 |

统一设置（与 B1 对齐）：

- 优化器 AdamW；学习率沿用 B1 的单一共享预算（或同一对数网格上相同次数的验证集搜索）
- epoch 数、batch/梯度累积规则与 B1 一致
- 训练裁剪/输入分辨率与 B1 一致（当前为 512 芯片 → 256 训练裁剪 → 全 512 评价）
- 增强：**默认沿用 B1 现有策略**；若引入新增强，需同时重跑 B1 三家（见 §5.5）

## 八、消融计划

| 消融 | 配置 | 目的 |
|---|---|---|
| 波段 | RGB / RGB+NIR / 官方六波段 / 十波段 | 量化红外与波段数的边际收益（主设计文档 §2.1 要求） |
| 时相 | T=1 / T=3（T5） | 时相信息的价值 |
| 容量 | 1M / 5M / 28M | 容量 vs 收益，避免"更大即更好"的误读 |
| 机制 | mean vs attention vs 3D conv | 时相融合方式的性价比 |
| 波段注意力 | 有无 + 权重可视化 | 模型是否真的利用了红外（可解释性证据） |

每项消融使用同一 seed 集合，报告均值±标准差与成本。

## 九、评价与报告

1. **同表规则**：S0/S1 自成表（任务 × 自研模型 × 消融），不得与 B0/B1/B2 混排；若要横向讨论，只能做定性比较并显式标注训练状态差异。
2. **报告内容**：主指标（各任务）、辅助指标、逐类 IoU、训练曲线、参数量/FLOPs/步长/显存/时长、失败案例。
3. **结论口径**：区分"预训练的价值"（S0 vs B1/B2）、"架构设计的价值"（S1 内部递进）、"输入信息的价值"（波段/时相消融）三类结论，禁止用 S0 的高分反推"预训练无用"而不检查协议。

## 十、实施步骤与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| **阶段 0** | 脚手架：`from_scratch` 协议（新增 `scratch` regime）、`workers/scratch/`、模型配置、smoke 脚本 | `rs-eval dispatch --action probe` 与 1 epoch 冒烟通过，run.json 合法 |
| **阶段 1** | ① 小 U-Net 在 T1 跑通 3 种子 | 进 Portal，形成 S0 首行；与 B1/B2 的差距量化 |
| **阶段 2** | 扩到 T2、T5（T5 依赖时序管线） | 三任务 S0 表齐 |
| **阶段 3** | ④ 波段注意力 + RGB 消融 | 红外增益曲线 + 注意力权重证据 |
| **阶段 4**（可选） | ②/③/⑤ 容量与机制对照；自监督预训练预研 | 选型建议 |

每个阶段结束提交报告：结果表、成本表、结论与下一步建议。

## 十一、风险与陷阱

1. **小数据过拟合**：T1/T2 训练集很小，从零训练需配合增强与正则化；不得用测试集挑选超参。
2. **增强口径**：给自研模型加增强而不重跑 B1 三家 → 表格不可比（本方案强制同步）。
3. **参数量混淆**：把"更大模型赢"当作"架构更好"；必须报告参数量与 FLOPs。
4. **隐藏的输入优势**：分辨率、波段、时相选择必须与协议一致，否则单列。
5. **预训练污染**：若后续做自监督预训练，必须记录预训练数据并检查与评测集重叠（PASTIS 与 AnySat 的重叠问题即为前车之鉴）。
6. **单种子结论**：任何"自研模型更好/更差"的判断都需要 3 种子均值±标准差。
7. **基础设施误用**：worker 必须走 `WorkerRequest` 契约与原子 `run.json`，不得绕过控制层直接写结果目录。

## 十三、与主设计文档的关系

- 本文复用主设计文档的**轨道分离**、**同表比较铁律**、**同预算搜索**、**3 种子**、**RGB 消融**与**成本报告**要求；
- 本文新增的只有 **S 轨道**与**自研编码器**，不触碰 7 任务的数据协议、评价指标与 Prithvi 复现口径；
- 若自研模型在 S0 上接近或超过 B1 的预训练模型，应优先检查协议一致性（输入分辨率、增强、评价口径），再考虑宣布结论。
