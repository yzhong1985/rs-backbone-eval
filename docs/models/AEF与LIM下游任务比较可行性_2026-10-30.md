# AEF 与 LIM 下游任务比较可行性

日期：2026-10-30  
状态：待评审的可行性说明；已核查论文、官方数据说明及部分本机数据元信息，尚未实现 AEF 接入或运行比较实验。  
核查代码基线：`85592ed`；项目配置及账本优先于本文的时点快照。  
范围：iSAID、ISPRS Potsdam、LoveDA 语义分割，OSCD 变化检测，以及 FAIR1M-2.0、DIOR、DIOR-R 目标检测。用户所述“Potsdom”按 Potsdam 理解。

## 1. 建议结论

这些数据集可以用于 LIM、MaRS、Galileo 等图像主干的下游比较，但不能预设 AEF 同时具备全部数据集的接入条件。建议保留高清图像主干评测，另设满足地理配准、时间覆盖要求的 AEF 比较组；可靠对齐以后，再评估 `LIM + AEF` 的互补收益。

当前最值得核查的是 OSCD 的时间与配准条件。Potsdam 有地理参考，但原始数据早于公开 AEF 年份；LoveDA 的原始影像为 2016 年；其余高分图像集的逐图定位和日期尚未形成可验证闭环。把 AEF 上采样或接一个复杂任务头不能解除这些限制。

“数据集适合比较”与“项目已实现”分开记录。截至本轮，项目已有 T9/iSAID 与 T10/FAIR1M 配置和相关实现；其余列出的任务需要分别审查并注册。本文没有创建模型、任务、下载配置或训练队列。

## 3. 数据集逐项判断

| 数据集 / 任务 | LIM 等图像主干路线 | AEF 当前判断 | 进入比较前需要的证据 |
| --- | --- | --- | --- |
| iSAID / 语义分割 | 复用统一 UPerNet；遵守现有 T9 协议 | 当前接入受阻 | 原图到地理网格的可信映射、采集日期；现有图像坐标不能当经纬度 |
| Potsdam / 语义分割 | RGB 轨可行；NIR、DSM 另开输入增强轨 | 可定位，但同期比较不满足 | 原始 GeoTIFF 配准校验；影像早于 2017，不能直接用后期 AEF 宣称同期分割 |
| LoveDA / 语义分割 | 适合城乡土地覆盖与域迁移 | 类别适合，但年份和定位受限 | 原图是 2016 年；PNG 裁块需逐块地理映射，仅知道城市不够 |
| OSCD / 变化检测 | 两时相共享编码器，统一变化检测头 | 空间尺度较匹配，时间需逐对审计 | 原始双时相日期、像素配准、两期 AEF 支持窗口及对应标签区间 |
| FAIR1M-2.0 / 旋转检测 | 统一 FPN + Rotated Faster R-CNN | 当前不纳入 AEF 检测主表 | 逐图坐标、日期及配准；10 m 特征对小目标的空间信息限制需披露 |
| DIOR / 水平检测 | 统一 FPN + Faster R-CNN | 大型地物可研究，尚不具备接入证据 | 来源定位、逐图 GSD/日期与地理映射；不能只凭图像名称查询 AEF |
| DIOR-R / 旋转检测 | 统一 FPN + Rotated Faster R-CNN | 与 DIOR 同样受定位和时间约束 | 复用同源图像审计；独立锁定 OBB 标注、转换和评价器 |

Potsdam 官方报告说明数据为 5 cm、原始瓦片具有地理参考，并在 2015 年已发布，因此早于公共 AEF 年份；本文不臆定一个未经核实的具体采集日。[ISPRS 官方报告](https://isprs.org/society/si/SI-2015/ISPRS-SI2015-Gerke_report_WGIII4_2015.pdf)

LoveDA 官方数据表描述 2016 年 7 月、0.3 m、1024×1024 PNG 影像；公开的城市范围不能替代逐像素配准。[官方数据表](https://zenodo.org/records/5706578/files/Datasheet.pdf)、[官方项目](https://github.com/Junjue-Wang/LoveDA)

OSCD 是 2015–2018 年的 24 对 Sentinel-2 影像，14 对训练、10 对测试，标签针对城市变化；DIOR-R 与 DIOR 使用同一组图像，分别对应 OBB 与 HBB 标注。[OSCD 官方介绍](https://rcdaudt.github.io/oscd/)、[DIOR/DIOR-R 作者说明](https://gcheng-nwpu.github.io/)

除已直接抽查的本机文件外，“定位受限”表示尚无验收通过的映射，不表示已证明发布方永远无法提供原图坐标。需要向数据负责人取得原始地理文件或可验证的映射表后重新判断；本次未对外发送申请。

## 4. 两类容易混淆的限制

### 4.1 地面分辨率与编码器步长

AEF 的 10 m 指地面网格；LIM 的 /4 或 Galileo 的 patch 8 指相对于输入图像的像素步长，不能直接比较数值大小。必须同时报告输入 GSD、原生特征步长及对应地面尺度。

例如，1024 像素的 5 cm Potsdam 裁块只覆盖 51.2 m，每边约 5 个 AEF 网格；同样大小的 0.3 m LoveDA 裁块约对应每边 31 个 AEF 网格。这些只是尺度计算，不是模型效果估计。上采样后的密集输出仍可评测，但不能声称获得了原生高分细节。

把高分标签降到 10 m 可以形成新的粗尺度实验，应另命名并锁定面积占比、混合像元、边界和 ignore 规则；不能把粗尺度分数当作原数据集标准分数。小车等类别在降尺度后可能消失，需报告有效 GT 支持量。

### 4.2 年度表征与双时相变化

原版 OSCD 标签描述两个具体日期之间的变化。原论文示例包括 Rio 的 2016-04-24 → 2017-10-11，以及 Montpellier 的 2015-08-12 → 2017-10-30，前期超出公共 AEF 覆盖。[OSCD 原论文](https://rcdaudt.github.io/files/2018igarss-change-detection.pdf)

不能把 2017/2018 年特征代入后仍称原版 OSCD 的同期比较。即使两张影像都落在可用年份内，也需注意：

- 同一年度的两张影像会查询到同一个年度表征，无法由该产品构成两次独立状态观测。
- 跨年的年度汇总仍可能包含原始标签区间之外的变化，不能仅凭年份不同认定时间对齐。
- 公共特征与 OSCD 精细配准后的像素网格需验收；地理坐标相同不等于已复现其配准变换。
- 若筛出子集，提前固定资格条件和样本清单，报告为 OSCD 时间兼容子集；所有方法在同一子集重跑，不能与原版完整测试成绩直接排名。

如果没有合格子集或服务支持，改用 2017 年之后、具备地理配准和独立时间标签的新变化检测数据，单独注册任务；不能沿用 OSCD 名称掩盖任务变化。

## 5. 与 LIM 比较的实验定义

### 5.1 高清图像主干比较

保留 iSAID、Potsdam、LoveDA 的高分分割任务，以及 FAIR1M、DIOR、DIOR-R 检测任务。各图像主干使用同一任务定义、输入信息规则、统一任务头、样本和预算；冻结与微调分轨。RGB、RGB+NIR、RGB+DSM 等输入不同的实验单列。LIM 在 OSCD 上先使用两期 RGB 与共享权重，额外波段适配属于独立方案。

这组实验可以先进行，不因 AEF 尚未通过地理/时间准入而等待。新增数据集的具体划分、头和资源预算仍需实施评审，不能把所有候选一次性扩成三种子长队列。

### 5.2 AEF 与 LIM 的冻结表征比较

仅在地理、时间、标签匹配的数据上进行：AEF 读取对应区域的 64 维特征，LIM 编码对应区域 RGB；训练同一家族的轻量预测器，预声明适配层和参数量，统一标签网格与样本预算。首轮可用线性头，并以相同搜索机会评估小型非线性头。

AEF 使用多源、多时相信息，LIM 使用指定 RGB，故结果回答“各自可用表征在这个应用上的效果与成本”，不支持把差值全部归因于 backbone 架构。AEF 也不具备本次可用的编码器微调路径。

少标注实验拟使用 1%/5%/10%/100% 训练监督，按区域或对象组采样，固定总量及各类支持量；验证/测试始终保留，不能把邻接像素随机拆分当独立泛化。种子预声明为 17/42/73，工程 smoke 与单种子开发结果单列。

### 5.3 互补实验：LIM + AEF

地理和时间验收通过后比较三组：`LIM-only`、`AEF-only`、`LIM+AEF`。融合可以在任务头前引入坐标对齐的 AEF 上下文，公开融合模块、参数量与训练预算。为区分新增参数的影响，增加容量相近的 LIM-only 头对照。

没有逐块坐标时不能给整座城市或整张图随便分配同一个向量，声称完成像素级融合；这样的实验至多属于另行定义的场景先验对照。是否有融合增益以真实结果判断。

## 6. 标签来源、训练覆盖和时间信息审计

按三条独立轴记录：输入域 home/away、预训练是否见过评测图/区域、是否使用同源标签。AEF 全球表征可能覆盖测试区域本身，这与使用测试标签不同，应分别披露；空间留出也不能自动证明该位置未参与其预训练。

官方产品说明公开特征由 AEF v2.1 生成，而论文主要报告 v2.0；生产版加入美国 CDL 作物图目标，已有 NLCD 监督。因此，若后续扩展到本项目 CDL 来源的 T5 或美国土地覆盖任务，须追查年份、区域和类别来源，不能把它称作无标签泄漏的独立证据。也不能以此推断本次列出的全部高分数据集已被污染。[产品与版本说明](https://developers.google.cn/earth-engine/datasets/catalog/GOOGLE_SATELLITE_EMBEDDING_V1_ANNUAL?hl=en)

使用晚于标注日期的年度特征，可能获得未来状态信息。同期制图、历史标签迁移、事后事件分析和实时预测必须分开定义；简单将 AEF 年份设为“最近一年”不能替代时间协议。

LIM 的 Million-AID 与 iSAID/FAIR1M 等是否同源，仍按已有文档记为“未排除”。同样的审计口径用于 MaRS、Galileo 和 AEF，不能仅因主场/客场标签而免查。

## 7. 数据取得、成本与项目接入

官方入口：`gs://alphaearth_foundations/satellite_embedding/v1/annual/`。先用空间索引按 AOI/年份筛选，再读取目标 COG 窗口；不下载全球全集。payload 放仓库外，按部署 RuntimePaths 管理，来源与下载方式正式实施时登记 catalog。

GCS 原始值为有符号 int8，NoData 为 -128；按官方映射先屏蔽无效像元，再计算 `sign(v) * (v / 127.5) ** 2`，不要直接将整数当连续特征或只做线性缩放。重投影、缩放与聚合方式固定；不要将原始量化整数直接平均。[官方读取及反量化说明](https://developers.google.com/earth-engine/guides/aef_on_gcs_readme)

每份派生特征记录产品/模型版本、年份及支持窗口、源对象 URI 与 hash/版本标识、CRS/变换、读取分辨率、NoData、配准误差、重采样及派生文件 hash。缓存键包含上述身份及 tile 偏移，不能跨年份或不同网格复用。

单独报告本地下游训练、数据传输、LIM 特征提取、AEF 读取/预处理、缓存及端到端推理成本。AEF 的表征已由服务方预计算，不能因本地只训练头就声称其全球编码器计算成本为零；缺少上游成本时明确不可得。

AEF 接入应定义为预计算特征消费路径，控制层不加载 torch，worker 保持依赖边界。正式 task/model/protocol、预算、结果分组和 Portal 需一起验收；本文不预占新的 task ID，不把 AEF 外部表征结果自动并入现有 D1。

## 8. 分阶段交付与 review 决策

| 阶段 | 工作 | 通过条件 |
| --- | --- | --- |
| P0 数据资格审计 | 每图/每对日期、坐标、像素配准、标签来源与 AEF 覆盖表 | 未知/缺失项显式标记，不能用声明值冒充实测 |
| P1 单区域读取 | 小 AOI 的 AEF 读取、反量化、有效覆盖和叠图校验 | 无效像元与边缘正确，留存来源与配准误差报告 |
| P2 最小比较 | 同一数据清单上的 LIM-only、AEF-only 冻结头 | 预声明监督量、头和时间定义；完整预算单种子，smoke 不进主表 |
| P3 正式比较 | 锁定协议后完成三种子及少标注曲线 | 分割报每类 IoU/边界或尺寸分层，变化检测报变化类 F1/IoU/PR；不只报 OA |
| P4 可选融合 | 在可信配准上加入 LIM+AEF 和容量对照 | 解释增益、失败及额外成本，不改变已有任务身份 |

检测实验另报 HBB/OBB 身份、每类 AP、尺寸分层召回和整图合并成本；DIOR 与 DIOR-R 的同源影像不能被当成两份完全独立的泛化证据。FAIR1M 遵守项目当前实施后的协议与审计规则，旧设计文档只作历史背景。

建议 review 决定：

1. 高清分割/检测任务继续按图像主干矩阵推进，AEF 只在数据资格通过的单独比较组接入。
2. 首先核查 OSCD，若时间不兼容则不强行替换日期；选择新的地理配准变化数据或单独命名的兼容子集。
3. Potsdam/LoveDA 若使用后期 AEF，只能另立明确的跨时间辅助实验，不能冒称同期标准 benchmark。
4. 首轮仅做一个合格数据集的最小冻结比较，实测成本后决定三种子、少标注与融合的展开规模。
