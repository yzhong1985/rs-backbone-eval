## P1：实验条件混选

### 问题

`best` 直接在所有 cell 里取 `max(mean)`，而 cell 集合包含：

- `init=random`（随机初始化对照面板）；
- `label_fraction < 1.0`（少标注实验）；
- 不同 manifest / 不同输入尺寸的变体。

这些在 AGENTS 里明确是**独立面板**，不能当任务主成绩。原实现既没过滤，也没在卡片上显示条件。

### 修复

1. 新增 `_is_default_condition(cell)`：`init` 必须为 `pretrained`、`label_fraction` 必须为 `1.0`；
2. `_pick_best(cells)` 只在默认条件里选；若无候选，返回 `None`，卡片显示"暂无默认条件下的正式结果"；
3. 卡片在分数下方显示条件：`lr=… · pretrained · 标注 1.0`；
4. 任务页新增 `non_default_cells` 自动警告，列出前三个非默认单元及其条件。

### 验证

- 单测 `test_best_cell_ignores_random_init_and_partial_labels`：默认单元 0.70、随机初始化 0.95、10% 标注 0.99 → 选中默认单元；
- 线上数据当前 `non_default_cells = 0`，说明现有账本还没有这类单元，属于**提前拦截**。

## P2a：切页串内容

### 原因

`renderTaskPage` 与 `renderComparePage` 都是 `await fetch` 后直接写 DOM，没有校验"这是不是当前页面"。 T3 的响应晚于 T4 到达时，就会覆盖 T4 的内容。

### 修复

引入单调递增的 `viewToken`：路由切换时自增，请求发出时捕获当前值，`await` 返回后若 `token !== viewToken` 直接 `return` 丢弃结果。运行详情页与对比页共用同一机制。

### 验证

代码层面已加守卫；本地无法自动化浏览器竞态，**需要评审侧再复现一次**（T4 → 快速切 T3 → 等 2 秒，应保持 T4）。

## P2b：刷新无效

### 原因

`#reload` 只调 `load()`（首页矩阵/运行表/下载），任务卡与任务页不重新请求；对比页还把结果缓存在 `taskState.compare` 里，永不失效。

### 修复

- `load()` 末尾改为 `await loadTaskCards(); route();`——刷新会重取任务卡，并按当前 hash 重渲染任务页/对比页；
- 删除 `taskState.compare` 的读缓存（每次进对比页都重新请求）；
- 初始化只调 `load()`，避免重复请求。

## P2c：排除标记遗漏

### 原因

运行列表只判断了审计排除（`excluded_run_ids`），没有判断 `superseded` 与"非正式预算"。于是 1 epoch 的 smoke 记录仍显示为普通 `completed`。

### 修复

后端给每条运行加 `flags`：

| flag | 判定 |
|---|---|
| `excluded` | 在 `excluded_run_ids`（审计 stale / 无 commit） |
| `superseded` | `is_superseded(record)`（tags.superseded） |
| `reduced` | `is_reduced_run(record)`（未达官方 epoch 预算） |

前端把每个 flag 渲染成徽标（"审计排除 / 已被取代 / 非正式预算"），整行置灰。

### 验证

线上 T8：3 条 smoke 记录显示 `reduced`；单测 `test_runs_carry_flags_for_superseded_and_reduced` 覆盖三种 flag。

## P2d：指标方向错误

### 原因

`best` 用 `max(mean)`。T7 是生物量回归，主指标 RMSE **越小越好**，会选出最差的模型。

### 修复

改为按 cell 自带的 `direction`：`maximize` 取最大、`minimize` 取最小。任务卡与跨任务对比页在最小化指标后加 `↓` 标记。

### 验证

单测 `test_best_cell_honours_the_metric_direction`：RMSE 27.5 与 40.0 两条 → 选 27.5。

---

## P2e：配置缺失时整页失败

### 原因

任务的 manifest 有成绩但 `configs/tasks` 里没有该任务时，`spec` 为 `null`。前端虽然有 `detail.spec || {}`，但随后仍访问 `spec.bands.length`——`{}` 是 truthy，于是 `undefined.length` 抛错，整页白屏。

### 修复

- 前端所有 spec 字段改为可选链 + 默认值：`(spec.bands || []).length`、`spec.time_steps ?? "—"` 等；
- 后端明确：任务不在 configs 但有成绩时返回 200、`spec: null`、`notes: null`（不 404）。

### 验证

单测 `test_task_without_config_still_returns_cells`：账本里造一个 `T99` 运行，`/api/tasks/T99` 返回 200 且 `spec is None`、`cells` 非空。
