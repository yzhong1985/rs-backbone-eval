## 0. 路线口径

评审引用的记录属实：`docs/reports/阶段进展更新_2026-10-26.md` 第 60 条写明"不以超过 LIM 作为验收条件"。

**需求澄清后**：上级要看的是"新主干在 LIM 的主场任务（iSAID，纯 RGB）上各自能做到什么水平"，而不是"新主干能否赢 LIM"。这两件事不同：前者不违反 10-26 决定，后者才是被排除的验收口径。v1 的错误是**没有把口径写清楚**，把"能力谱系"和"选型对比"混在一起写了。

**处理**：v2 §0 改为明确三件事——结论表述为"同协议下的能力谱系"、结果标 home/away、不出现"LIM 优于/劣于基座"的总结句；同时保留 A（只出 LIM 分数）作为 B 的前置步骤，按主干逐个接入、逐格出结果，避免一次性承诺全部算力。

## 1. 算力

**v1 的错**：3 万–8 万块 × 50 epoch = 150 万–400 万样本；要在 10–15 h 内完成需 28–110 张/秒，而 524 M 的 MiT-Huge 在 1024² 下（第一级 65,536 token、关 AMP、开梯度检查点、6 卡每卡 batch 2）实际约 1 张/秒量级 → 每种子 17–46 天。**v1 的"三种子 1.5 天"错了一到两个数量级，已撤回。**

**处理**：

- 新增 **P0-b 吞吐 smoke** 作为 gate：512² 与 1024² 各 200 iter，测 img/s、峰值显存、验证耗时、pos_embed 插值后是否正常收敛；
- 预算改为**按迭代数**（建议 20k–30k 步，有效 batch 8）+ 每 epoch 抽样固定块数；
- v2 **不再给任何小时数**，等实测。

## 2. 权重核查

评审逐条复算，全部成立。v1 的错误与修正：

| v1 | 复核结果 |
|---|---|
| 552 M | 552.3 M 总量 = **编码器 524.4 M** + 预训练 decoder 27.9 M |
| "MAE 式预训练" | **MixMIM**（`args.model='mixmim_base'`，`mask_ratio=0.5`） |
| 未提预训练数据 | **Million-AID**，`input_size=224` |
| 未提训练进度 | **`epoch=150` 而 `args.epochs=300`** → 半程快照 |
| 未提位置编码 | `absolute_pos_embed (1, 3136, 256)` = 56×56，1024 输入需插值到 256×256 |
| 建议移植 `mit_mona_plus.py` | **权重里没有任何 mona/adapter 键** → 应移植不带 Mona 的 `mit.py`；Mona 要作为单独变量声明 |

另外补了一条：同事 iSAID 配置加载的是 `mitmonaV3_H_stage4_600W/checkpoint499.pth`，与本份 `epoch=150` **不是同一个权重**，因此原 R7（结果不可合并）比 v1 写的更严重。

## 3. 统一 UPerNet

- 同事 `models/spnet.py:80` 的 `UperNetAlignHead` 实为 **PPM + FPN + AlignedModule（SFNet 式流对齐）**，另带 aux 分支（配置 `aux_weight: 0.2`），**不是标准 UPerNet**；v1 把它描述成"4 级 MLP + 1×1 fusion"是错的。
- 我们仓库里**已经有标准 UPerNet**：terratorch 的 `UPerNetDecoder`，Prithvi B0 在用（`workers/prithvi/src/prithvi_worker/t1_baseline.py`）。因此 v1"不需要从零写"的论据不成立，但"有现成标准实现"这个结论仍然成立——只是来源不同。
- **BN 问题**：同事用 SyncBN + 6 卡 batch 12，我们有效 batch=2。v2 要求二选一并写进协议：GroupNorm，或冻结 BN 统计。
- 更正 v1 的另一处错误：现有轨道**并非都用 `lite_spatial_head`**——T3/T5 用 `temporal_segmentation_head`，AnySat 侧是 `+spectral_adapter`，T8 是 `+band_adapter`，B0 用 `upernet_decoder`。

## 4. 控制层

评审指出的机制问题成立：轨道由 `protocol_id` 决定（`matrix.py:19` `PROTOCOL_TRACKS`），`head_id` 只是单元里的 variant，而 `_rank()`（`matrix.py:252`）按验证分数选 headline → **UPerNet run 若复用 `full_finetune`，会悄悄顶掉 B1 主分数**。

v2 §3 给了逐文件清单：`PROTOCOL_TRACKS` / `TRACK_NAMES` / `TRACK_ORDER` / `OFFICIAL_EPOCHS`、`scorecard()` 里写死的 B1/B2 逻辑（约 `matrix.py:681`）、`report.py`、Portal、`configs/{tasks,models}`、各 worker `runner.py` 的允许列表、`test_registry.py`（精确集合）、`test_review_fixes.py` / `test_scorecard.py` / `test_portal.py`。
