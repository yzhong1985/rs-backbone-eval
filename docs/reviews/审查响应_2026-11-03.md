## 1. head_only 回放（`replay.check_loaded_keys`）

`_load_state` 把哈希校验过的预训练主干载入 `model.encoder`，然后返回头权重；之后
`load_state_dict(strict=False)` 必然报主干键缺失。新增 `check_loaded_keys(missing,
unexpected, kind)`：

- `head_only`：只允许 `detector.backbone.` 前缀缺失（与 `prune.BACKBONE_PREFIXES` 一致）；
- 头键缺失、任何多余键仍报错；形状不符由 `load_state_dict` 自身抛错；
- `latest` / `best`：任何缺失都报错。

测试 `tests/test_replay_integration.py::test_head_only_replays_through_load_for_eval`
走真实 `load_for_eval` + `LimDetector`：主干来自 `LIM_CHECKPOINT`、头来自 `head_only.pt`；
删掉一个头键或加一个多余键都必须失败。

## 3. 原协议身份（`visualization.identity_drift`，`visualize_run.py`）

两个缺口都已补：

1. **数据**：在加载模型前计算实际 manifest 的 sha256，与 `run.json.dataset.manifest_sha256`
   比较；产物同时写 `manifest_sha256`（实际）与 `manifest_sha256_recorded`（记录）。
2. **训练身份**：从 run 自己的 `latest.pt`（或由它导出的 `head_only.pt`）以 mmap 读出
   `TrainingCheckpoint.identity`，逐项比对 task / model / protocol / seed / manifest /
   pretrained_checkpoint / git_commit / torch_version / device_type / configs。
   - 缺 identity 或缺任一字段 → 漂移（fail closed）；
   - 指纹两端的环境分别取自训练 identity 与当前进程，不再用当前值填历史侧；
   - 训练没记录的 cuda / cudnn / numpy / GPU 型号写入 `env_unverified`，不参与判定。

`replay_mode` 新增 `drift` 参数，有任何漂移即为 `reevaluated`，原因写入 manifest。

测试：root 环境 `test_identity_drift_*`、`test_drift_makes_the_replay_a_reevaluation`；
LIM 环境用审查的合成探针改写为回归：身份全部一致 → `original_protocol`（正对照）；
数据哈希被改 → `--mode original` 退出 3，`reevaluate` 产物同时记录两份哈希；
checkpoint 记录 torch 2.4.0 → 退出 3；identity 缺失 → 退出 3。

## 5. GPU 与互斥（`visualize_run.py`）

- **全局锁**：`runs_root/../.visualize_run.lock`（`flock`，非阻塞），持有到进程退出；
  第二个生成器退出码 4。输出目录存在性检查移到锁内，消除两个进程都通过检查后互相覆盖。
- **GPU 空闲**：与 `rerun_baselines.sh` 同一阈值（显存 ≤ 2000 MiB）；忙时默认拒绝
  （退出码 5），`--wait` 每 300 s 轮询排队，`--device cpu` 不受限。
- **顺序**：参数校验 → 锁 → 输出检查 → 数据与身份 → GPU 检查 → 构建模型。被拒的请求
  不会分配显存。测试 `test_busy_gpu_is_refused_before_the_model_is_built` 会在模型被构建时
  直接失败。
