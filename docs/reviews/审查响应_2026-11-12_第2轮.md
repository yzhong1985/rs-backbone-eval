## P1-1 T8 OE128 迁移会报错（T11D/T11P 投影器共存）

**问题**：`find_projector` 要求 `(target, seed)` 目录下只有一个 `.pt`。T11P 加入后
同一目录会有 T11D 和 T11P 两份投影器，T8 OE128 迁移直接失败。

**修复**（`workers/clay/src/clay_worker/transfer.py`）：

- `TRANSFER_PROTOCOLS` 从 `(target, dims)` 改为 `(target, dims, source_task)`，
  T8 的 A64/OE128 明确声明 `source_task="T11D"`；
- `find_projector(target, seed, source_task=..., runs_root=...)` 按来源任务筛选，
  不再按文件数量判断；
- 旧投影器 payload 没有 `task_id` 时，读取 `source_run_id` 指向的 `run.json`
  的 `task_id`，因此不需要改写已缓存的投影器；仍无法判定或命中多份时给出可读
  的失败信息；
- run tags 增加 `transfer_projector_source_task`，便于审计。

**测试**：新增 `test_t8_projector_selection_is_pinned_to_its_source_task`：同一
`oe128/seed17` 目录放 T11D/T11P 两份投影器，断言选中 T11D；worker CPU 测试通过。

## P1-3 缓存可能跨实验条件误用

**问题**：Prithvi 的 token/projector 指纹只有 checkpoint、manifest、task、bands、
frames、grid；随机初始化（`RS_EVAL_INIT=random`）会复用预训练特征，训练集归一化
统计量变化也不会失效。

**修复**：

- `_feature_fingerprint` 与 `_fingerprint` 增加 `init`（`pretrained`/`random`）和
  `normalization`（训练集逐波段 mean/std 的 sha256 前 16 位）；
- `train_t11p` 统一计算这两个值，写进 tags，并传给特征缓存和投影器指纹；
- Clay 的 token 缓存只用固定的传感器 metadata 归一化，因此只加随机初始化隔离：
  `cache_fingerprint(..., init=...)` 仅在 `init != "pretrained"` 时把 `init` 写进
  payload，**预训练指纹保持不变**，已部署缓存和 T11D 投影器不受影响；
- 随机初始化因此在 Clay 和 Prithvi 上都得到独立 namespace，不会读到预训练特征。

**成本说明**：Prithvi 的旧 T11P 特征缓存/投影器指纹没有 `init`/`normalization`
字段，修复后不会被复用，需要重算（约 10 分钟/一次）。已完成的 T11P 三 seed
指标不受影响；后续重跑 `o128` 前需要先重跑对应 seed 的 distill。

**测试**：`test_cache_fingerprints_separate_init_and_normalisation`、
`test_cache_fingerprint_separates_random_init_without_moving_pretrained`。

## P2-1 冷、热缓存影响可复现性

**问题**：`_train_probe` 用 `shuffle=True` 的 DataLoader 提取训练特征；冷缓存时
特征顺序是随机的，热缓存时是 manifest 顺序，同一 seed 的训练顺序因此不同。

**修复**：特征提取统一使用 `shuffle=False` 的 loader；头训练本身已经在
`_head_train` 里用固定 seed 的 `randperm` 重新排序，所以不需要 DataLoader
再 shuffle。

**测试**：`test_feature_extraction_cold_and_warm_cache_keep_manifest_order`：
三样本冷提取写缓存、再热读取，断言两次 feature 张量和 group 顺序完全一致。
