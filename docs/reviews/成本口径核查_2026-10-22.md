# 成本口径核查：Clay T5（2026-10-22）

针对上级 2026-10-22 的核查意见：报告把 Clay 的"约 4.6 分钟、1.4GB"标为 B1 全量微调成本，而 3.1 亿参数模型的 AdamW 全量微调不可能只有 1.4GB。按建议核对四项证据。

## 结论

1. **Clay T5 是 B2（冻结骨干、只训头），不是 B1。** 可训练参数 2,671,661 / 总 314,114,605。
2. **1.4GB 不是 Clay T5 的数字。** 三条 Clay T5 运行的 `peak_gpu_memory_mb` 都是 **None（未记录）**；1.4GB、6.4 分钟来自 T1 的 head-only 旧运行（`final-clay-lr3e-4-*`，1396MB / 6.4 分钟），它们已在 10-21 被打标 superseded。
3. **但审计的底层判断成立**：报告 D3 一列把 **B2 的可训练参数**和 **B1 的耗时/显存**放在一起，确实是从不同轨道取数。已修正，见 §5。

## 四项证据（Clay T5，`clay_v1_5-T5-frozen_probe-*-v3`）

### 1. optimizer 里有哪些参数

- `workers/clay/src/clay_worker/t5.py:205`：`AdamW([p for p in model.parameters() if p.requires_grad], ...)`
- 构造时 `freeze_backbone=True` → 编码器全部 `requires_grad=False`（`t5.py:102-104`），`train()` 里编码器强制 `eval()`（`t5.py:106-110`）
- 运行记录：`trainable_parameters = 2,671,661`，`tags.head_parameters = 2671661`，两者相等 → 优化器里只有时序头

**判定：优化器不含主干参数。** 2.67M 而不是 300M。

### 2. 主干参数是否变化

结构上不可能变化：

- 所有编码器参数 `requires_grad=False`，不在优化器里；
- 特征提取在 `torch.inference_mode()` 下执行（`t5.py:374`），不建图；
- 冻结路径只保存 `best_checkpoint.pt`（时序头）。

**限制（如实说明）**：该路径**不保存完整模型**，因此无法在事后做"训练前后主干权重逐位对比"。证据是代码门控 + 优化器内容 + 推理模式，而不是权重 diff。若需要权重级证据，需在冻结路径额外保存一次主干哈希（建议后续加）。

### 3. 计时包含什么

- `_train_from_cache()` 在**特征提取之后**才 `started = time.time()`（`t5.py:425`），训练循环结束即 `wall = time.time() - started`，**评测尚未开始**；
- 运行记录：`wall_time_seconds = 2405s ≈ 40.1 min`，`phases = {}`（空），`cache_bytes = 17,080,713,472`。

**判定：40.1 分钟只是"头训练"，不含 17GB 特征提取，也不含评测。** 不能当作端到端成本。

### 4. 峰值显存是否覆盖完整训练步

- 三条 Clay T5 运行的 `peak_gpu_memory_mb` 均为 **None**；
- 冻结路径当时**没有调用** `reset_peak_memory_stats` / `max_memory_allocated`。

**判定：Clay T5 没有可用的显存峰值记录。** 报告里任何 1.4GB 都不能归到这条运行上。

## 5. 报告侧的缺陷与修正

**缺陷**：`scorecard()` 的 D3 用 **B1 运行**取 `wall/peak`，却用 **B2 运行**取 `trainable/total`，同一列混了两个轨道。Clay 的 B1 是 312.9M 可训练参数 + 9.9GB 峰值，配上 B2 的 2.67M，读起来就像"300M 模型只占 1.4GB"。

**修正**（提交记录见仓库）：

- D3 改为全部取自 B1：`B1 可训练 / 总`；B2 的可训练参数单列在括号里；
- Clay 现在显示：**37.5 分钟，9904 MB，B1 可训练 312,887,554 / 总 312,887,554（B2 可训练 2,671,661）**；
- 新增测试锁住"D3 参数必须来自 B1"。

**同时补齐 Clay T5 的成本记录**：冻结路径现在会记录
`peak_gpu_memory_mb`（训练+评测期间）与 `phases = {cache, train, eval}`，后续运行可直接读出提取/训练/评测三段耗时。已完成的旧运行不重跑，报告中其成本仅标注为"头训练耗时（不含提取）"。

## 6. 给后续的结论

- **B1 与 B2 的成本不能并排比较**：Clay B1（T1，312.9M 可训练）是 37.5 分钟 / 9.9GB；Clay B2（T5，2.67M 可训练）是 40 分钟 / 未记录。前者是"全量微调"，后者是"读缓存训头"。
- 报告的 2.4 已写明成本口径差异；本轮把 D3 的参数来源也统一了。
- 若要给 T5 一个**端到端**成本，需要新的运行（本次已加计时点），或在旧日志上重建提取时间；不为此重跑训练。
