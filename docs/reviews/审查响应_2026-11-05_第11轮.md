## 3. 运行验收（5090 实测）

- `rs-eval doctor`：data / weights / runs / cache / config 五个路径全部 `yes`；
- 样本解码：`1024×1024×3 uint8`，冷读约 202 ms；
- DataLoader（4 worker）：200 tile / 13.4 s = **15.0 tile/s**；
- 100 步诊断 run（完整 worker 入口，CUDA 前向、反向、optimizer step、NMS / RoIAlign）：
  - **0.401 s/step**、**4.99 tile/s**；
  - eval 16 tile / 3.8 s ≈ 0.2375 s/tile；
  - `status=completed`，tags 含 `device=cuda`、`host=nvidia-geforce-rtx-5090`、
    `hostname=YZ-WORKPC`、`torch=2.9.1+cu128`；
  - 诊断 run 已移入 `~/rs-eval/runs_quarantine/`，不计入正式结果。

由此推算：25000 step × 0.401 s ≈ 2.79 h，加 test 评估约 0.16 h，**单 seed ≈ 2.95 h**。
两个 seed ≈ 5.9 h；seed 42 的最晚启动时间设为 **04:00**，否则留到下一晚。

## 4. 验收口径修正

`audit_runs.py` 只检查 `required_fixes` 的 git 祖先关系，不检查 host、manifest hash、
步数或预算；预算另由 `matrix.formal_candidates` 检查。因此回传后做两层验收：

1. `audit_runs.py`：修复祖先；
2. 逐 run 读 `run.json`：`host` / `hostname`、manifest sha256、`optimizer_steps`、
   `preprocessing_id`、micro/accum、预声明种子集合。

文档 §6.3 已按此改写，并增加了"目标 run_id 不存在"的预检。
