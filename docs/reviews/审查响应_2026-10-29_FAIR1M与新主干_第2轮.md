## 2. G0：取消逐 worker 编译 MMCV 的默认安排

已复查 Rotated Faster R-CNN 的配置及 RoI 训练源码：proposal 和匹配使用水平框，RoI 提取为普通 RoIAlign，回归目标仍为 OBB。因此正式实现优先使用共享 torch 检测逻辑与 torchvision 的水平框算子，旋转 NMS / 多边形评测采用无梯度 CPU 几何；MMRotate/MMCV 仅留在独立参考层。[配置](https://github.com/open-mmlab/mmrotate/blob/main/configs/rotated_faster_rcnn/rotated_faster_rcnn_r50_fpn_1x_dota_le90.py)、[RoI 训练源码](https://github.com/open-mmlab/mmrotate/blob/main/mmrotate/models/roi_heads/rotate_standard_roi_head.py)

这样减少的是自编译扩展及旧 MMRotate 集成的风险，以下验证仍需保留：

- 配套 torch/torchvision wheel、CUDA 算子加载；本轮仅检查元数据，没有执行 GPU 算子。Prithvi/Clay 找到 torchvision 0.29.1/0.19.0，AnySat/OlmoEarth/LIM 独立环境未发现对应 dist-info。
- RoIAlign 的 `aligned`、采样和坐标语义、FPN 层级选择、旋转框编码及 loss/梯度对齐；torchvision 默认配置不应直接视作参考实现配置。
- CPU 旋转几何的退化框、角度、阈值边界、同分排序及原图 GT 对齐；Shapely 是 GEOS 的接口，不是完全无二进制依赖。
- 密集大图合并的耗时/内存实测。CPU 后处理可避开反传依赖，但不能未经测量就认为速度必然可接受。

G1 公开 checkpoint 与标准训练校准不取消，简化安装不等于已验证检测器正确。

## 3. 预算：基于已提交修复验收并补齐权威预算

更正此前“修改未提交”的时点描述：`94ac560 fix(budget)` 已合入 main，`9b9826c` 已记录 quarantine 与 v2 重跑。第一轮修复完成了 worker/控制层共享判断，但仅按 run 自报的 `total_steps_budget` 比较，仍存在 400/400 诊断被当作正式结果的问题。

本轮以 `9b9826c` 为基线，在独立 worktree 复现并修复，代码提交 **`11bafd4`**：

- `OFFICIAL_STEPS = {"T9": 25000}` 是 T9 正式预算权威，worker 自报 limit 只作审计，不决定准入。保留共享函数签名，LIM 与 Clay 两个 T9 worker 无需改动。
- T9 只接受实际 optimizer steps 的证据，不再回退到约 8 个 epoch。优先使用结构化 `training.optimizer_steps`；旧 worker 只有 `tags.train_steps` 时兼容读取。
- epoch 制完成量为零/缺失、未注册预算的任务默认不准入。显式保留 T1S/T8 的既有 50 epoch 预算，避免把已有域外任务误当未知预算。
- 保留 SMOKE/REDUCED-BUDGET 诊断标记排除；没有改写已有 run.json，也不改变 quarantine 记录。

| 合成输入 | 修复前 | `11bafd4` 验收结果 |
| --- | --- | --- |
| T9，400/400 自报，无缩减 notes | 可能准入 | 排除 |
| T9，25,000 实际 steps | 达到自报预算则准入 | 达到权威 25k，准入；自报 limit 不决定结果 |
| T1，0 epoch，无 steps | 可能准入 | 排除 |
| T9，50 epoch，无有效 steps | 可回退 epoch 准入 | 排除 |
| T10，50 epoch 或自报 25k steps | 可能准入 | 未注册预算，排除 |
| 同 seed、同 variant：较新 400 步 vs 较旧 25k | 400 步可能顶替正式结果 | canonical/matrix/Portal 均保留 25k |

这是函数、真实 RunRecord、同 cell 选择及 Portal/report 路径的回归，不依赖旧 losscheck notes 的保护。正式 gate 不需要先把 step limit 加进 variant_key 才能阻断短跑；今后如开放不同正式预算的独立研究轨道，需要另行注册协议和预算身份。

## 5. 顺序：新主干先走 iSAID B2U

已调整为：来源审计和输入验证 → UPerNet / T9 B2U smoke → 预声明 seed 17 的完整预算首轮 → 资源核算 → 统一检测器接入及三种子展开。

MaRS 优先，因为可复用四级特征接口；Galileo 先验证 RGB mask、归一化、空间恢复和 Base 在正式尺寸下的显存。Nano/Tiny 只证明其自身链路，不能代替 Base 验收。检测 G0/G1 独立推进，不阻塞 iSAID 接入；iSAID 低分不是自动取消检测候选的规则。

## 6. 候选来源、规模与尺度

用户已明确说过上级希望增加 MaRS 和 Galileo，这一事实已写入决策项。无需再问是否自行扩项；仍需分阶段安排资源，不能据此把所有任务/种子同时排进单卡队列。

6 个既有配置 + 2 个新候选 = 8 个主干；检测三种子最多 24 个 run，另计 R50 校准。只有新增冻结 R50 主表基线才再加 3 个 run。iSAID 首轮、smoke、G1 复现和 CPU 后处理均另外计费，不能用 24 或 27 代表整个项目总成本。

新文档 §6.1 已把 Galileo 与其余模型放入同一张 GSD/步长表：其选定 S2 RGB 路径以 10 m 为基准，patch 8 对应 /8；模型支持可变 patch 和显式 GSD，不应概括为全部预训练数据均为 10 m。

输入尺寸事前规则设为：1024 主协议，OOM 标记资源阻断，512 用于诊断。若另开全模型 512 协议，在该组任何正式指标可见之前锁定全部条件；不能看到结果后改变主表规则。已产生的 iSAID 1024 结果保持原协议身份。
