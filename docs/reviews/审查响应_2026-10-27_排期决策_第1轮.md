## 逐条回应

### 第 1 条：bug 机制描述错误 —— 成立

原文写"指标为 0 或未定义时写成了空值"，前半句是错的。实测：

```text
pydantic 序列化 0.0  → {"v":0.0}   → 可正常读回
pydantic 序列化 NaN  → {"v":null}  → 读回时校验拒绝（value 需要 number）
```

根因链条与审查意见一致，且比原文更具体：

1. `ConfusionMatrix.iou()` 在分母为 0 时返回 `NaN`（`evaluation/confusion.py:113`）。
2. `multiclass_metrics()` 的加权和 `sum(support(i) * iou(i))` 遇到 `support=0` 与 `iou=NaN` 时产生 `0 × NaN = NaN`，整项被污染（`evaluation/segmentation.py:30`）。
3. `to_metric_records()` 刻意保留 NaN（注释写明"NaN values are preserved"）。
4. `model_dump_json()` 把 NaN 写成 `null` → 读回时 `RunRecord` 校验失败 → **整条记录被拒收**。

用 Clay T8 的真实混淆矩阵复核（`clay_v1_5-T8-frozen_probe-17-v1`）：

| 量 | 值 |
|---|---|
| class_0 的 GT 像素数 | **0**（T8 的 `label_mapping` 是 `0 -> ignore, 1..24 kept`） |
| class_0 的 IoU | `NaN`（分母为 0） |
| 加权 IoU（含 `0×NaN`） | `NaN` → 写成 `null` |
| 加权 IoU（跳过 NaN 重算） | **0.6935** |
| 主指标 mIoU（只统计出现过的类） | **0.41963516…**，与记录中的主指标完全一致 |

**因此**：`class_0` 是忽略类，它在 T8 上**必然**分母为 0，所以这不是偶发 bug，而是**每条 T8 正式运行都会稳定复现**的确定性问题；同时**主指标与 F1 完全有效**。"整条记录读不进来" ≠ "训练无效"，原文档混为一谈了。

### 第 2 条：'必须重训 / 白烧算力' 证据不足 —— 成立，原建议已撤回

核查结果比审查预期更有利：

| 产物 | 是否存在 | 来源 |
|---|---|---|
| 六条正式 T8 记录的 `confusion_per_scene.json` | **全部存在**（逐 group 的 25×25 计数矩阵） | `run.json` 的 `artifacts` 字段 |
| AnySat 的 `best_checkpoint.pt` | **仅 B1（`select=True`）保存**；冻结轨不保存权重 | `workers/anysat/src/anysat_worker/t8.py:298-301`，已核对冻结记录目录内确无 checkpoint |
| 逐轮断点续训 | **不存在** | 同上，AnySat T8 未接 checkpoint 恢复 |

关键推论：

- **指标可以从混淆矩阵直接重算**，无需重训；我用 Clay 记录验算，主指标逐位吻合（0.4196351633827435），说明重算链路可信。
- **但中止当前 AnySat 训练确实会丢失已有进度**（无逐轮断点），这一点原文档的"作废 4 小时"反而低估了实际代价，而"再跑就是白烧"又高估了损失——两个方向都判断错了。

原文档"继续跑都是白烧 28 小时"一句**撤回**。正确表述是：**在完成指标修复或重算之前，T8 记录不可读；但训练产物可复用，不存在"重跑才有结果"的必然性。**

### 第 3 条：方案对比不公平、时间线矛盾 —— 成立

三处问题都承认：

1. **A 含"修 bug"，B/C 却默认"永不修 bug"** —— 这是把"是否修 bug"偷偷绑进了"是否中止 T8"，导致 A 必然占优。修 bug 与中止 T8 是两件独立的事，应拆开决策。
2. **时间线自相矛盾** —— 前文承诺 A 的 T8 在"10/29 白天"完成，后文又说 AnySat 是否重跑"待定"，交付范围前后不一致。根因是没定义"T8 完成"到底指三种模型 × 三种子，还是仅 Clay+Prithvi。
3. **"另一台机器无决策价值"不成立** —— 单种子至少能验证可跑性、估出真实工时、给出方向性信号，这本身就是原文档自己主张的"先 smoke 再铺开"的做法。

本次已补上缺失的方案 D（见新文档第四节），并核查了可行性：

- 3080 的 `~/rs-eval/data` 有 T2/T3/T4/T5/T8/T1S 的 manifest，**唯独缺 T1**；
- T1 原始数据仅 **1.8 GB**，局域网传输成本可忽略；
- 3080 当前被 T4 第 3 个种子占用，**今晚 18:30 后空出**；
- 风险：3080 只有 20 GB 显存，AnySat T1 全量微调在 4090 上峰值约 20.4 GB，需 `batch=1` + 梯度累积 2（有效 batch 仍为 2）并先做 smoke。

### 第 4 条：'已有结论不会被推翻'必须改 —— 成立

原表述把"数值不变"和"结论不变"混在一起，逻辑上不成立：补测 AnySat 缺波段的**目的**就是检验现有解释；如果 AnySat 同样抗缺波段，则"只有 Clay 稳得住"必须改写。已改为：

> 已完成的实验数值不因排期调整而改变；但任何新补的证据都可能修正**解释与结论**。

同时把缺波段结论的处理方式限定清楚（原文档确实过度概括）：

- 扰动实现是**推理时把指定通道替换为训练集均值**（`perturb.py:130`），不是"物理上缺失通道"，也不是"删掉 token"；
- 因此结论只能限定为：**在 T1、冻结路径、该替换方式下**，Clay 保持 83%，其余三个模型降到 1%–14%；
- 不能推广成"缺波段致命"或"元信息不影响"这样的通用判断——后者也只覆盖 T1 冻结路径的三种扰动。

### 第 5 条：单种子的后续规则要提前定 —— 成立

原文档"若结论方向明确再决定补满"确实是**看结果决定样本量**，已删除。改为预先声明规则（见新文档 5.3）：

- 单种子运行**只作可行性/成本诊断**，标注 `exploratory`，**不进主表、不进 D1/D2 汇总**；
- 补满三种子的触发条件**与结果好坏无关**，只看三条：可跑性通过、单种子耗时落在预算内、该单元在正式表中有对应 cell；
- 若单种子失败或 OOM，**不构成"结果不好"**，只记录为工程结论。
