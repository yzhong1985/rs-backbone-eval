## P1-1 诊断运行仍可覆盖正式共享缓存

**问题**：adapter / projector 的共享路径只用 `epochs` 区分。一个 **8 epoch
但限制训练集或 step** 的诊断 run 与正式 run 的 `epochs` 相同，会写到同一个
`adapter_raw.pt` / `oe128.pt`，后跑的正式 run 可能加载诊断产物。

**修复**（`workers/anysat/src/anysat_worker/t11p.py`）：

- 新增 `_budget_signature(epochs, train_rows, limit, smoke)`，例如正式
  `e8-n1455-l0-s0`、受限诊断 `e8-n4-l1-s1`；
- `_fingerprint(...)` 的 payload 增加 `budget`，adapter 和 projector 路径都由
  该指纹决定；
- probe / distill / B 层共用同一 budget 计算；
- run tags 记录 `budget_signature` 和 `artifact_scope`（`formal` /
  `diagnostic`）；
- 新增 `test_fingerprint_separates_training_budgets`。

**验证**：8 epoch + `TRAIN_LIMIT=4` + `LIMIT_BATCHES=1` 的 CPU smoke 发布到
`.../b8bf10b1e6135f17/...`，与正式 budget 的指纹不同；不再覆盖正式路径。

## P1-2 探针不保存任务头

**问题**：raw/S128/O128 训练完只写指标，没有 `head.pt`；S128 的监督投影器
E 也没有落盘，run 结束后无法直接重评。

**修复**：

- 新增 `_probe_payload(...)`，保存 `head.*`，并在有投影器时保存
  `projector.*`；
- 每个探针 run 写 `head.pt`；S128/O128 另写独立的 `projector.pt`
  （S128 为监督训练，O128 为蒸馏冻结）；
- payload 带 `bands`、`frames`、`grid`、`head_dims`、`num_classes`、
  normalization mean/std、adapter fingerprint/source、checkpoint sha、
  manifest sha、seed、protocol、readout；
- `head.pt` / `projector.pt` 都注册为 checkpoint artifact，并记录
  `head_artifact` / `projector_artifact` tags；
- 新增 `test_probe_payload_contains_head_and_projector`。

**验证**：CPU smoke 的 raw run 有 `adapter.pt + head.pt`（6 个 head 张量）；
S128/O128 有 `head.pt`（head + projector，10 个张量）和 `projector.pt`
（4 个张量）；两者都可 `torch.load`。

## P2 归一化缓存混用训练子集

**问题**：`channel_statistics` 的缓存键只有 manifest digest。`TRAIN_LIMIT`
run 用前几个 patch 算出的统计量会缓存到同一文件，之后全量 run 直接复用。

**修复**：

- 新增 `_norm_cache_key(manifest_digest, rows)`：对传入的 train rows 的
  `sample_id` 排序后取 sha256 前 16 位，加入缓存键；
- 缓存文件名形如
  `anysat_t11p_norm_3155a8c5e4dc5c00-08c747221903c163-p24-v2.json`；
- payload 记录 `train_rows` 与 `cache_key`；
- 新增 `test_norm_cache_key_separates_train_subsets`。
