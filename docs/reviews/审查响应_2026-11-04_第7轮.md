### 2. 20-bin 的时间位置会重复（LIM 与 AnySat）

- 新增共享helper `rs_backbone_eval.timeutil.days_since_reference()`，参考日
  `2018-09-01`（AnySat PASTIS loader 的 `reference_date`、U-TAE 的 PASTIS
  口径），返回整日差，可跨年、可大于 366；
- `lim_worker/t11_ltae.py` 用 `_date_position()` 替换 `_doy()`，并把 LTAE 的
  `T` 从 366 改为上游默认 **1000**（位置已是日偏移，不是年内序号）；
- `anysat_worker/t11.py` 同样改用 `_date_position()`；single/20bin 都走它
  （single 只有一帧，影响小，但口径保持一致）；
- run tags 记录 `temporal_positions="days since 2018-09-01"`、`ltae_T=1000`；
- 回归：`test_days_since_reference_is_monotone_across_the_pastis_series`
  （2018-09-24 / 2019-09-24 不再同日、跨 1 月单调、>366 可用），
  LIM/AnySat 的 decode 测试断言 20-bin positions 严格递增且不重复；
- **旧 diag2 作废**：它按旧编码跑且是 REDUCED-BUDGET，只作历史记录，不进正式结果。

### 3. AnySat / Clay 的 `optimizer_steps` 多记 4 倍

- 两个 worker 原来 `total_steps += steps` 累加 micro-batch 数；现改为在每次
  `optimiser.step()` 后 `total_steps += 1`，包括 epoch 尾部的 flush step。
- LIM 20-bin 本来就是每个 micro-batch 一次 `step()`，无需改。

### 4. BB 轨头不一致

- AnySat 从 `LiteSpatialHead(1536)` 换成 **`UPerNetHead([1536], fpn_dim=256)`**，
  与 LIM（4 级金字塔）和 Clay（4 个同尺度层）同一解码器；
- AnySat 的 dense 输出是输入分辨率（128×128），新增 `_dense_grid()` 把它平均
  池化到 stride-8 网格（16×16）再做单尺度金字塔，和 Clay T9 的做法一致；
  logits 再双线性上采样回标签尺寸；
- `head_id` 改为 `anysat_s2_{variant}_upernet_fpn256`，notes 同步更新；
- 回归：AnySat T11 runner 测试断言新的 head_id，伪骨干下跑通。
- 注意（实现中发现）：`UPerNetHead.forward()` 接受的是“各层列表”，传单个
  tensor 会被当成 batch 维迭代；AnySat 调用处已改为 `head([grid])`，测试
  覆盖 batch=1 与 batch>1 的路径（batch>1 时传错会直接报层数不符）。

### 5. AnySat 归一化缓存没有失效条件

- 缓存 key 改为 `{variant}-{manifest_sha256[:16]}-p{STATS_PATCHES}-v1`，
  覆盖样本集合、patch 数、解码版本（位置编码口径变化也计入 `v1`）；
- 写文件改为同目录临时文件 + `os.replace()` 原子替换；
- 缓存 JSON 里记录 `manifest_sha256`、`variant`、`patches`、
  `positions="days since 2018-09-01"`，便于事后核对。
