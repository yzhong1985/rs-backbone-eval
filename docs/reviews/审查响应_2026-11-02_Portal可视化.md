## 1. 小屏布局溢出（已修）

根因有三处，不止 `.content`：

1. **grid 轨道的自动最小尺寸**：`1fr` 的 min-content 被宽矩阵表撑开，整页跟着变宽。
   `.content { min-width: 0 }` + 窄屏 `minmax(0, 1fr)`；
2. **任务页 / run 页的 `table.mini` 没有滚动容器**：首页修好后，`#/task/T10` 在 390px
   仍是 **722px**（审查未覆盖到的同源回归）。7 处 `<table class="mini">` 全部包进
   `.table-wrap`；
3. **资源卡片的 sha256 长串没有断点**：把卡片撑到 410px（审查看到的"约 60px 外溢"
   一部分来自这里）；`overflow-wrap: anywhere`。另外三个顶部按钮在 560px 下换行。

真实 Chromium 实测（home / task / run / compare；drawer 打开另测）：

| 视口 | 修复前 | 修复后 `scrollWidth` | 结果 |
| ---: | ---: | ---: | --- |
| 320 | — | 320 | OK |
| 390 | 1329（首页）/ 722（任务页） | 390 | OK |
| 768 | — | 768 | OK |
| 1024 | — | 1024 | OK |
| 1440 | 1440 | 1440 | OK |

判定脚本排除了 `overflow-x` 已裁剪的表格和 `position: fixed` 的抽屉；修复后未裁剪元素
中没有越过视口的节点。drawer 打开时 `cardScroll == cardClient`（320/390/768）。

`official_validation`，生成器不能默认 `test`。

## 3. 回放身份与"重评"（设计 §7）

manifest 固定：`run.json` 的 git commit / manifest sha256 / `model_checkpoint_sha256` /
protocol / seed / input；三份配置的内容 sha256 与 `request.json` 哈希；主干与头文件哈希；
生成器版本与哈希；滑窗、stride、合并方式、分数阈值、NMS 参数。

**配置漂移**用 `git show <run.git_commit>:<config path>` 取原内容与当前文件比对，
而不是只记路径。判定规则写进生成器：

- 代码/配置/审计标记都与原 run 一致 → `mode = original_protocol`；
- 否则 `mode = reevaluated`，Portal 每张图都带"重评：当前代码/配置，非原 run 分数"
  徽标，并保留原 `stale_flags`（T10 的 `T10_DETECTOR`、T9 的 `T9_PADDING`）。

身份校验不通过时默认**失败**，只有显式 `--mode reevaluate` 才降级为诊断重评。

## 4. 样本单位与错误定义（设计 §4/§5）

- **单位**：`scene-window`。T9 按 `group_id` 整图滑窗 + logits 平均
  （`lim_worker/t9.py:357`），T10 按场景恢复坐标 + 旋转 NMS（`t10.py:511`）；
  图只画 manifest 的 `window`，卡片里的 TP/FP/FN 是**整景**口径。窗口裁剪不改变指标。
  `--unit tile` 仅作诊断，manifest 标 `diagnostic: true`，Portal 加"不能解释正式分数"横幅。
- **多分类**：同时给 `foreground_binary_iou`、`per_class_iou`（缺失类记 `null` 不记 0）、
  `macro_iou`，以及选中类别的 one-vs-rest TP/FP/FN；新增"类别互换"橙色像素与
  `switch_pairs`，避免 1/2 互换被二值 IoU 涂成绿色。
- **空场景**：桶扩为 `hit / partial / miss / empty_correct / empty_false_alarm`，
  GT=0 且预测=0 记为正确空场景，不再算"未命中"。
- **检测**：类别感知贪心匹配、IoU 0.5、分数阈值取自协议、旋转 NMS 参数写入 manifest。

## 5. P2 一致性与成本（设计 §6/§8/§10）

- `--samples 9` 与"每桶 3 张"的歧义改为 `--per-bucket 2`（默认）+ 总上限说明；
- `hash(sample_id)` 改为 `sha256(f"{seed}:{group_id}:{x}:{y}:{w}:{h}")` 升序，
  跨进程稳定，并记录 `candidates_sha256`；
- 成本按候选池（`--pool 40`）估算，记录实际推理窗口数与耗时；T9 约 2–5 分钟、T10 约 2–4 分钟；
- 生成器必须走空闲检查/队列，不能在正式训练旁启动，日志写 `visualization/generate.log`；
- 示例 manifest 换成真实 T9 run（`head_only` + `T9_PADDING`），字段与分桶规则一致，
  不再把 TP=3/FP=7/FN=5 放在 `miss`，也不再混用 DOTA 类名与分割 IoU；
- 明确桶内哈希只保证可复现、不保证无偏；跨 run 对比用 `--list` 固定共享清单。
