## 仍需注意

1. **T4 数据链路尚未接进 bootstrap。** `bash scripts/colab_bootstrap.sh T4` 会退出 2。Colab 运行 T4 前，需根据下载 catalog 固定 revision 准备其影像、标签和相同 manifest。初版包未在本机提供，无法验证其实际内容；还需确认固定 AnySat 源码目录随包提供并正确设置 `ANYSAT_SRC`。
2. **smoke 不会自动排除出主比较表。** 已实测：相同 seed 的较新 completed smoke 会被 `matrix.canonical_runs()` 当成重试覆盖正式 run；`variant_key()` 不区分 epochs/limit，`audit_runs.py` 也只审查代码祖先关系。当前使用独立 smoke runs 目录隔离，文档已修正；聚合器仍需后续加正式预算准入。
3. **batch 2 是项目预算，并非所链接的 Prithvi 官方配置。** 当前上游 [T1 配置](https://github.com/NASA-IMPACT/Prithvi-EO-2.0/blob/main/configs/sen1floods11.yaml) 为 batch 16，[T5 配置](https://github.com/NASA-IMPACT/Prithvi-EO-2.0/blob/main/configs/multicrop.yaml) 为 batch 8。维持自定义 batch 2 可用于项目内对比，但不应宣称精确官方复现；文档已改正。
4. **AnySat T5 的 frozen_probe 实际训练了输入适配器。** 与配置 `train_input_adapter: false` 的名称语义不一致；它是“冻结 backbone、训练 adapter+head”，不是纯线性或固定输入 probe。既有 worker 会记录 adapter/head 参数和 frozen 状态，比较表仍需说明；本次保留原有实验定义，续训不更改协议。
5. **物理数据校验与硬件实测仍必需。** bootstrap 的新校验是路径存在且非空，不是逐文件内容哈希或 raster 解码审计。不同 GPU/微批次的随机计算也不保证逐位一致。恢复同一 run 时保持原 micro-batch/accum 设置，正式训练前分别验证 T1/T3/T4/T5 的训练、验证显存和写盘耗时。
