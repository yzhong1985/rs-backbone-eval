## 1. 需求与背景

iSAID（T9）与 FAIR1M（T10）的正式 run 是 8–21 h 级。此前只有 AnySat 的 T1/T3/T4/T5 接了
`TrainingCheckpoint`，LIM/Prithvi 的长跑一旦中断（重启、OOM、拔电）只能从 0 开始，20 万 tile 的
预算是按"完整跑一遍"算的，重跑既费卡也破坏"同一 cell 同 host 同设置"的可比前提。

本轮把 LIM T9、LIM T10、Prithvi T9 三个循环接到同一套 checkpoint：
`RS_EVAL_CHECKPOINT_ROOT`（落盘位置）/ `RS_EVAL_CHECKPOINT_EVERY`（每 N 个 epoch 存一次）/ `--resume-from`。

## 2. 改动

语义与 AnySat 现有实现一致：

- **在 epoch 边界保存**，崩溃后重放当前 epoch（不是从 epoch 中间续）；
- 续训前校验 task / model / protocol / seed / manifest / 预训练权重哈希 / git commit / 关键设置
  （epochs、crop、lr、有效 batch、FPN 维度、keep_ratio 等），任一不一致直接拒绝；
- 计数器（`optimizer_steps`、`epochs_completed`）从 checkpoint 读，不重置；续训时若步数预算已满足，
  直接进入评测；
- `latest.pt` 写临时文件后原子替换，另可镜像到 `RS_EVAL_CHECKPOINT_ROOT/<run_id>/latest.pt`。

## 3. 自查发现的两个缺陷（均已修）

### 3.1 保存点落在 `if budget_hit: break` 之后 —— 正式跑永远不会存盘（`9bb477a`）

第一版把保存插在循环尾部已有的 `if budget_hit: break` 之后，于是它成了**死代码**：只有步数预算被
打满那一轮才可能保存，而正常跑满 epoch 的路径一次都不保存。

发现方式：3080 上 `...-resumeA`（2 epoch）跑完，日志正常、指标正常，但 run 目录里**没有**
`latest.pt`——`ls` 返回码 2。这是单测驱动 `TrainingCheckpoint` 对象时看不到的（对象本身没问题，
是**调用位置**错了）。

修复后与 AnySat T1/T3/T4/T5 对齐：

```python
if budget_hit:
    checkpoints.save(completed_epochs, optimizer_steps, final=True)
    break
... validation ...
checkpoints.save(epoch + 1, optimizer_steps, final=epoch + 1 == epochs)
if checkpoints.start_epoch == epochs:
    checkpoints.save(epochs, optimizer_steps, final=True)
```

`tests/test_resume_wiring.py` 用 AST 断言：每个已接续训的循环体里必须有**直接位于循环体**（而不是
嵌套在某个 `if` 下）的 `checkpoints.save(...)`。已验证该断言对 `93def25` 版 `t10.py` 判定为
0 个直接保存（失败），对修复后为 1 个（通过）。这个测试不依赖 torch，因此在根环境 CI 里会真正执行
（`tests/test_training_checkpoint.py` 需要 torch，在根环境会被 skip）。

### 3.2 dispatch 白名单没跟着放宽（`617844b`）

worker 已能续训，但控制层仍拒绝：

```
dispatch rejected: resume is supported only for AnySat T1/T3/T4/T5 train
```

即功能在真实入口不可达。现改为显式表：

```python
RESUMABLE = {
    "anysat_base": {"T1", "T3", "T4", "T5"},
    "lim_mit_huge": {"T9", "T10"},
    "prithvi_eo_v2_300_tl": {"T9"},
}
```

并补用例：三组可续 (task, model, protocol) 通过；`probe` 动作与未接续训的 model 仍被拒绝。

### 3.3 关联：T10 评测阶段 NameError（`d594485`、`f543158`）

同一轮端到端 smoke 暴露：`train_t10` 里 `for class_id, value in ...` 遮蔽了模块级 `class_id()`
helper，ruff 又因"未使用 import"删掉了它，训练正常、**评测第一步就 NameError**。已改循环变量名并
恢复 import。这类问题只能靠端到端跑抓，单测与 lint 都看不到。

## 5. 边界与已知限制

- **epoch 边界语义**：崩溃时当前 epoch 的训练量会重放，因此 `wall_time_seconds` 累计的是"实际占用
  卡的时间"，会略大于理论训练时间；`optimizer_steps` 与 `epochs_completed` 不会重复计数。
- **同一 run 不能并发写**：`TrainingCheckpoint` 在目标路径已存在时直接报错，续训必须用新的 `-vN`
  run id（与 dispatch 既有规则一致）。旧的 run 目录保留，不删除、不覆盖。
- **设置校验偏严**：`epochs` 在 settings 里，所以"用 4 epoch 的 checkpoint 续成 50 epoch"会被拒绝。
  这是有意的（预算是 cell 的一部分）；真要延长预算应该另开 run 并在报告里标为不同预算。
- **smoke checkpoint 不能续成正式预算**：身份校验会比对 manifest/git/设置，但 smoke 只是小设置，
  仍属操作纪律范畴，不在代码强制范围内。
- **两个在途 run 无法续训**：4090 的 `lim_mit_huge-T9-upernet_frozen-train-17-v3`（17:11 起）与
  3080 的 `prithvi_eo_v2_300_tl-T9-upernet_frozen-train-17`（21:43 起）都启动于本功能之前，只能
  跑完；其后新起的 run 才有 checkpoint。这与 AGENTS.md 的说明一致。
- **尚未覆盖**：MaRS / Galileo 的 T9 worker 还没有训练循环，因此也没有续训；报告与 Portal 仍无
  检测视图（T10 指标只在 `run.json` 与附录里）。
