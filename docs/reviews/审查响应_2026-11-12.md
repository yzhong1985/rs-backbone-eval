## P1 T8 迁移没有保存训练后的头

**问题**：三个已完成的 T8 迁移 run 只有指标和混淆矩阵，没有头权重，无法重评或
推理。

**修复**（`workers/clay/src/clay_worker/transfer.py`）：

- 训练结束后写 `head.pt`，与 `run.json`、混淆矩阵放在同一 run 目录，并登记为
  `task_head` artifact；
- 头只在这个迁移里训练，编码器和投影器都是冻结的，所以 payload 同时记录完整的
  读出链：
  - `state_dict`、`in_channels`、`num_classes`、`bands`、`wavelengths_um`、
    `gsd_m`、`patch`；
  - chip 协议（训练每景每 epoch 32 个 224 px、validation 64/景固定种子、test
    全网格）；
  - GF-2 训练集逐通道 `mean`/`std`（这些统计量来自固定种子的 chip 抽样，不写在
    manifest 里，必须原样保存才能复现）；
  - 读出类型（`raw-1024` 或 `pastis-{target}`）、seed、protocol、epoch 数、
    `reduced_budget` 标记、编码器 checkpoint 路径与 sha256。
- 投影器不是只记路径：训练时把它复制到 run 目录的 `projector.pt`，登记为
  `readout_projector` artifact；payload 同时记录源路径和 sha256。这样缓存被清理后
  仍可复现。
- 写入用临时文件 + `replace`，中断不会留下半个 `head.pt`。

**验证**：新增 CPU 测试 `test_t8_transfer_head_is_self_contained`（根环境
`pytest` 收集）：构造 64 维头 + 假投影器，断言 state_dict 完整、metadata 正确、
投影器已复制、两个 artifact 都已登记。三个真实 run 用 `-v2` 重跑（干净提交、
固定 manifest），完成后逐个断言 `head.pt` 存在且可 `torch.load`。

复现或推理时只需：`head.pt` + 同目录 `projector.pt` + 环境变量指向的 Clay
checkpoint，按 payload 里的 mean/std 归一化。

## P2 缓存迁移校验仍不完整

**问题**：`phase_migrate` 不检查旧版本兼容性，也不检查特征窗口数；已复现 3 份
特征对应 4 个窗口仍被盖章为有效。

**修复**（`scripts/fbp_extract_windows.py`）：

- 新增纯函数 `_migrate_blocker(cached, windows=..., source=..., version=...)`，
  migrate 只在它返回 `None` 时盖章，否则打印原因并计入 stale：
  1. **版本兼容**：无 `version` 的旧文件可以盖章（这是 migrate 存在的原因）；
     有 `version` 且不等于当前 `EXTRACT_VERSION` 的文件必须重算，不能把旧规则
     产物“洗白”；
  2. **窗口数**：`features.shape[0] == len(windows)`，3 对 4 直接拒绝；
  3. **通道数**：AEF 必须 64 通道、OlmoEarth 必须 128 通道；
  4. **窗口坐标**与 **source** 仍需逐值一致（上一轮已加的检查保留）。
- `_is_current` 同样新增可选的 `rows` / `channels` 约束，提取跳过路径也不会
  复用截断的特征数组。

**验证**：新增 5 个 CPU 测试，覆盖旧版本可迁移、版本不兼容拒绝、3 特征 vs 4
窗口拒绝、通道数错误拒绝、`_is_current` 拒绝截断数组；在部署缓存上重跑
`--phase migrate`，结果见下。
