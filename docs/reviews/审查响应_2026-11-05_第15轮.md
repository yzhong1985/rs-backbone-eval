## 2. LR 探索不再与 BBF 主结果同格

问题：baseline、lr5e5、lr1e5 都映射到 `BBF`，`_rank` 会按验证集从中挑一个当 headline；BBT 等其他轨只跑一组超参，直接对比不公平。

修复：

- 新增 `BBFL`（BBF-LR）轨，`lim_s2_20bin_finetune_lr5e5` / `_lr1e5` 映射到 `BBFL`；

- 报告新增说明：BBFL 是 8-epoch 全量微调的 LR 探索轨，headline BBF 仍只保留基线配方，不要把 BBFL 的验证集选模结果当成 BBF 主结果；
- `TRACK_ORDER`/`TRACK_NAMES`/报告 note 同步更新。

## 3. `final_checkpoint.pt`：先完成、原子写、失败不丢指标

问题：保存发生在 `writer.complete()` 之前，且不是原子写；磁盘满时一个已经算完指标的 run 会被记成 failed。

修复：

- `writer.complete()` 先写，保证 `run.json` 已经是 `completed`；
- 新增 `_save_final_checkpoint`：
  - 写入 `final_checkpoint.pt.tmp`，再用 `os.replace` 原子替换；
  - 写前检查剩余空间（full fine-tune 需 3 GB，frozen 需 0.5 GB）；
  - 写失败只在 tags 写 `checkpoint_error`，不再让 run 失败；
- lane 启动前增加 `require_free_gb` 磁盘预检（默认 20 GB，可用 `RS_EVAL_MIN_FREE_GB` 覆盖），`T11BBF4090` / `T11BBFLR4090` / `T11BBF20` 都已接入；
- 新增测试：`test_checkpoint_write_failure_does_not_fail_the_run`（模拟 `torch.save` 抛 `OSError("disk full")`，断言返回错误且文件不存在）。

当前磁盘：`/geodata` 约 48 GB 可用（95% 已用）。LR 筛选 6 个 run + 20ep 3 个 run 约需 18 GB，预检会阻止空间不足时起跑；50ep 前需要把已完成 checkpoint 传到 NAS/5090。
