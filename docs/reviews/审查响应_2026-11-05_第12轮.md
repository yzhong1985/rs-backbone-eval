## 1. 问题与修复

### P1：回传命令会丢失 run 目录

**问题**：`rsync -a --ignore-existing ~/runs/lim...-v8-5090/ <ledger>/` 的源路径尾随 `/`
表示"复制目录内容"，会把 `run.json`、`latest.pt` 等直接铺到账本根目录；
`--ignore-existing` 只跳过同名文件，不能保护整个目录。

**修复**：文档 §6.3 改为逐个 run 传输，源路径不带尾随 `/`：

```bash
for run in ~/rs-eval/runs/lim_mit_huge-T10-*-v8-5090; do
  rsync -a --ignore-existing "$run" yzhong@192.168.1.89:/geodata/rs-eval/runs/
done
```

并在 4090 上先做目标存在性检查：

```bash
ls -d /geodata/rs-eval/runs/lim_mit_huge-T10-*-v8-5090 2>/dev/null \
  && { echo "target exists: stop"; exit 1; }
```

### P2：截止条件只是人工规则

**问题**：文档写"seed 42 只在 04:00 前启动"，但 lane 会无条件跑完 `SEEDS` 列表。

**修复**：T10B2 lane 增加 `RS_EVAL_RERUN_START_BEFORE=HH:MM`：

- 每个 seed 启动前比较 `date +%H%M`；
- 超时打印 `seed <n> skipped: past RS_EVAL_RERUN_START_BEFORE=...` 并停止链条；
- 未设置时不改变原行为。

本次 5090 的 lane 在改动前已启动（`c748b2d`），但 seed 17 于 00:14 启动、
预计 03:10 完成，满足 04:00 条件，因此不需要中断；seed 73 不在本链条内。
下一次起跑会带上该环境变量。

### P2：耗时估算漏算 AP

**问题**：`eval_seconds` 在 `evaluate(...)`（COCO AP）之前停止计时；
`wall_time_seconds` 也在最终 test 评估之前取值。按 0.16 h 估评估会偏少。

**修复**：文档 §6.1 改为：

- 推理 + NMS：2445 tile × 0.2375 s ≈ 0.16 h；
- AP 计算与其他开销：按约 0.04 h 预留；
- 单 seed 合计约 **3.0 h**，两个 seed 约 6 h。

不修改 worker 的计时语义（改 `wall_time_seconds` 会改变已入账 run 的可比性），
只在部署文档中如实说明。
