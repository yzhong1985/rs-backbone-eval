## 2. 必修 1：val 的标注与影像错位

### 复现

| 数据 | 影像 `size` 与 XML `<size>` 一致 |
| --- | --- |
| train（抽 300） | 300/300 |
| val（全 1,732） | **458/1,732（26%）** |

影像都是正方形（1000²/1500²/3000²/5000²），XML 却大量写 800×600、600×800，分布完全不同；
例如 `val/489.tif` 是 1500×1500，XML 写 600×800，目标坐标全落在左上 566×663 内。

### 根因

我按"同名 stem"把 **FAIR1M1 仓库里 1,732 张没有标注的影像** 和 **FAIR1M2 仓库的 val 标注**
配到了一起。两个仓库的 id 空间并不对应。

决定性验证：把 FAIR1M2 自己的 `images.zip` 解开（8,287 张）再逐张比对 ——
**200/200 尺寸一致**，而 FAIR1M1 的同名影像只有 49/200。所以正确配对是"影像和标注来自同一个
仓库"，FAIR1M1 里那 1,732 张无标注影像是另一批数据（疑似测试集），不是 val。

### 处理

- `images/val` 全部换成 FAIR1M2 的影像，逐张校验后 **1,732/1,732 尺寸一致**、目标坐标越界率
  1.20%（train 1.58%，属 FAIR1M 边界目标的正常水平）；FAIR1M1 那 1,732 张移入
  `images/unlabeled/`，不参与任何 split；
- `configs/downloads/catalog.yaml` 新增 `data_fair1m_val`（FAIR1M2 的 images + labelXmls，
  含本地 SHA-256），原来漏登记的两个文件现在有出处；
- `scripts/fetch_fair1m.sh` 重写：按仓库成对取用、把无标注影像单独归档，并在结束前校验
  **每张影像尺寸必须与标注一致（<99% 直接失败）** —— 这正是我上一版缺的那道闸；
- 你说得对，`c748eeb` 那个"GT 当预测 mAP=1.0"的自检不读影像，抓不到这类错位；现在数据侧的
  一致性由 fetch 脚本和 `audit-data` 分别把关。

## 3. 必修 2：`poly2obb` 旋转两次

### 复现

100×20 的框从短边起点写 `(0,0),(0,20),(100,20),(100,0)`：旧代码先选长边（`θ=0`），又因
`width<height` 再交换并 `+π/2`，得到 `θ=1.571`；还原后与原框 IoU **0.111**。真实数据抽样
800 个 XML、16,861 个目标：短边起点占 43.2%，旧实现重建 IoU <0.5 的比例与你的 39.1% 一致。

### 修复

选定长边那一对之后，宽高和角度**直接取用**，不再二次交换
（`detection/geometry.py`）。验证：

- 同一矩形从 4 个起点、两个绕向共 8 种写法 → 得到**完全相同**的 `(cx, cy, w, h, θ)`，重建 IoU 全 1.0；
- 真实标注 14,686 个目标重建 IoU：**均值 0.979、中位 0.984、<0.5 仅 1 个（0.01%）**；
- 新增 `test_a_box_written_from_the_short_edge_is_not_rotated_twice` 与
  `test_every_vertex_order_produces_the_same_box`。旧的 `test_le90_always_reports_the_long_edge`
  确实如你所说用的是长边起点，覆盖不到这个分支。

## 4. 必修 3：空 tile 崩溃

### 复现与根因

空 tile 和"只有 ignored 目标"的 tile 都在 `_roi_losses` 的
`torch.cat([... for target in targets if len(target)])` 上抛
`ValueError: torch.cat(): expected a non-empty list`。另外 `_rpn_losses` 对空 tile 直接
`continue`，等于白跑一次前向。

### 修复

- 空 tile：RPN 视为**全负样本**（`labels=0`，再被 ignore/valid 掩码修正）正常采样，RoI 分支
  在无目标时返回 0；ignore-only 的 tile 同理，只是 ignore 区域内的 anchor 不被采；
- 顺带修掉两个被"把 GT 加进 proposals"暴露出来的缺陷：
  - **RoI 回归的 anchor 表示错了**：`encode()` 期望 `x1,y1,x2,y2`，却传了 `cx,cy,w,h,θ`。
    由于 `cx > w` 几乎总成立，"anchor 宽"是负数，`log` 出 NaN。此前的测试只断言 loss 有限，
    所以一直没暴露；现在改成 `encode(hull(boxes), matched)`，并加
    `test_ground_truth_in_the_proposals_gives_a_finite_regression_loss`；
  - 正样本索引用 `positive`（`boxes` 的下标）去索引 `sampled` 的行，越界；改为"前
    `positive_count` 行就是正样本"。
- 加 `test_empty_and_ignored_only_tiles_train_the_rpn_on_negatives`：断言 loss 有限、
  `loss_rpn_cls > 0`、`loss_cls == 0`、可以 backward。
