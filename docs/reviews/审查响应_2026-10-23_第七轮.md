## P2-1：T4 审计条件未按模型收窄

**结论：成立，已修复。**

### 事实

`T4_METRIC`（`ca27c4c`）修的是 OlmoEarth worker 的缺陷：
`workers/olmoearth/src/olmoearth_worker/tasks.py` 在二分类任务里无条件把
`foreground_iou` 改名为 `metric_name`，T4 因此把前景 IoU（≈0.24）写成了
`mean_iou`，而同一混淆矩阵的二类 mIoU 是 ≈0.61。Clay/Prithvi/AnySat 的
worker 从未做这个改名，修复前后都直接写 `mean_iou`。

但 `required_fixes` 里写成了：

```python
if task == "T4":
    fixes.append(T4_METRIC)
```

于是所有模型的 T4 记录都被要求包含 `ca27c4c`，与修复的真实影响范围不符。

### 修复

改为仅对 OlmoEarth 两个模型生效：

```python
OLMOEARTH_MODELS = {"olmoearth_v1_2_tiny", "olmoearth_v1_2_base"}
...
if task == "T4" and model in OLMOEARTH_MODELS:
    fixes.append(T4_METRIC)
```

新增回归测试：OlmoEarth 的 T4 仍要求 `T4_METRIC`；Clay/Prithvi/AnySat 的 T4
不再要求。

### 影响

当前账本里没有“正式、且早于 `ca27c4c` 的 Clay/Prithvi/AnySat T4”记录：三个
Clay T4 与三个 Prithvi T4 都在 `ca27c4c` 之后（`1d935a1` / `15c336c`），因此本轮
可见的 stale 计数不变（仍 13 条）。仅有的两条早于修复的 T4 记录是
`smoke-t4-anysat` / `smoke-t4-prithvi`，它们同时还缺 `P0`，本来就是短跑诊断，
不会进入正式结果。该修复防的是历史或回溯的正式记录被误排除。

## P2-2：T3 B0 结论过强且固定输出

**结论：成立，已修复。**

### 事实

原句固定为：

> 论文配置的 Prithvi B0（UPerNet 512、官方类权重）为 0.1558 ± 0.0298（n=3），
> 与轻量头同一水平：T3 的天花板不在头。

两个问题：

1. B0 与 B2 同时改变了三组变量：骨干是否训练（全微调 vs 冻结）、时序输入
   （3 帧 + location 坐标 vs 逐日期统计）、训练配方（UPerNet、官方类权重、
   lr 1e-5）。多变量同时变化，不能把“B0 与 B2 同档”归因于任务头；
2. 句子是硬编码的，即使 B0 明显高于或低于轻量头，也照旧输出同一结论。

### 修复

把说明抽成 `_t3_b0_note(...)`：先按分数计算相对位置（落在区间内 / 高于 / 低于，
并给出差值），再固定附上归因边界。当前输出：

> 论文配置的 Prithvi B0（UPerNet 512、官方类权重、全骨干微调、3 帧 + location
> 坐标）为 0.1558 ± 0.0298（n=3），落在冻结轻量头的 0.1536–0.1766 区间内。但
> B0 相对 B2 同时改变了骨干是否训练、时序输入（3 帧 + location vs 逐日期统计）
> 和训练配方（UPerNet、类权重、lr），多变量同时变化，不能把分差归因于任务头；
> 它只说明该论文配方在本划分上的表现。

回归测试覆盖三种位置（区间内 / 高于 / 低于），并断言不再出现“天花板不在头”。
