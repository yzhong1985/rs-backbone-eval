## 3. 原协议回放判定（已收紧）

原判定确实过宽。现在要求：

```
fingerprint = sha256(sorted(files: blob_sha) + params + env)
```

- `files` 是适配器声明的推理依赖，**同时包含 Python 与 YAML**：生成器、
  worker 的 t9/t10、`detection/*`、`evaluation/segmentation.py`、预处理/数据集读取、
  三份配置；
- `blob_sha` 用 `git rev-parse <run_commit>:<path>` 取原版本，与当前工作树内容哈希比较；
- `params` 是适配器实际使用的完整参数（滑窗、crop/stride、合并、阈值、三阶段 NMS、
  ignore、时相策略），缺键即失败；
- `env` 记录 torch/CUDA/timm 等影响数值的版本与相关环境变量；
- `fingerprint_at_run == fingerprint_now`、工作树干净、`stale_flags` 为空，才允许
  `original_protocol`；
- **后代关系本身不算证据**；文件在该 commit 不存在、参数不全、dirty、环境缺失，
  一律 `reevaluated`，除非显式 `--mode original` 且能补齐全部身份。

`reevaluated` 在 Portal 每张图都带徽标，并保留原审计标记。

## 4. 裁剪与匹配顺序（已写死）

设计的顺序现在明确为：

1. 整景预测（T9 滑窗 + logits 平均；T10 全 tile + 坐标恢复 + 合并 NMS）；
2. **整景匹配**（T10 类别感知贪心 IoU 0.5；T9 整景混淆矩阵）；
3. 保存每个 GT/预测的 `match_id` 与 `status`；
4. **仅为绘图**裁窗口，沿用第 3 步状态；
5. 可选 `window_metrics`，单独字段，不参与分桶。

窗口边界**不产生 ignore**：只有原始无效像素（T9=255）和图外 padding 才按协议忽略。
T10 不是"裁到窗口后重新匹配"。卡片里 `scene_metrics` 与 `window_metrics` 分栏，
分桶一律用 `scene_metrics`。
