## 1. GSD 来源

评审的核查正确：`unzip -l` 确认 DOTA 的 `images/part*.zip` 里**只有 PNG、没有 txt**（`.txt` 计数为 0）；iSAID 的 json 只有 `file_name` / `ins_file_name` / `seg_file_name`，**没有 gsd**。逐图 `gsd` 只在 `labelTxt` 的标注文件里（首行 `imagesource` / `gsd`，部分为 `None`），而我们没有下载那一卷。

**v4 处理**：

- Clay 一律用**固定声明值 1.0 m**，`gsd_source=declared`；
- 若将来需要逐图 GSD，把它作为 **P0-a 可选任务**（下载 `labelTxt-v1.0/labelTxt.zip` 并补进 `catalog.yaml`），本版不依赖。

---

## 2. GSD 错配的范围

v3 只说了 Clay/AnySat，确实低估。v4 在 §2.4 增加「隐含 GSD」列：

| 主干 | 隐含 GSD |
|---|---|
| LIM | 原生（0.3–1 m） |
| Prithvi | **30 m**（HLS 预训练） |
| OlmoEarth | **10 m**（S2 入口） |
| AnySat | **10 m**（S2 入口） |
| Clay | 声明 1.0 m（唯一可显式告知） |

推论改为："**除 LIM 外，四个主干都存在尺度错配，只有 Clay 有一个能显式传 GSD 的入口**。" 这直接决定结论怎么写。

## 3. 已定决策的变更记录

评审指出：`68e5ca1` 记录的 D2 是"用 TerraTorch UPerNetDecoder"，v3 改成了自研，但没标明这是对已定决策的修正。

v4 新增 **§0.1 已定决策与变更记录**，D2 一行写明：实现路径由 TerraTorch 改为 `heads.py` 自研 torch-only UPerNet，原因是 terratorch 把 `nn.BatchNorm2d` 写死（`decoders/utils.py:43`）且只装在 prithvi 环境。§9 第 2 条也加了同样的标注。

## 4. batch 不在 variant_key

确认：`variant_key()` 含 `head_id`，但不含 `tags` 里的 `effective_batch` / `grad_accum`。

**v4 处理**：

- **worker 侧硬校验**：T9 的 `micro_batch × grad_accum ≠ 8` 直接报错退出，不写 `run.json`；
- tags 固定记录三项；
- 若将来要试别的 batch，必须用 `head_id` 后缀（如 `upernet_gn_b4`）区分，否则会被当成同一 variant 平均。

---

## 5. B2U 的可训练部分

确认不对等：Prithvi 需要 3→6 的 1×1 卷积适配器、AnySat 需要 3→10 的光谱适配器；LIM/Clay 不需要（Olmo 只需填充，无参数）。

**v4 处理**：

- 协议取 `train_input_adapter: true`，含义明确为"**入口结构必需时允许适配器**"，不是"每个模型都加"；
- 报告逐主干列出 `可训练参数 = 头 + 适配器`，并注明适配器是结构必需；
- 与现有 B2 的对应：现有 B2 是 `frozen_probe`（无适配器）与 `frozen_adapter`（有适配器）两个协议；**B2U 是一条轨道里的两种形态**，靠 `head_id` 与 `adapter_parameters` 区分，报告按"有无适配器"分组展示。

## 附：P0-a 数据体检初步结果（本轮顺带完成）

| 项 | 结果 |
|---|---|
| 训练 / 验证图数 | 1411 / 458 |

| 切块数（val, 1024/512） | 7,136 |
| 调色板 | 抽样 120 张共 **16 色**，与"15 类 + 背景"吻合 |
| 类别一致率 | 14/15 类 >80%；Harbor 72%、GTF 82%，2 类颜色冲突，需 devkit 复核 |

**结论**：`1024/stride512` 下训练集只有 2 万块，25k 步 ≈ 10 个 epoch 当量，**预算可以按 1024 裁块**，不必退到 512。
