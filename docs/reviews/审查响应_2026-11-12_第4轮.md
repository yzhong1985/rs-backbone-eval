## P1-1 宽头 B 层两臂的 head 初始化与 batch 顺序不一致

**问题**：宽头教师臂在模型之前构建 teacher projector，消耗了全局 RNG，导致
同 seed 下两臂的分类头初始化不同；`DataLoader(shuffle=True)` 又复用被偏移的
全局 RNG，洗牌顺序也不同。这违反了“两臂唯一差别是教师余弦”的前提。

**修复**（`workers/anysat/src/anysat_worker/t11p.py`）：

- 先构建 `AnySatT11P`（含 `self.head`），再构建 `head_projector` /
  `teacher_projector`；教师臂只多一个 teacher projector，head 初始化与标签臂
  使用同一段 RNG 序列。
- 训练循环改用 `_epoch_order(size, seed, epoch)`：显式
  `torch.Generator().manual_seed(1_000 * seed + epoch)`，不再消费全局 RNG。
  探针、蒸馏、B 层共用该 helper。
- 新增 `test_epoch_order_is_seeded_and_reproducible`。

**验证**：CPU smoke 的宽头两臂均完成；`b_stage_teacher_projector` 在标签臂为
`false`、教师臂为 `true`，且两臂 `head` 初始化顺序一致（模型先于 projector）。

## P1-2 全 void 守卫与 B 层累积步数错位

**问题**：

1. `_train_probe` 没有 `labels != IGNORE_INDEX` 守卫；`batch=1` 时全 void patch
   会让 `CrossEntropyLoss(ignore_index=19)` 产生 NaN。
2. B 层用 `enumerate(train_loader)` 的 `step` 判断累积窗口；遇到全 void 的
   `continue` 后 `step` 仍递增，可能在只累积 1 个有效微批时就 step，尾批判断
   也与 `steps % accumulation` 不一致。

**修复**：

- 探针、蒸馏、B 层的每个微批都先检查
  `int((labels != IGNORE_INDEX).sum()) == 0` 并跳过；跳过的微批不增加
  `pending` / `batches`。
- 三个训练循环统一用 `pending`（有效微批数）控制
  `optimiser.step()`，`steps`（优化步数）只用于 `limit` 与日志；
  循环末尾按 `pending` 刷新尾批。
- loss 曲线的分母改为 `batches`（有效微批数），不再用优化步数。

## P1-3 训练/评测 autocast 口径不一致

**问题**：训练用 CUDA bf16 autocast，`_evaluate` 用 fp32，蒸馏/探针/B 层的
评测数值与训练数值路径不一致。

**修复**：`_evaluate` 与 `_evaluate_tokens` 都包在
`torch.inference_mode()` + `torch.autocast(device_type="cuda",
dtype=torch.bfloat16)` 内；探针、B 层、蒸馏验证统一走同一路径。

## P2-4 协议声明与代码实现相反

**问题**：`anysat_t11p_probe_s128` 和 `anysat_t11p_distill_o128` 仍声明
`train_input_adapter: true`，但代码已改为加载并冻结 raw 适配器。

**修复**：两个 YAML 改为 `train_input_adapter: false`；新增
`test_adapter_flags_match_the_shared_adapter_contract`，固定
raw=true、s128/o128/distill=false、B 层=true 的契约。

## P2-5 教师 projector 的 total_parameters 与 train/eval 模式

**问题**：宽头教师臂的 `teacher_projector` 是模型外的局部模块；
`total_parameters` 只用 `model.parameters()`，漏计约 42.6 万参数；
`AnySatT11P.train()` 还会把已冻结的 adapter/projector 重新设为训练态。

**修复**：

- `total_parameters` 在模型参数之外加上独立的 `teacher_projector`；CPU smoke
  中宽头标签臂 126,106,629、教师臂 126,532,997，差值 426,368 即 teacher
  projector。
- `AnySatT11P.train()` 改为
  `self.adapter.train(self.adapter_trainable)`、
  `self.projector.train(any(p.requires_grad ...))`、head 同理；冻结模块保持
  eval。B 层循环显式管理外置 teacher projector 的训练/评测态。

## P2-6 梯度累积下 loss 曲线翻倍

**问题**：探针/蒸馏每个微批累加 `total`，但 `steps` 只在优化步递增，
`total / steps` 在 `accumulation=2` 时约放大 2 倍；B 层又用微批计数的
`steps`，三者口径不一致，epoch 索引也不一致。

**修复**：三个循环都分别维护 `batches`（有效微批）和 `steps`（优化步）；
曲线与 `distill_train_loss` 用 `total / max(batches, 1)`；B 层曲线改用
`epoch + 1`，与探针/蒸馏一致。
