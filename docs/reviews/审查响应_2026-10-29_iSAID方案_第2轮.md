## 1. 各主干的输入路径（新增 §2.4）

v2 只写了"用统一头"，但没写"3 通道 0.3–1 m 的 RGB 怎么进每个主干"，而这恰恰决定客场不利程度。v3 逐主干给出：

| 主干 | 通道 | 元数据 | 金字塔 | 记录 |
|---|---|---|---|---|
| LIM | 原生 3 通道 | 无 | 原生 4 级 | `head_id=upernet_gn` |
| Prithvi | 3→6，1×1 卷积合成 NIR/SWIR（**禁止补零**，沿用 T8） | 不传 | token 抽层 `[5,11,17,23]` | `head_id=upernet_gn+band_adapter` |
| Clay | 3 通道 + 波长 0.48/0.56/0.655 | **GSD**：优先 DOTA 元信息，缺失时按声明默认值 | 8×8 token 抽 4 层 | tags 记 `gsd_source` |
| OlmoEarth | 放入 12 波段张量 B02/B03/B04，其余按 T1 的填充规则 | 无 | 稠密 token 池化 T/BS | tags 记 `filled_bands` |
| AnySat | `s2` 10 波段入口 + 光谱适配器 | **GSD 按 10 m 解释**（T8 已暴露该问题，此处差距更大） | token 展平顺序需逆向（风险最高） | tags 记 `gsd_assumed=10` |

并在文中写明推论：**结果只能读作"各自最自然接入方式下的水平"**，不能读作架构优劣。

## 2. 统一头改为自研（不依赖 terratorch）

评审的两条依据均成立：

- `terratorch/models/decoders/utils.py:43` 是 `self.norm = nn.BatchNorm2d(out_channels)`，写死；
- terratorch 只装在 `workers/prithvi` 环境，其余 worker 没有；而 `heads.py` 是控制层共享模块，不应反向依赖 worker 框架。

v3 改为：在 `src/rs_backbone_eval/heads.py` 增加一份**只依赖 torch** 的 UPerNet（PPM + FPN + 分类头），`norm_layer` 可配置、默认 GroupNorm；`head_id=upernet_gn` 与既有 `upernet_decoder`（B0 的 terratorch 实现）明确区分。

---

## 3. 有效 batch

v2 自相矛盾（§2.2 写 2、§5.3 写 8）。v3 统一：

- **iSAID 单独口径：有效 batch = 8（micro 1 × accum 8）**，所有主干一致；
- 同时在协议与 tags 里写 `micro_batch` / `grad_accum` / `effective_batch` / `norm_layer`。

并撤回 v2 对同事配置的误述：他们是 **SyncBN + batch 12 分布在 6 卡**，BN 统计来自 12 个样本；"单卡等效 batch 2"不准确。这也正是我们单卡不能照搬他们设置、必须改用 GN 的原因。

---

## 4. registry schema

评审指出的约束属实：`ProtocolSpec` 继承 `RegistryModel`，`model_config = ConfigDict(extra="forbid")`（`registry.py:13-14`），`regime` 是 `Literal`，因此 v2 说的"新协议声明 head/batch/BN"写不进去。

v3 §3 给两种做法：

- **A**：扩 schema（加 `head_id` / `norm_layer` / `effective_batch`），同步改 `test_registry`；
- **B（推荐）**：不动 schema，协议只表达轨道，头与 batch 放 `tags`；`variant_key()`（`matrix.py:59`）本就把 `head_id` 编进 key，因此不同头的 run 不会被并成一条。

补充一条 v2 的正确部分：因为 `variant_key` 含 `head_id`，UPerNet 与轻量头**不会混成同一条 run**；但 `_rank()` 仍在同一轨道内按验证分挑 headline，所以**新协议（新轨道）仍然必须**。

## 5. 算力与 GPU 优先级

- 按迭代数重算：25k 步 × 有效 batch 8 = **20 万样本**；若吞吐 1 张/秒 → **≈2.3 天/种子**；LIM 三种子 ≈7 天；5 主干 × 3 种子 ≈**35 天**（单卡）。
- 新增 §5.2：第一轮只做 **B2U + LIM + 1 个种子**（exploratory），先拿到真实吞吐与第一个数字。
- 新增 §5.3 GPU 优先级：P0-b 必须等 4090 空出（T4 DEM 预计 15:10 结束），**不能与它并行**；iSAID 与 T1S/T8 补跑抢同一张卡，需明确先后。
- §9 增加两条决策项（优先级、范围）。
