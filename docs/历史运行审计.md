## 1. 目的与方法

新增外部模型（OlmoEarth Tiny 等）要有**同口径的对照**。本审计逐条核对历史运行是否满足当前协议，回答"哪些对照可以复用、哪些必须重跑"。

**判据**：只看**会改变存储指标值**的修复；仅改聚合/报告口径的修复不计入（重跑报告即可）。

**判定方式（关键）**：

1. **用 Git 祖先关系，不用提交时间。** 仓库中 `1445a0b` 与后续修复具有相同提交时间，按时间判断会把修复前的代码判为合格；脚本用 `git merge-base --is-ancestor` 逐条核对（`-dirty` 后缀按基础提交核对）。
2. **逐条判定，不按组汇总。** 同组里一条最新记录 + 一条无版本记录，**不会**被判为"满足"；无代码版本的记录一律计为"无法判定"，单独列出。
3. **各路径必需修复不同**：B0 需要 `ea9e8a4`；T3/T5 需要 `ea9e8a4`；Prithvi/Clay T5 再加 `3b4460a`；Prithvi 冻结 T1/T2/T3 与 Clay 冻结 T3 加 `35a972e`。
