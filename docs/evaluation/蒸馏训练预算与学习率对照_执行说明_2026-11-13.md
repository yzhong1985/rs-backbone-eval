# 蒸馏路线：训练预算与学习率敏感性对照（执行说明，交给 agent）

- 日期：2026-11-13
- 背景：`docs/design/AEF_Feature_Encoder_阶段结论_2026-11-13.md`。到目前为止所有 T11D / T11P
  学生实验都用同一套固定配方：**8 epoch、学习率恒定（头/投影器 3e-3，B 层主干 1e-4）、
  没有 warmup 和衰减、没做过学习率或轮数搜索**。8 epoch 是沿用 T11O 教师探针的口径，
  不是为学生调出来的。
- 从 run.json 的训练曲线看（seed 17）：
  - 蒸馏投影器已收敛（OE64 余弦 val cosine 0.9534 → 0.9554 → 0.9554）；
  - 冻结探针接近收敛（训练 loss 每轮降 0.01～0.02）；
  - **B 层宽头明显没收敛**（Clay T11D 最后三轮 0.503 → 0.466 → 0.416；T11P 三个主干每轮
    仍降 0.045～0.06）；
  - **10% 标签 B 层训练量严重不足**：每 epoch 只有约 73 步，8 epoch 约 580 步，只有全量的 1/10。
- 目的：确认两条核心结论在“训够了 / 换学习率”时是否仍然成立：
  1. 冻结蒸馏读出不超过原始特征（预计不受影响）；
  2. B 层加教师项约等于 0；10% 标签时教师有害（**受影响较大**）。
- 全部是诊断（`panel: diagnostic` 或 `label_fraction` panel），不进 headline / scorecard / Portal。

## 1. 共同的训练配方改动

新增一个**显式的配方开关**，只对本说明的新协议生效；已有协议的配方逐行不变。

| 项 | 已有协议（不变） | 本说明的新协议 |
|---|---|---|
| epoch | 8 | 由协议 YAML 的 `epochs` 声明（见各节） |
| 学习率调度 | 恒定 | **1 epoch 线性 warmup + 余弦衰减到 0**（按优化器 step 计算） |
| 主干学习率（B 层） | 1e-4 | 由协议声明（`backbone_learning_rate`），默认 1e-4 |
| 头/投影器学习率 | 3e-3 | 3e-3（不变） |
| 选 epoch 规则 | 各自原规则 | **一律取最后一个 epoch**（B 层、探针）；蒸馏投影器仍按原规则 |
| 每个 epoch 记录 | 训练 loss | 训练 loss、当前学习率；B 层另记 **validation mIoU**：24 epoch 的协议每 4 个 epoch 一次，80 epoch 的协议每 10 个 epoch 一次（只记录，不用于选择） |

实现要求：

- 调度用 `torch.optim.lr_scheduler.LambdaLR`，step 数按实际优化器步数算
  （B 层：每 2 个 patch 一步；10% 标签时步数相应变少）。
- 配方名写进 tags：`lr_schedule="warmup1-cosine"`、`schedule_total_steps`、
  `schedule_warmup_steps`。旧协议写 `lr_schedule="constant"`（只加 tag，不改计算；
  如果加 tag 需要改旧路径代码，确认数值不变即可，不加 audit fix）。
- **每对比较的两臂必须用同一套调度、同一 epoch、同一学习率**；差别只有“是否有教师项”。
- 中间 validation 评测会增加时间（验证集 482 张，比 10% 训练集大 3 倍多），所以按上表的间隔
  做，不要每个 epoch 都评。

## 2. 实验清单（按优先级）

### P1. 10% 标签 B 层，按步数对齐（必须做）

问题：标签少时教师有害（Clay T11D −0.021），是不是只因为没训够？

- 主干：**Clay，T11D**（与原 10% 结论同一设置，可直接对照）。
- 读出：与原 10% 实验相同的 **128 维 B 层**（`clay_rgbn_ft_last4_v1` / `clay_rgbn_ft_last4_distill_v1`
  的配方），manifest 用 `/geodata/rs-eval/data/manifests/T11D_subsets/10pct-groups.jsonl`，
  `RS_EVAL_LABEL_FRACTION=0.1`。
- **epoch = 80**（146 个 patch × 80 ≈ 5,840 步，与全量 8 epoch 的步数基本相同）。
- 两臂：仅标签 / + 教师（OE128，权重 1.0 不变）。
- 3 个种子；run id 后缀 `-lf10-e80`。
- 新协议：`clay_rgbn_ft_last4_e80` / `clay_rgbn_ft_last4_distill_e80`（`panel: diagnostic`，
  `epochs: 80`，`train_backbone: true`）。

**附加臂（建议一起做，同一批代码）：半监督设置**，即“标签只用 146 个，教师用全部 1455 个”。

- 新协议 `clay_rgbn_ft_last4_distill_semi_e80`。
- 实现：训练集用 **完整 T11D manifest**（1455 行），同时读取 10% 子集 manifest 的 sample_id 作为
  “有标签集合”；有标签的 patch 计算 `标签损失 + 教师损失`，其余 patch **只计算教师损失**。
  有标签集合由环境变量 `RS_EVAL_LABELED_IDS=<子集 manifest 路径>` 声明，写进 tags
  （`labeled_ids_manifest`、`labeled_samples=146`、`teacher_samples=1455`）。
- 步数对齐方式：**有标签 patch 的访问次数与 P1 主臂相同**。每个 epoch 按固定种子打乱
  146 个有标签 patch，**每个有标签 patch 后面紧跟 k 个无标签 patch**（从 1309 个无标签
  patch 中按 `torch.Generator().manual_seed(1_000 * seed + epoch)` 无放回轮流抽取，
  多个 epoch 合起来覆盖全部 1309 个），跑 80 epoch。
- **k = 1**（固定，写进协议和 tags `semi_unlabeled_per_labeled=1`）。k 越大越贵，k=1 时
  单条耗时约为主臂的 2 倍；80 epoch × 146 × 1 ≈ 11,700 个无标签访问，覆盖每个无标签
  patch 约 9 次。
- 有效 batch 仍为 2：按顺序每 2 个 patch（有标签或无标签都算）做一次优化器步。无标签
  patch 只贡献教师损失；一个步里两个 patch 的损失按 patch 平均。
- 这一臂只和 P1 的“仅标签”臂比较（同种子配对）。
- **标签损失绝不能读到 146 个以外的标签**：加单测，构造一个无标签 patch 的标签全为某个哨兵值，
  断言训练过程中它从未被送进交叉熵。

### P2. B 层宽头 24 epoch（T11P，三个主干）

问题：训够以后，宽头 B 层上的教师项是否仍约等于 0？

  `clay_s2six_ft_last4_raw1024(_distill)_e24`、
  `prithvi_t11p_ft_last4_raw1024(_distill)_e24`、
  `anysat_t11p_ft_last3_wide(_distill)_e24`。`epochs: 24`，调度见 §1。
- 3 个种子；manifest 为 T11P 主 manifest；run id 后缀 `-e24`。
- AnySat：适配器指纹包含 budget（`e24-…`），每个种子先跑一次 `anysat_t11p_probe_raw` 的
  `_e24` 版本发布适配器（新协议 `anysat_t11p_probe_raw_e24`，epochs 24），再跑 B 层。
  **AnySat 这一对耗时最长（约 6.6 h），放在 lane 最后；如果时间紧可以只跑 seed 17**，
  在结果里写明 n=1。

### P3. B 层主干学习率小扫描（Clay T11P 宽头，单种子）

问题：教师项是否对主干学习率敏感？

- 主干学习率 `3e-5`、`1e-4`、`3e-4` × 两臂（仅标签 / + 教师），**seed 17**，**24 epoch**
  （和 P2 同配方，其中 `1e-4` 那组可直接复用 P2 的 seed 17，不重跑）。
- 新协议：`clay_s2six_ft_last4_raw1024(_distill)_e24_blr3e5`、`…_blr3e4`。

### P4. 冻结探针 20 epoch（Clay T11D）

问题：冻结读出的排序（原始 ≈ S64 > O64 > A64 > PCA64）会不会因训够而改变？

- 协议：`clay_rgbn_probe_{raw,s64,o64}_e20`（`epochs: 20`，调度见 §1）。
  O64 探针复用已有的余弦投影器（不重新蒸馏）。
- 3 个种子。

## 3. 预先声明的判据（跑之前写死）

所有比较按**同一种子配对**，报告每个种子和配对均值。

| 实验 | 比较 | 判定 |
|---|---|---|
| P1 | （+ 教师）−（仅标签），80 epoch | ≤ −0.01 且 3/3 为负：维持“标签少时教师有害”，并去掉“可能只是没训够”的保留意见。在 ±0.01 内：改为“训够后约等于 0”。≥ +0.01 且 3/3 为正：改为“训够后有帮助”，**修改阶段结论 §3.3** |
| P1 半监督 | （半监督）−（仅标签） | 同上三档。≥ +0.01 且 3/3 为正，是整条路线里第一个正面信号，需要在 T11P 上复核后再写结论 |

**结论（按 §3 判据）**：80 epoch 后配对差均值 **+0.0021**，三个种子符号翻转

应彻底改为"标签少时教师项约等于 0，符号随种子波动"。这与 T11P 宽头 10%
（−0.003 / +0.009 / +0.008）方向一致。

说明 146 个 patch 上继续训练已在过拟合；test 的提升（0.2202 → 0.2403）与验证曲线不同向，
按已知的 split 组泄漏，只能当作"长预算下教师项不显著"的证据，不能当作"训练越久越好"。

## P4. 冻结探针 20 epoch（Clay T11D）

| 读出 | s17 | s42 | s73 | 均值 ± pstdev | 8 epoch 均值 | 20 − 8 |
|---|---:|---:|---:|---:|---:|---:|
| 原始 1024 维 | 0.3372 | 0.3111 | 0.3398 | 0.3294 ± 0.0127 | 0.3185 | +0.0109 |
| **S64（标签监督 E）** | **0.3672** | **0.3719** | **0.3845** | **0.3745 ± 0.0072** | 0.3174 | **+0.0571** |
| O64（余弦蒸馏） | 0.3001 | 0.3051 | 0.3091 | 0.3048 ± 0.0037 | 0.3010 | +0.0038 |

**结论（按 §3 判据）**：O64 仍低于原始特征（3/3 配对为负），**排序不变**，不改阶段结论
§3.1 的"蒸馏不如原始特征"。但这一组暴露了一个更重要的事实：

- **8 epoch 的 S64（0.3174）本身没训够**：同样协议 20 epoch 就到 0.3745（3/3 +0.05 以上），
  远超所有冻结读出，包括 InfoNCE 的 0.3340（8 epoch 探针）。
- 冻结读出（原始 +0.011、O64 +0.004）几乎不随探针预算变化，**只有"E 与头联合训练"的
  S64 会随预算大幅上升**。所以"冻结特征饱和"与"可学习读出还能涨"必须分开说。
- 因此原先把 NCE 的 0.334 与 8 epoch S64 的 0.317 相比、写成"超过标签监督"是**错的**
  参照：在 20 epoch 预算下 S64 = 0.3745，NCE 的 8 epoch 探针（0.3340）低于它 0.041。
  NCE 探针在 8 epoch 时仍在涨（无 epoch 选择，取最后一轮），所以补了 `T11DNCE20`
  （`clay_rgbn_probe_o64_nce_e20` / `_a64_nce_e20`，6 条）做同预算比较，结果见下节。

- **NCE − 原始特征**：+0.0117 / +0.0357 / +0.0092，**3/3 为正，均值 +0.0188**。
- **NCE − 标签监督 S64**：−0.0184 / −0.0251 / −0.0354，**3/3 为负，均值 −0.0263**。
- **NCE − 余弦 O64**：+0.0434（逐种子 +0.0487 / +0.0416 / +0.0400）。

**结论**：

1. **对比学习蒸馏是唯一在同等读出预算下稳定超过原始特征的蒸馏方式**
   （+0.019，3/3 为正；余弦 O64 反而低于原始特征 0.004）。这一条把阶段结论里
   §3.1 第 4 条恢复到"正面"，但**必须写明是 20 epoch 预算、且只超过原始特征 0.019**。
2. **但它没有超过标签监督**：S64 在 20 epoch 下 0.3745，比 NCE 高 0.026（3/3 为负）。
   所以"对比学习超过 S64"这个说法只在"8 epoch 的 S64 自己没训够"的前提下成立，
   **正式收回**；正确的写法是"冻结蒸馏读出的排序为 S64 > NCE(OE64) > NCE(AEF64) >
   原始 > 余弦 O64"。
3. 8 epoch → 20 epoch 的增益：NCE +0.014～0.015、原始 +0.011、余弦 O64 +0.004、
   **S64 +0.057**。冻结读出（含蒸馏）在 8 epoch 已接近饱和，只有"E 与头联合训练"的
   S64 还在显著上涨 —— 这解释了为什么 8 epoch 时 NCE 看起来"超过标签监督"。
