# T11P：六波段 Clay/Prithvi/AnySat 匹配对（设计与运行口径）

日期：2026-11-12
状态：Clay/Prithvi 三 seed 已完成；AnySat 已实现并通过 CPU smoke，正式三 seed 待排。

## 1. 要回答的问题

四波段（T11D）的结论是“冻结读出的上限约 0.32，瓶颈在冻结主干与 80 m 时间
均值，而不是四波段输入没有信息”。这条结论只覆盖 Clay 一个主干。T11P 把同一
个教师读出实验放到 **Prithvi-EO-2.0 300M** 上，并要求两个主干共享输入预算：

| 项 | T11D（已有） | T11P（本任务） |
|---|---|---|
| 波段 | B02/B03/B04/B08（Clay 原生 4 波段） | B02/B03/B04/B8A/B11/B12（Prithvi 原生 6 波段） |
| 帧数 | 2019 年 20 期 | 2019 年 4 期 |
| 标签 | PASTIS-HD，20 类，void=19 忽略 | 同左 |
| 样本 | 1455 / 482 / 496 | 同左（同 patch、同 group） |

T11P **不并入 T11D 的 cell**：时间预算不同（4 vs 20 期）。T11P 内部 Clay、
Prithvi 与 AnySat 使用完全相同的 6 波段、4 期、标签和读出协议，因此可以在同一
track 内横比。AnySat 额外需要一个 6→10 波段适配器（原生 S2 入口固定十波段），
这是它自己的输入适配预算，单独在 run tags 中声明。

## 2. 输入与 manifest

- 原始 payload：`derived/aef-2019/PASTIS-HD/DATA_S2/S2_<patch>.npy`，形状
  `(T, 10, 128, 128)`，int16 原始 DN；
- 列选择：PASTIS S2 顺序 `B2,B3,B4,B5,B6,B7,B8,B8A,B11,B12` → 取
  `0,1,2,7,8,9`；
- 日期：sidecar `dates_s2`，只保留 2019，按日期均匀取 4 期（与 T11D 共用
  `select_2019_frames`）；
- manifest：`uv run rs-eval build-manifest --task T11P`，当前
  `3155a8c5e4dc5c005037b0b41e261530c3eb85d48358c118e67f689ff0d6fb96`，
  2433 行，test 496 / validation 482 / train 1455，audit 0 error。

PASTIS 没有经纬度，Prithvi 的位置元数据按零填充，已在每个 run 的 tags 声明。

## 3. 读出协议（两个主干完全一致）

| track | 协议（Clay / Prithvi） | 读出 |
|---|---|---|
| B6R | `clay_s2six_probe_raw` / `prithvi_t11p_probe_raw` | 冻结主干的原始 token，时间均值，1×1 conv 头 |
| B6S | `clay_s2six_probe_s128` / `prithvi_t11p_probe_s128` | 同一头 + 可训练 E(1024→128)，用标签联合训练 |
| B6O | `clay_s2six_probe_o128` / `prithvi_t11p_probe_o128` | 冻结的 OlmoEarth128 蒸馏投影器 E |
| B6F | `clay_s2six_ft_last4` / `prithvi_t11p_ft_last4` | 末 4 个 transformer block + E + 头，仅标签 |
| B6D | `clay_s2six_ft_last4_distill` / `prithvi_t11p_ft_last4_distill` | 同上 + 1.0×(1−cos(E, OE128 教师)) |
| B6R/B6S/B6O | `anysat_t11p_probe_{raw,s128,o128}` | AnySat 也使用同一读出定义；区别是输入先经 6→10 适配器 |
| B6FA | `anysat_t11p_ft_last3` | AnySat 末 3/6 个 spatial block + 适配器 + E + 头，仅标签 |
| B6DA | `anysat_t11p_ft_last3_distill` | 同上 + OE128 教师余弦 |

投影器先由 `clay_s2six_distill_o128` / `prithvi_t11p_distill_o128` 训练：
- Clay：16×16 token（80 m），教师按 8×8 均值聚合；
- Prithvi：14×14 token（224 px 输入 / patch 16），教师从 128 px 网格自适应
  平均到 14×14；
- 两个投影器都只在该主干自己的 token 空间训练，路径按 checkpoint + manifest +
  task + 波段 + 帧数 + seed 的指纹区分，不能互换。

### 3.1 AnySat 的输入适配与 B 层预算

- AnySat 的 `s2` 入口固定 10 波段（B2,B3,B4,B5,B6,B7,B8,B8A,B11,B12），T11P
  只给 6 波段；使用 `SpectralAdapter` 显式学习缺失的 4 个波段（1,610 参数），
  禁止零填充。已存在的 6 个波段通过残差直通，网络只合成缺失波段。
- **适配器只训练一次**：`anysat_t11p_probe_raw` 用标签联合训练适配器 + 头，
  并把适配器发布到按 checkpoint + manifest + seed + 归一化 + epoch 预算的指纹
  目录（`adapter_raw.pt`）。后续探针与蒸馏都加载这同一份适配器并冻结，所以
  raw / S128 / O128 三者的特征提取完全一致，只差 E 和头；1 epoch 的 smoke
  适配器不会进入正式指纹。
  - `raw`：适配器 + 头联合训练，主干冻结；
  - `s128`：冻结适配器 + 可训练 E(1536→128) + 头；
  - `o128`：冻结适配器 + 由 `anysat_t11p_distill_o128` 训练并冻结的 E，只训练头。
- `anysat_t11p_distill_o128` 只训练 E（适配器冻结），所以 E 学到的是同一份
  学生特征上的教师方向，探针再冻结 E 与适配器。
- B 层两个 arm 都从同一份 raw 适配器初始化，适配器保持可训练；因此有/无教师
  的唯一差别仍是教师余弦。
- B 层预算：AnySat Base 只有 6 个 spatial block，每块约 7.08M 参数。末 **3/6**
  块 + final norm 约 21.3M，占 126M 总参数的 16.9%，与 Clay/Prithvi 末 4/24
  块（约 50.7M / 311M、16.3–16.7%）的参数份额接近。块数是 50% 深度，和
  Clay/Prithvi 的 17% 深度不同，所以 B 层单独成轨（B6FA/B6DA），不与 B6F/B6D
  平均。
- AnySat 的 token 网格是 16×16（80 m），与 Clay 同网格；教师同样自适应平均到
  16×16。

## 4. 计算口径

- 有效 batch 固定 2 patch：Prithvi 用 `PRITHVI_WORKER_BATCH_SIZE=1` +
  `PRITHVI_WORKER_GRAD_ACCUM=2`；Clay 用 batch 2。
- epoch = 8（T11P 官方预算，与 T11D 探针/B 层一致）。
- Prithvi 冻结读出使用 token 缓存：首次编码 2433 patch × 4 帧，之后 raw / S128 /
  O128 / distill 共用；缓存目录
  `RS_EVAL_CACHE_ROOT/pastis-t11p/prithvi/features/<fingerprint>/`。
- 224 px 输入是预训练位置网格的要求；标签仍在 128 px 网格上计算，logits 双线性
  上采样，不把 224 px 当成新的 10 m 观测。
- 成本估计（单 4090，串行）：Clay 首次 token 缓存约 8 min；Prithvi 首次特征缓存
  约 10 min；之后每个探针 run 主要是头训练；B 层 6 个 run 约 2–3 h。完整匹配对
  约 4–5 h GPU。

## 5. 必须与数字一起读的限制

- Prithvi 预训练是 HLS 6 波段；PASTIS 是 S2 L2A，波段中心接近但不是同一传感器
  （B8A≈NIR_NARROW、B11≈SWIR_1、B12≈SWIR_2）。
- 4 期 vs 20 期是不同时间预算；T11P 结果不能与 T11D 拼排名。
- **AnySat 的预训练语料包含 PASTIS-HD**。因此 AnySat 在 T11P 上的分数不是
  “完全未见任务”的泛化证据；报告与 run tags 都带 `pretraining_overlap` 声明。
- AnySat 需要学习 6→10 适配器，Clay/Prithvi 不需要；同 track 比较的是“同任务、
  同输入预算下的读出”，AnySat 的适配器是它自己的输入预算。
- Clay 的 token 网格是 16×16（80 m），Prithvi 是 14×14（224 px 输入下约 114 m
  名义支持）；同一 track 比较的是“同输入预算下的读出”，不是同空间支持。
- 教师仍是 PASTIS 年度 AEF/OlmoEarth；T11P 只改变学生输入和主干，不改变教师。
- 正式 run 必须固定 T11P manifest、从干净提交 dispatch；smoke 使用
  `PRITHVI_WORKER_LIMIT_BATCHES` / `PRITHVI_WORKER_EVAL_LIMIT`，不会进入矩阵
  （test 样本数不足 496）。

## 6. AnySat 命令

```bash
export RS_EVAL_MANIFEST=/geodata/rs-eval/data/manifests/T11P/3155a8c5e4dc5c005037b0b41e261530c3eb85d48358c118e67f689ff0d6fb96.jsonl
export ANYSAT_T11P_BATCH=1 ANYSAT_T11P_ACCUM=2   # 有效 batch 2

# 先 raw（训练并发布 6->10 适配器），再蒸馏 E，最后是 S128/O128 探针
uv run rs-eval dispatch --task T11P --model anysat_base --protocol anysat_t11p_probe_raw --action train --seed 17
uv run rs-eval dispatch --task T11P --model anysat_base --protocol anysat_t11p_distill_o128 --action train --seed 17
uv run rs-eval dispatch --task T11P --model anysat_base --protocol anysat_t11p_probe_s128 --action train --seed 17
uv run rs-eval dispatch --task T11P --model anysat_base --protocol anysat_t11p_probe_o128 --action train --seed 17

# B 层配对
uv run rs-eval dispatch --task T11P --model anysat_base --protocol anysat_t11p_ft_last3 --action train --seed 17
uv run rs-eval dispatch --task T11P --model anysat_base --protocol anysat_t11p_ft_last3_distill --action train --seed 17
```
