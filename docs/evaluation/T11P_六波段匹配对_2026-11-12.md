# T11P：六波段 Clay/Prithvi 匹配对（设计与运行口径）

日期：2026-11-12
状态：任务/协议/manifest 已注册；Clay 探针已通过；正式 run 待排。

## 1. 要回答的问题

四波段（T11D）的结论是“冻结读出的上限约 0.32，瓶颈在冻结主干与 80 m 时间
均值，而不是四波段输入没有信息”。这条结论只覆盖 Clay 一个主干。T11P 把同一
个教师读出实验放到 **Prithvi-EO-2.0 300M** 上，并要求两个主干共享输入预算：

| 项 | T11D（已有） | T11P（本任务） |
|---|---|---|
| 波段 | B02/B03/B04/B08（Clay 原生 4 波段） | B02/B03/B04/B8A/B11/B12（Prithvi 原生 6 波段） |
| 帧数 | 2019 年 20 期 | 2019 年 4 期 |
| 标签 | PASTIS-HD，20 类，void=19 忽略 | 同左 |
| 样本 | 1455 / 482 / 496 | 同左（同 patch、同 group） |

T11P **不并入 T11D 的 cell**：时间预算不同（4 vs 20 期）。T11P 内部 Clay 与
Prithvi 使用完全相同的 6 波段、4 期、标签和读出协议，因此可以在同一 track 内
横比。

## 2. 输入与 manifest

- 原始 payload：`derived/aef-2019/PASTIS-HD/DATA_S2/S2_<patch>.npy`，形状
  `(T, 10, 128, 128)`，int16 原始 DN；
- 列选择：PASTIS S2 顺序 `B2,B3,B4,B5,B6,B7,B8,B8A,B11,B12` → 取
  `0,1,2,7,8,9`；
- 日期：sidecar `dates_s2`，只保留 2019，按日期均匀取 4 期（与 T11D 共用
  `select_2019_frames`）；
- manifest：`uv run rs-eval build-manifest --task T11P`，当前
  `3155a8c5e4dc5c005037b0b41e261530c3eb85d48358c118e67f689ff0d6fb96`，
  2433 行，test 496 / validation 482 / train 1455，audit 0 error。

PASTIS 没有经纬度，Prithvi 的位置元数据按零填充，已在每个 run 的 tags 声明。

## 3. 读出协议（两个主干完全一致）

| track | 协议（Clay / Prithvi） | 读出 |
|---|---|---|
| B6R | `clay_s2six_probe_raw` / `prithvi_t11p_probe_raw` | 冻结主干的原始 token，时间均值，1×1 conv 头 |
| B6S | `clay_s2six_probe_s128` / `prithvi_t11p_probe_s128` | 同一头 + 可训练 E(1024→128)，用标签联合训练 |
| B6O | `clay_s2six_probe_o128` / `prithvi_t11p_probe_o128` | 冻结的 OlmoEarth128 蒸馏投影器 E |
| B6F | `clay_s2six_ft_last4` / `prithvi_t11p_ft_last4` | 末 4 个 transformer block + E + 头，仅标签 |
| B6D | `clay_s2six_ft_last4_distill` / `prithvi_t11p_ft_last4_distill` | 同上 + 1.0×(1−cos(E, OE128 教师)) |

投影器先由 `clay_s2six_distill_o128` / `prithvi_t11p_distill_o128` 训练：
- Clay：16×16 token（80 m），教师按 8×8 均值聚合；
- Prithvi：14×14 token（224 px 输入 / patch 16），教师从 128 px 网格自适应
  平均到 14×14；
- 两个投影器都只在该主干自己的 token 空间训练，路径按 checkpoint + manifest +
  task + 波段 + 帧数 + seed 的指纹区分，不能互换。

## 4. 计算口径

- 有效 batch 固定 2 patch：Prithvi 用 `PRITHVI_WORKER_BATCH_SIZE=1` +
  `PRITHVI_WORKER_GRAD_ACCUM=2`；Clay 用 batch 2。
- epoch = 8（T11P 官方预算，与 T11D 探针/B 层一致）。
- Prithvi 冻结读出使用 token 缓存：首次编码 2433 patch × 4 帧，之后 raw / S128 /
  O128 / distill 共用；缓存目录
  `RS_EVAL_CACHE_ROOT/pastis-t11p/prithvi/features/<fingerprint>/`。
- 224 px 输入是预训练位置网格的要求；标签仍在 128 px 网格上计算，logits 双线性
  上采样，不把 224 px 当成新的 10 m 观测。
- 成本估计（单 4090，串行）：Clay 首次 token 缓存约 8 min；Prithvi 首次特征缓存
  约 10 min；之后每个探针 run 主要是头训练；B 层 6 个 run 约 2–3 h。完整匹配对
  约 4–5 h GPU。

## 5. 必须与数字一起读的限制

- Prithvi 预训练是 HLS 6 波段；PASTIS 是 S2 L2A，波段中心接近但不是同一传感器
  （B8A≈NIR_NARROW、B11≈SWIR_1、B12≈SWIR_2）。
- 4 期 vs 20 期是不同时间预算；T11P 结果不能与 T11D 拼排名。
- Clay 的 token 网格是 16×16（80 m），Prithvi 是 14×14（224 px 输入下约 114 m
  名义支持）；同一 track 比较的是“同输入预算下的读出”，不是同空间支持。
- 教师仍是 PASTIS 年度 AEF/OlmoEarth；T11P 只改变学生输入和主干，不改变教师。
- 正式 run 必须固定 T11P manifest、从干净提交 dispatch；smoke 使用
  `PRITHVI_WORKER_LIMIT_BATCHES` / `PRITHVI_WORKER_EVAL_LIMIT`，不会进入矩阵
  （test 样本数不足 496）。
