## 3. 实现

### 3.1 A. MSE 蒸馏

**T11D（Clay）**：完全按 `T11D_MSE蒸馏对照_实验说明_2026-11-13.md` §4 实现（4 个协议，12 条 run）。

**T11P（三个主干）**：同样的做法，教师换成 OE128：

| 主干 | 新蒸馏协议 | 新探针协议 | 新 target |
|---|---|---|---|
| Clay | `clay_s2six_distill_o128_mse` | `clay_s2six_probe_o128_mse` | `oe128mse` |
| Prithvi | `prithvi_t11p_distill_o128_mse` | `prithvi_t11p_probe_o128_mse` | `oe128mse` |
| AnySat | `anysat_t11p_distill_o128_mse` | `anysat_t11p_probe_o128_mse` | `oe128mse` |

要点（三个 worker 一致）：

- 新 target 名指向同一个教师树 `olmoearth-2019-128`、128 维；投影器发布路径因 target 名不同而独立，
  **不会覆盖** `oe128`。
- 损失：未列入 `DISTILL_LOSS` 的协议保持原来的 `1 − cos`，一行不动；MSE 组用逐维平方误差、
  不做长度归一化、在 token 有效掩膜上取平均（`_masked_mse`）。
- 验证集同时记录 val cosine 和 val MSE；MSE 组按 val MSE 最小选最佳 epoch。
  `distill_loss`、`distill_selection` 写进 tags；`writer.complete` 的说明文字按实际损失写。
- 探针的 `distilled` 分支按 target 名加载投影器，确认 `projector_source_path` 指向 `oe128mse`。
- **AnySat 特有**：蒸馏和探针都依赖同种子、同预算的共享 6→10 输入适配器（由
  `anysat_t11p_probe_raw` 发布，指纹含 budget）。100% 标签的适配器已经存在（v3），
  正常应能直接找到；找不到说明指纹不一致，**停下来排查，不要自行重训适配器**。
- 每个新 target 请顺便记录“平均箭头”基线（训练集教师 token 平均向量对验证集的 cosine / MSE），
  写进 tags `mean_baseline_val_cosine` / `mean_baseline_val_mse`。T11D 的参考值见 T11D 说明 §3。

### 3.2 B. PCA128 探针（T11P）

| 主干 | 新探针协议 | 输入 |
|---|---|---|
| Clay | `clay_s2six_probe_pca128` | 1024 维时间均值 token |
| Prithvi | `prithvi_t11p_probe_pca128` | 1024 维 token（缓存的冻结特征） |
| AnySat | `anysat_t11p_probe_pca128` | 1536 维 token，**经过共享适配器**（和 S128/O128 读出同一输入） |

- 用 128 维，和 T11P 的 S128 / O128 同维度。
- Clay 的 `_fit_pca` 把 64 写死了，改成参数（保持 `pca64` 路径的结果不变）。Prithvi / AnySat
  移植同样的做法：**只用训练集** token 拟合（中心化 + 协方差特征分解 + 取前 128 个方向 +
  符号规范化），验证集和测试集只做投影。
- PCA 之后接和其他探针相同的分类头和训练配方。
- 写入 tags：`pca_components=128`、`pca_explained_variance`；把 `pca_mean.npy` /
  `pca_components.npy` 存进 run 目录并登记为 artifact，和 Clay T11D 一致。

### 3.3 C. 10% 标签宽头 B 层（T11P）

**协议不新增**：沿用现有宽头协议，通过 label fraction panel 区分：

| 主干 | 仅标签 | + 教师 |
|---|---|---|
| Clay | `clay_s2six_ft_last4_raw1024` | `clay_s2six_ft_last4_raw1024_distill` |
| Prithvi | `prithvi_t11p_ft_last4_raw1024` | `prithvi_t11p_ft_last4_raw1024_distill` |
| AnySat | `anysat_t11p_ft_last3_wide` | `anysat_t11p_ft_last3_wide_distill` |

步骤：

1. **10% 子集 manifest**：用和 Clay T11D 10% 实验**完全相同的 146 个训练样本**。
   - 来源：`/geodata/rs-eval/data/manifests/T11D_subsets/10pct-groups.jsonl` 里 `split=train` 的
     `sample_id`（已核对：146 个全部在 T11P 训练集里）。
   - 从 T11P manifest 中保留这 146 个训练样本和全部 validation（482）/ test（496），写到
     `/geodata/rs-eval/data/manifests/T11P_subsets/10pct-groups-from-T11D.jsonl`。
   - 生成脚本放 `scripts/`，带单测（CPU、`tmp_path`），在脚本和本文件结果节里记录
     来源 manifest 的 sha256 和新文件的 sha256。不要改 T11P 主 manifest。
2. **放开训练集大小门槛**：
   - Prithvi `t11p.py:635`、AnySat `t11p.py:695` 现在要求训练集 ≥ 1200 行。改成和 Clay
     `_minimum_train_rows()` 一样：只有声明了 `RS_EVAL_LABEL_FRACTION` 时才允许少于 1200 行；
     没声明时门槛不变。加测试。
3. **归一化统计量**：Prithvi / AnySat 都从当前训练集计算（`channel_statistics(train_rows, …)`），
   用子集 manifest 时自然只用这 146 个样本，**这是预期行为**（模拟“只有这么多数据”）。
   确认 Prithvi 的 `normalization_digest` 会随之变化，因而投影器 / 缓存指纹不会和 100% 的混用；
   AnySat 的缓存键已包含子集摘要。
4. **AnySat 的输入适配器**：B 层要加载同预算的共享适配器，而 10% 的预算签名
   （`e8-n146-…`）和 100% 不同。所以每个种子要**先跑一次 10% 的 `anysat_t11p_probe_raw`** 来发布适配器，
   再跑两条宽头 B 层。
5. **教师项**：+ 教师臂仍读取这 146 个样本对应的 OE128 教师 token，不读 validation/test 的教师。
6. run id 统一加 `-lf10` 后缀，例如
   `prithvi_eo_v2_300_tl-T11P-prithvi_t11p_ft_last4_raw1024-train-42-lf10`。
   确认 run.json 里 `tags.label_fraction = "0.1"`，`train_samples = 146`，test 496/496。
7. 三个种子用同一个子集（与 T11D 一致）；子集的随机性不在本实验考察范围内。

注意：Clay T11D 的 10% 实验用的是 **128 维** B 层，本轮 T11P 用的是 **宽头** B 层，
跨任务只比方向，不比数值。

  汇总里的“N 条失败”可能包含跳过的 run。可以另开一个提交修复（**lane 不在跑时**），
