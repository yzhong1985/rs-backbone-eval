日期：2026-10-30  
触发：上级看到同事报告里的 iSAID **71.04 mIoU**，问我们 `mean_iou=0.4873` 为什么差 22 点。  
结论：**不是口径问题，也不是解码器问题**；差异来自"冻结 vs 全量微调、训练预算、测试增强、主干预训练"四件事的叠加。
本文记录核查过程与数字，便于以后复用，不必重新讨论。

## 3. 外部结果的配置核查

代码位置：`/home/yzhong/projects/rs_segmentation`，配置
`downstream/segmentation/config/isaid/spnet_mit_mona.yaml`。

| 项 | 外部配置 | 位置 | 我们 |
| --- | --- | --- | --- |
| arch | `spnet` | `spnet_mit_mona.yaml:8` | UPerNet 头（`heads.py:117`） |
| SPM / 可变形 | `spm_on: False`、`is_deformabel: False` | `:9` | — |
| backbone | `mit-huge-mona` | `:10` | MiT-Huge（MixMIM） |
| 训练方式 | 全量微调（无冻结开关；只 `freeze_bn_scope: backbone` 冻结 BN 统计） | `:37` | 主干冻结 |
| 训练裁剪 | 1024，随机缩放 0.5–2.0 | `:15,:17,:18` | 1024，无缩放抖动 |
| batch | 12（6 卡） | `:27` | 8（单卡累积） |
| lr / 轮数 | 6e-5 poly0.9 / **200 epoch** | `:45,:46` | 1e-3 / 8.4 epoch |
| 测试 | `tta_mode: d4` + `scales [0.5,0.75,1.0]` | `:80,:86` | 单尺度滑窗，无 TTA |

### 3.1 关键发现：这份配置里的 "SPNet" 实际就是 UPerNet

1. `models/spnet.py:32` 的 `SPNet` 把解码器交给 `UperNetAlignHead`（`:50`），该 head 是
   PPM + FPN + 各层上采样拼接 + `conv_last`（`:80` 起），与 mmseg 的 UPerNet 结构同源，
   只是 neck 宽度 128（我们 256）、norm 是 BatchNorm（我们 GroupNorm）、多了 aux FCN 头（权重 0.2）。
2. `models/customize.py:230` 的 `AlignedModule`（SFNet 的语义流对齐）里，**计算 flow 的分支整段被注释**
   （`:234–251`），`forward` 只剩 `F.interpolate`（`:253`）——即普通双线性上采样。
3. 配置里 strip pooling 与可变形分支都是关闭的。

所以"他们用 SPNet、我们用 UPerNet"不构成差异来源；**换解码器不会带来 22 个点**。

### 3.2 mit-huge-mona 与我们 mit-huge 的差别

- 几何完全相同（SegFormer MiT-Huge）：`embed_dims [256,512,1024,2048]`、
  `depths [3,4,18,3]`、`num_heads [4,8,16,32]`、`sr_ratios [8,4,2,1]`
  （外部 `models/backbone/mit_mona_plus.py:428–437`；我们 `workers/lim/src/lim_worker/mit.py:218–226`）。
- 差别在 MLP 里插入 `MonaTokenAdapter`（`mit_mona_plus.py:11–33`）：3×3 / 5×5 / 7×7 三路**深度卷积**，
  由全局平均池化产生三路 softmax 门控，再经瓶颈投影回原维度，加可学习标量 γ（初始 0）。
  属于给 token 混入局部多尺度归纳偏置，**不改变注意力机制**；参数量约多 10 M（估计值，未逐层核对）。
- 预训练配方不同：他们 `mitmonaV3_H_stage4_600W_epoch499.pth`（600W 数据、499 epoch）；
  我们 `mit_huge_600.pth`，run tag 记 `pretrained_epoch=150`。
  **架构改动与预训练差异绑定**，无法单独归因。

## 4. 为什么"把 epoch 加到 200"补不上这 22 点

我们这条 run 的逐 epoch 训练 loss：

```
0.8145 0.4972 0.4273 0.3886 0.3534 0.3242 0.3050 0.2904 0.2809
Δ      -0.317 -0.070 -0.039 -0.035 -0.029 -0.019 -0.015 -0.010
```

第 8→9 epoch 只降 0.010（相对 3%），已经平台化。冻结主干的头部表达上限由已固定特征决定，
再训 190 个 epoch 的预期收益是 **+0.02 量级**（外推，非实测），到不了 0.6。

真正的杠杆按贡献排序：

| 杠杆 | 外部 | 我们 | 预期贡献（估计） |
| --- | --- | --- | --- |
| 解冻主干（B1U） | 全量微调 | 冻结 | **最大项**，同预算下 +0.05~0.10 |
| 训练预算 | 200 epoch × batch 12 × 6 卡 | 8.4 epoch | 样本量差约 14× |
| 测试增强 | d4 TTA + 多尺度 | 无 | +1.5~3 点（文献经验值） |
| 主干 | mona + 600W/499ep | MiT-Huge + epoch150 | 不可分离 |

## 5. 成本：为什么不把 200 epoch 直接塞进主表

在本机（4090，1024/512 切片，4.40 tile/s）：

- 每个 epoch = 23,808 tile ≈ **1.5 h**；
- 200 epoch ≈ **300 h ≈ 12.5 天/种子**；
- 三种子 ≈ **37 天**；外部则是 6 卡 × batch 12 跑同一预算。

因此"文献预算复现"只能是**预声明的独立系列**（锁预算、锁切片、锁 TTA、全模型统一），
不能混进现有"同预算横评"主表，也不能在看到主表结果后回头修改主表预算。

## 6. 汇报口径

> 0.4873 是 **B2U 冻结轨**（524 M 主干冻结、只训 6.96 M 头、8.4 epoch、单尺度滑窗、无 TTA）。
> 外部 0.71 量级是 **SPNet（经核对即 UPerNet）+ mit-huge-mona 全量微调 200 epoch + d4 TTA + 多尺度**。
> 口径换算不改变结论：15 前景类 0.4539、16 类含背景 0.4873、per-image 16 类 0.5128。
> 差距来自预算与训练方式，不在解码器。下一步先测**解冻增益**，再决定是否开文献复现系列。

## 7. 复算方法

```bash
# 每类 IoU、含/不含背景、per-image 口径（读取该 run 的 per-scene 混淆矩阵）
workers/lim/.venv/bin/python - <<'PY'
import json, numpy as np
d = json.load(open('/geodata/rs-eval/runs/lim_mit_huge-T9-upernet_frozen-train-17-v3/confusion_per_scene.json'))
m = np.sum([np.array(v) for v in d['groups'].values()], axis=0)
tp = np.diag(m).astype(float); gt = m.sum(1).astype(float); pr = m.sum(0).astype(float)
iou = tp / np.maximum(gt + pr - tp, 1)
print('16 classes', round(float(iou.mean()), 4), '| 15 fg', round(float(iou[1:].mean()), 4))
PY
```

外部配置的核查点：`spnet_mit_mona.yaml` 的 `arch/spm_on/backbone/epochs/tta_mode/scales`；
`models/spnet.py` 的 `SPNet` → `UperNetAlignHead`；`models/customize.py:230` 的 `AlignedModule`
（flow 分支被注释）；`models/backbone/mit_mona_plus.py:11` 的 `MonaTokenAdapter`。
