## 2. 已确定的范围

| 维度 | 本轮约定 |
|---|---|
| 最终目标 | 能力强、可继续扩大规模的主干；小模型只是资源有限时的路线验证手段 |
| 输入 | 至少 RGB+NIR，最多后续增加 SAR；不以兼容更多传感器或任意波段数作为主要目标 |
| 首个学生 | 优先复用 Clay v1.5；现有 T11 十波段入口仍需新增四波段协议并验收 |
| 第二候选 | DOFA Base，固定实际版本、checkpoint 和配套波长层；不同时铺开所有骨干 |
| 教师目标 | AEF64、OlmoEarth v1.3 的 64/128 维，首轮三个都比较 |
| 教师含义 | 预计算 embedding 监督，不是复制教师参数；OE64 为同一 OE128 产品的前 64 维 |
| 主学习方式 | 直接逐位置蒸馏，方向余弦损失；小 MLP 为主，Linear 为简单对照 |
| 首轮数据 | PASTIS-HD 开发；FBP/T8 为必做国产四波段下游迁移 |
| 后续 | 主干适配、获选系列 Base/Large；再按需要做 FLAIR-HUB、事件任务、SAR |
| 暂缓 | MAE/JEPA、全排列损失搜索、多个教师同时混合、以教师向量拼接作为学生推理输入 |

首轮 PASTIS 输入只取 S2 B02/B03/B04/B08。年度主口径为 2019 年实际可用日期，
默认按日期均匀选至多 20 期；冻结探针先固定时间均值，不额外训练 LTAE。
若资源试跑表明需更少日期，先在新协议中声明共同预算，所有教师配置同步调整。
单景可单列诊断，不把多时相收益写成单景能力。不要使用 PASTIS-HD 的 SPOT RGB 冒充四波段。

新学生实验按 `AGENTS.md` 保持有效 batch=2。历史年度产品探针的 batch=8 属于原协议，
不直接继承为新蒸馏默认值；也不覆盖或改写旧协议与旧 run。

## 3. 第一项执行任务与交付顺序

### P0：环境、数据与接口验收

1. 先运行 `uv run rs-eval doctor`，确认实际 data/weights/cache/runs 路径、设备和可用容量。
   本次文档环境没有真实外置数据与账本，不把历史部署路径存在视为数据已验收。
2. 只读核对 T11/T11O/T11O128 manifest 的 sample_id、split、标签与覆盖；固定 manifest 哈希。
   复用 1455/482/496 划分。额外蒸馏与统计拟合只使用训练区域；validation 仅选配方。
3. 抽样确认四波段顺序、DN/反射率处理、实际日期、教师版本、反量化、NODATA 和地理映射。
   三个目标使用同一有效位置交集。OE128 及其前缀分别聚合、计算范数。
4. 对真实 Clay 四通道 forward、输出网格、冻结梯度与吞吐做少量 GPU smoke。
   教师按实际 token 地理支持聚合；不能把插值后的间距当成新增空间观测。

P0 交付：抽样对齐图、输入/输出 shape、有效覆盖统计、特征/教师缓存指纹、峰值显存、
吞吐与全量成本估计。若出现数据缺口，报告具体缺什么，继续独立的代码/CPU 验证。

### P1：实现首轮蒸馏与对照

- 在独立 worker 中实现数据配对、Linear/MLP、教师损失与可复用特征缓存；控制层不加载模型。
- 按注册表新增明确的四波段学生协议/必要 model 或 task ID，并补充精确集合测试。
  不直接用现有年度 embedding task 的输入声明冒充原始四波段学生。
- 首轮固定一个学生和 MLP 配方，比较 A64/O64/O128；保留原始 F、train-only PCA、
  64/128 维任务监督控制及同网格教师参照。不同阶段的标签使用量和优化成本分开记录。
- 冻结 F 的阶段只缓存提取一次。缓存指纹包括 checkpoint、输入日期、波段、网格、
  预处理、manifest 与提取代码；不要跨失效指纹复用。
- CPU-only 测试覆盖解码、掩膜、样本配对、冻结状态、输出宽度、缓存失效与账本输入声明。
  测试只用 stub/tmp_path，不依赖真实 GPU 或数据集。

正式训练前，根据 P0 固定 distill 步数上限、优化器/LR、有效 batch、验证与 checkpoint
选择规则、下游预算、运行 ID 和预计 GPU 时长，写入可版本化配置/运行清单。先用 seed17
训练/验证开发，再锁定配方补 17/42/73；短跑按 diagnostic 记录，不冒充正式结果。
原有 T11 8 epoch 指下游任务头预算，不自动等于新蒸馏阶段的训练预算。

P1 交付：可 dispatch 的实现、CPU 检查结果、少量 smoke 账本、确定的运行清单、
配方与预算记录。进入正式队列前遵守干净提交、外部 bundle、manifest 固定和日志归档规则。

### P2：下游验收与主干改善

- PASTIS 先冻结表示训练同一任务头，按 mIoU、类别 IoU 和配对 seed 差比较三个目标。
- 固定候选配方后，在 FBP 的原生 16-bit GF-2 四波段影像上训练新的任务头。
  F/E 迁移前冻结，不读取 FBP 教师，也不在 FBP 上额外蒸馏；评测前核验真实 NIR 与 split。
- FBP 原始影像与年度教师的年份错配不限制上述普通迁移。这里不是零样本分类；
  新任务使用当地标签训练新头。若据 FBP 验证集反复调整路线，要明确其开发集角色。
- 仅更新 E 的成功只能证明读出有效。随后用同初始化、同可训练模块和任务预算，
  对照有/无教师损失的 LoRA/部分解冻；同时评测投影前 F 和 E(F)。
- 10%/100% 标签分 panel；按地块/大图地理组固定标签子集，分别报告；不要平均不同任务原始分数。

P2 交付：PASTIS 与 FBP 的基线/三种教师目标配对表、任务级成本、类别退化与空间分组
不确定性。多任务有稳定证据后再扩大主干或投入下一种学习方式；不要求所有备选都跑完。
