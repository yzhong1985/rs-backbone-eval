# AEF 首个任务：PASTIS-HD 多时相对齐与 FLAIR-HUB 可用性评估

日期：2026-11-03。状态：**审查稿**（PASTIS-HD 正在下载，未开始训练）。
关联：`docs/evaluation/AEF_多模态主干对比_数据集与实验建议.md`、
`docs/evaluation/输入归一化口径_2026-11-03.md`。

## 1. 结论

1. **PASTIS-HD 是 AEF 的第一个任务**。全集 86.4 GB，正在下载到根盘
   `/home/yzhong/rs-eval/data-aef/PASTIS-HD`（`/geodata` 只剩 58 GB，放不下）。
2. **PASTIS-HD 没有 2020 年的观测**。官方 `metadata.geojson` 的 S2 日期范围是
   **2018-09-17 → 2019-10-27**，2,433 个 patch 中 0 个包含 2020 年日期。如果手上有
   “2020 年多时相”的副本，需要先核对版本与 metadata；按官方 release，不存在可选 2020。
3. **FLAIR-HUB 不是另一个数据集，而是 FLAIR#1 + FLAIR#2 的超集**。能用，但 726 GB、
   约 250 万文件；建议放第二批，并且只按需下载 S2 + 标签，不整包拉。
4. **对比口径**：先锁定 LPIS 标签年；AEF 用**标签年**的年度 embedding；时序模型用
   标签年时相或**完整作物季**（2018-09→2019-10）的全部时相；单时相模型用固定日历
   窗口选出的单景。AEF 年度 vs 时序是主实验；AEF 年度 vs 单景、特征年均、合成都只是
   消融，不能进 backbone 排名。

## 3. FLAIR-HUB 能用吗

**能用，但不适合作为第一个任务。**

优点：

- S2 是 10 m 且带显式日期，AEF 年度 embedding 的时间对齐没有歧义；
- 比 FLAIR#2 多了 S1、SPOT、DEM 和 23 类作物标签，可以做多模态与作物任务；
- 2020 年有大量样本，如果确实需要 2020，这是正确的来源（PASTIS-HD 没有 2020）。

代价与限制：

| 项 | 影响 |
| --- | --- |
| 726 GB / 250 万文件 | 下载与校验成本远高于 PASTIS-HD（86 GB / 2 万文件）；根盘 1.4 TB 可容纳，但会占掉一半 |
| 0.2 m 航拍 vs 10 m AEF | 只能聚合评价，不能把 0.2 m 分割分数和 AEF 10 m embedding 混成一个结论 |
| 可比性 | 已发表的 FLAIR#2 数字对应 FLAIR#2 官方 test；HUB 包含它。用 HUB 时必须**只取 FLAIR#2 子集**，或声明一套新的 HUB 划分，不能混着比 |
| 标签体系 | 19 类土地覆盖与 23 类作物是两套任务，不能合成一个 mIoU |

建议：**第二批再做**，并且用 `allow_patterns` 只下需要的分片，例如
`data/*_S2_*.zip` + `data/*_LABEL-LC_*.zip`（或 `LABEL-CROP`），不要整包 726 GB。

## 4. 多时相对齐协议（核心）

AEF 是**年度** embedding：官方说明它概括“a single calendar year”的观测，产品年份
**2017–2024**（本机索引里另有 2025 层，使用前核对）。PASTIS-HD 的观测止于
**2019-10-27**，所以“同一年”并不等于“同一时间支撑”，必须先写成协议。

### 4.1 三个时间概念

| 概念 | 定义 |
| --- | --- |
| **标签年** | LPIS 标注对应的年份。PASTIS-HD 的作物季跨 2018/2019，必须先确认标签年；不能默认 2019 |
| **观测窗** | 参与比较的影像日期集合。A1 用标签年；A2 用完整作物季（2018-09→2019-10） |
| **输入预算** | 每个模型能看到的时相数/模态。AEF 是 1 个年度向量；时序模型是 N 个日期；单时相模型是 1 个日期。**不同预算的结果不能放在同一张排名表里** |

### 4.2 主实验：年度表征 vs 时序融合

- **AEF**：取**标签年**的年度 embedding（如标签年为 2019，就用 2019）；
- **传统时序模型**（AnySat/Prithvi 等能吞时序的）：喂**同一标签年**内的全部 S2 时相，
  可选加 S1（按模型能力声明）；A2 则喂完整作物季；
- 两者都做 10 m 网格上的地块/像素预测，同一个头、同一份标签、同一划分、同一种子。

这条回答的是“AEF 的内部年度融合 vs 我们模型的时序融合”，是 AEF 对比的主结论。

### 4.2.1 为什么不是“选一个时相去对 AEF”

AEF 的一年一个向量，本身已经是“把该年观测融合完”的结果。拿它去对 PASTIS-HD 的
某**一个**时相，比较的是“年度融合 vs 单张影像”，不是 backbone 能力。按时间预算对齐：

| 轨道 | AEF 输入 | 我们的模型输入 | 回答的问题 |
| --- | --- | --- | --- |
| **A1 年度（主）** | 标签年年度 embedding | 标签年内的全部时相 | AEF 年度融合 vs 时序融合；干净但不与文献直接比 |
| **A2 全季/双年（主，敏感性）** | 2018+2019 年度 embedding 的均值或拼接（预先声明） | **完整作物季** 2018-09→2019-10 的全部时相 | 与 PASTIS 公开基线同输入窗口；AEF 双年是派生量 |
| **A3 年度对特征年均（消融）** | 标签年年度 embedding | 单时相模型逐时相提特征后取均值 | 冻结单景能否逼近年度表征 |
| **A4 年度对单景（消融）** | 标签年年度 embedding | 固定窗口内的一景（§4.3） | 预算不对称，只看“单景差多少” |
| **A5 年度对合成（消融）** | 标签年年度 embedding | 固定窗口内的中值/均值合成 | 合成输入是否足够 |

只有 A1/A2 能进 AEF 主结论；A3–A5 是消融。若只能选一个时相，那是 A4 的问题，
规则见 §4.3；并须用两个不同窗口做敏感性检查，排名不稳定就只能当消融。

**与文献比较时必须用 A2**：PASTIS 的公开基线（U-TAE 等）用完整
2018-09→2019-10 序列；A1 只取标签年（2019）会丢掉约 **11/46 = 23.9%** 的时相，
而且丢的正是播种期，A1 的数字不能直接和文献对齐。A2 的数字才和文献同输入窗口，
但它的 AEF 侧是“2018+2019 双年”派生量，也要标注。

### 4.3 单时相模型（LIM/Clay 等）

只给一张影像，选日规则必须**预先固定、对所有 patch 一致**：

1. 固定日历窗口，例如 `2019-06-01 → 2019-08-31`（作物生长旺季）；
2. 选窗口内**最接近窗口中点**（2019-07-15）的一景；
3. 同一天多景时，按 `(tile, sample_id)` 字典序取第一个，作为确定的打破平局规则；
4. 窗口内没有可用景时才回退到 ±30 天最近的一景；PASTIS 的 6–8 月每个 patch 至少有
   13 景，这个回退实际不会触发，保留规则只为其他窗口；
5. 仍无 → 记 `missing`，不补、不换年份；
6. 每个 patch 实际使用的日期写入 manifest；**禁止按 NDVI、标签或“哪景分高”逐 patch 挑**。

**云的处理**：PASTIS 包内没有随附云掩膜（下载后核对；若无），主实验**不做云过滤**，
与公开基线一致；单景选日可能选到云景，因此必须做敏感性（6 月/7 月两个窗口），并在
manifest 写明“未做云过滤”。AEF 官方说明其表征对云、扫描线等常见问题有鲁棒性，但
这不是“PASTIS 端也做了云过滤”。

敏感性检查：用 6 月窗口与 7 月窗口各跑一次，报告排名是否稳定；如果不稳定，说明
“选哪一景”本身影响结论，单时相结果只能作为消融。

### 4.4 复合输入（可选）

不能吞日期的模型，可以用窗口内的中值/均值合成（逐波段），但必须声明：
合成窗口、参与日期数、云处理、波段顺序；不能用“逐 patch 最优合成”这种依赖标签的做法。

### 4.5 AEF 的年份对齐

- 主口径：**标签年 = AEF 年**。标签年未确认前不锁定任何 AEF 年份；
- **年度产品的边界**：AEF 官方说明它概括一个**日历年**，PASTIS 的 S2 在 2019 年只到
  10-27。因此 AEF 2019 包含 11–12 月（PASTIS 没有对应观测），且 AEF 还融合了 S1 等
  其他源；“同年”只能保证年份标签一致，**不能保证时间支撑一致**。结果表必须写清
  “AEF 日历年 vs PASTIS 作物季”；
- 作物季跨两个日历年时：
  - **A1**：标签年单年 embedding（干净、可解释；丢 2018 秋约 23.9%）；
  - **A2**：2018 与 2019 两个年度 embedding 的均值或拼接（二选一，预先声明），配
    完整作物季；标注“双年融合”，不与 A1 混排；
- AEF 缺失该 patch/年份的向量 → 该 patch 从该实验剔除，记录数量；
- AEF 保持 10 m，不重采样到 1 m 去迁就 SPOT；SPOT 只用于单独的高分轨；
- AEF 官方年份 2017–2024；本机索引另有 2025 层（34,155 个 COG），使用前核对是否为
  正式年份。

### 4.6 云与无效像元

- PASTIS 包内是否自带云掩膜：下载后核对。**当前默认没有**；
- 无掩膜：主实验使用全部日期，manifest 明确“未做云过滤”；云的影响放进 E2 敏感性；
- 有掩膜（若确认）：按 patch 声明阈值（如云比例 >20% 的日期剔除），阈值写进 manifest；
- 不做静默插值/修补；`void` 标签按 PASTIS 协议处理，不并进 background。

### 4.7 划分、指标与预算

- 划分：PASTIS 官方 `Fold` 1–5，按 patch 分组，AEF 与传统模型共用同一 fold；
- 指标：mIoU（含/不含 background 分开报）、macro-F1、各类 IoU；
- 标签预算：同一批地块/像素，不因模型不同而改；
- 种子：预先声明（建议 17/42/73），同一 cell 同 host。

### 4.8 明确不能做的事

1. 用 2020 年的影像去配 2019 年的 AEF embedding（或反过来）；
2. 逐 patch 挑“最好看/分最高”的日期；
3. 把 AEF 年度结果和单时相模型结果放进同一张 backbone 排名；
4. 用 0.2 m 航拍的分割分数解释 10 m AEF 的能力；
5. 在标签年未确认前先跑正式 run。
